# 艺术指导、表达性反差与完整设计工程

UI Spec Studio 将 **Art Direction、Visual System、Asset Engineering、Motion Storytelling、Source Fidelity 与 Perceptual Quality** 连接到同一项产品工作：建立明确的视觉意图，找到能够承接它的成熟成果，完成必要的专业制作，再通过真实界面与连续使用确认结果。

专业应用同样可以拥有鲜明的摄影、字形、材质、三维形态和动态表达。产品类型帮助判断用户任务、信息关系与运行条件；具体视觉语言由产品目标、用户意图和实际观察共同决定。明确提出的艺术性、视觉冲击力与差异化，需要进入设计、实现和验收。

**熟悉的任务关系与成熟的使用品质，可以承载独立而鲜明的视觉表达。**

重要艺术方向也需要经受来自不同视觉领域与实现资源的比较。对于决定作品气质的素材、字体、构图和动态语言，根据设计影响、不确定性与潜在提升空间持续探索；重点考察实际看过的视觉证据、可比的替代方案和可实现的采用路径。[证据驱动的深度视觉探索](DEEP-VISUAL-EXPLORATION.md)提供完整决策机制。

本指南说明这些能力如何共同工作。运行方法仍由八份共同参考及接线参考负责，沿用 `init → iterate → finish`、可选 `shape` 和贯穿其中的 `audit`。

## 1. 同时确定使用目标与表达目标

在确定页面形式之前，区分三类条件：

| 条件 | 具体内容 | 设计中的责任 |
|---|---|---|
| 必须兑现的体验要求 | 准确信息、明确操作、必要阅读、键盘与辅助技术、真实状态及业务结果 | 通过实际操作、内容和工程证据确认成立 |
| 用户明确提出的审美目标 | 艺术性、视觉冲击力、材质、情绪、独立设计感及已确认方向 | 转成可见关系，持续保留并单独检查完成情况 |
| 可以重新研究的惯例 | 常见配色、导航外形、标题尺度、卡片排列及工具软件的典型外观 | 作为候选起点，以研究和当前任务验证其适用性 |

熟悉感可以来自可理解的对象、标签、操作结果、返回与继续方式。重新组织导航、改变容器形态或采用编辑式排版时，要检查这些线索是否继续成立。用户熟悉的语义关系，为视觉探索提供可验证的基础。

当一处艺术化处理影响操作，先定位具体原因：文字与背景对比、入口显著性、运动范围、内容密度或资源成本。修正相应关系，并复验原定表达目标。确实需要改变已确认方向时，说明证据、影响和可选路径，保留这项决定的实际授权。

## 2. 以艺术指导组织有意义的反差

艺术指导确定视觉主题、注意力顺序、主要表达载体，以及其他元素如何呼应。一个方向应足以影响构图、字形、素材、组件细节和时间节奏；“高级”“简洁”或“大胆”等词需要展开为实际选择。

**Expressive Contrast（表达性反差）** 以可理解的任务关系为基础，引入超出同类产品常见外观的视觉语言。先说明改变了什么惯常预期，再解释哪些关系使整个方案仍然协调：

- 产品语境中的反差：将编辑出版、摄影、雕塑或展览编排引入日常工作界面。
- 同一画面中的反差：通过密集信息与留白、理性文字与有机形态、平面结构与立体材质形成主次和节奏。
- 连续使用中的反差：让直接的重复操作与重要结果的表达性展开共同组织时间。

这些都是可探索的关系，具体主题由当前产品选择。素材可以表达品牌气质或情绪，并通过色彩、形态、构图或叙事与界面建立联系；其含义不必逐项映射成某个功能。主要识别元素与支持元素承担不同强度，使反差具有清晰的组织方式。

## 3. 让三类来源共同发展方案

| 来源角色 | 研究什么 | 如何作用于当前设计 |
|---|---|---|
| 功能与体验参照 | 任务入口、对象关系、状态、继续与恢复、细节完成度 | 确定值得继承的使用逻辑与品质 |
| 艺术与表达参照 | 跨领域摄影、字体、图形、材质、构图与动态语言 | 扩展题材与感知方式，形成独立方向 |
| 成熟实现资源 | 可采用的结构、功能区块、组件、字体、资产与动画能力 | 将所选关系落实为可运行、可适配的实现 |

同一来源可以承担多个角色，各项结论仍按实际观察对象归属。品牌网站或艺术作品可以提供表达依据；工作界面的使用判断需要相应的操作与内容证据。研究访问、资源获取和允许集成分别确认。

搜索可以从功能问题进入，也可以由优秀素材或完整区块反向改善方案。发现高价值线索后，实际浏览、播放、滚动、切换和比较，并说明这一发现改变了哪个决定。搜索范围随设计问题展开，充分依据出现后收敛。

存在显著方向分歧时，用少量完成度可比较的真实画面或可运行片段支持选择。保持任务、代表内容、显示条件和重要状态具有可比性，同时允许候选通过不同题材、构图、字形或运动语言表达实质差异。每个方向都应得到足够制作，使用户能够比较方向本身。已有明确意图或授权时，继续推进相应设计；用户选择的范围与整体验收分别记录。

## 4. 将视觉方向转成有角色分工的系统

视觉系统保存重复选择的关系，也容纳具有明确职责的差异。通过 Design Tokens、组件变量、共享样式和状态规则，把选定方向变成可维护的实现：

| 规则对象 | 值得明确的关系 |
|---|---|
| 字体与文字 | 展示、标题、正文、操作、注释和数据角色；字形、行宽、换行与语言覆盖 |
| 空间与形态 | 区域比例、分组节奏、留白、嵌套边界、圆角与实际容器尺度 |
| 色彩与材质 | 前景和表面层级、强调与状态、透明叠加、光影及主题对应 |
| 素材与图标 | 题材、裁切、光源、轮廓、线条、光学重量和相邻文字关系 |
| 动态与状态 | 触发原因、运动角色、轨迹、节奏、稳定状态和减少动态的对应表达 |

展示标题可以更有表现力，长文可以采用适合持续阅读的节奏，日常操作可以直接反馈，关键结果可以有独特编排。共同的角色和相互呼应的关系使它们属于同一个产品。

参数为重复实现提供控制；实际画面确认光学结果。等值间距、相同图标尺寸或机械圆角公式分别只能说明构造方式。用真实字体、短长内容和关键状态试装，再确认这些数值形成了所需关系。跨页面应用时，也保留各页面职责需要的合理差异。

## 5. 让素材成为真正采用的产品资产

重要素材与真实组件尽早共同进入试装。摄影题材、三维材质、字形或裁切会影响文字位置、空间比例和焦点，应在布局仍能调整时研究。优先选择有实际品质的成熟文件、字体、场景、材质与动态实现；独立身份或明确差异可以采用专业制作。

选择复用、加工、图形制作、建模渲染、程序化或生成式路线时，同时检查工具能力、质量、编辑需求和总成本。概念图支持方向判断；能够交付的产品资产还需要合适的尺寸、格式、使用条件、派生版本和真实位置验证。生成图片、可编辑曲线、三维场景、字体文件和实时交互各有自己的产物与检查要求。

重要资产保留 **来源与允许用途 → 可编辑母版 → 制作或导出 → 交付变体 → 实际放置 → 观察结果**。检查裁切、清晰度、透明边缘、字体覆盖、材质、加载和累计运行成本。选择预渲染、静态或实时输出时，依据当前体验需要；制作方式与交付方式分别决定。

素材的视觉价值还要进入用户日常使用的区域。完成首次操作后，检查已填入内容的输入、结果、导航、详情与报告：主题是否仍通过文字、轮廓、材质、图形或节奏清楚存在。欢迎页中的主视觉只能证明该欢迎页的表达范围。

## 6. 用动态叙事解释关系和过程

Motion Storytelling 从事件含义出发：什么触发变化，哪些对象相关，先出现什么反馈，内容怎样形成，注意力最终落在哪里。任务流转、证据归组、结果展开和对象建立关联，都可以研究具有语义的运动方式。

轨迹、持续时间、缓动、错位与停顿共同组织观察顺序。一个产品可以为频繁操作提供快速反馈，也为重要阶段采用更有表现力的变化。运动强度随过程职责变化；静态字体、素材、构图和形态继续承载身份。

异步结果由真实状态决定。等待反馈可以先出现，完成表达需要对应实际结果；取消、失败、新输入和重复操作也要保持语义清楚。通过调整局部运动、暂停时机、遮罩、层级、预渲染或交付形式处理具体问题，并验证表达是否保留。

减少动态、暂停和静态替代需保留内容与设计气质，并满足适用的可访问性要求。运行性能依靠对应设备和真实过程的测量；作者设定的播放速度只说明编排。

## 7. 按产物选择实现与验证方法

| 产物 | 实现重点 | 需要的验证 |
|---|---|---|
| 真实产品界面 | 可交互组件、语义文本、动态内容、权威状态和可恢复任务 | 实际操作、持续使用、可访问性、业务结果与运行条件 |
| 产品演示 | 代表性流程、准确内容、可理解反馈及清楚的演示范围 | 展示的流程与能力对应，示例内容明确，未演示条件单独保留 |
| 独立动态展示作品 | 固定舞台、图层与资产保真、可控制时间线、输出画质 | 中间构图、完整播放、可读停留、编码结果和所需循环衔接 |

同一素材可以在这些产物中采用不同实现。固定舞台的视频可用确定性时间控制；真实网站还需重新验证语义、输入、重排和服务时序。展示品质与产品履约各自需要对应证据。

在能够控制实现的场景，固定来源、素材、字体、视口、随机种子和时间轴有助于重复比较。记录实际控制方式及其覆盖范围，采集初始、过渡、稳定状态和必要的循环边界。关键帧集合（Contact Sheet）帮助比较阶段构图，原尺寸帧定位细节，完整播放检查节奏与衔接。最终编码文件也需查看。

确定性采集支持还原和回归；自然运行支持真实操作时序。逐帧、受控时钟和慢速播放的结论保留其条件，随后按任务需要回到正常运行。录制完成、实际查看、运动判断与帧交付测量分别记录，具体方法见[视觉观察指南](VISUAL-INSPECTION.md)。

## 8. 分别验证体验、表达与源设计保真

**体验成立性**与**表达完成度**分别形成判断，再共同决定方案是否达到要求：

| 判断 | 需要确认的内容 | 对应证据 |
|---|---|---|
| 体验成立性 | 能否理解、阅读、操作、继续和恢复；信息、状态与结果是否准确 | 实际任务、真实内容、键盘与相关辅助技术检查、业务和运行证据 |
| 表达完成度 | 已承诺的主题是否可见，素材和细节是否成熟，反差是否协调，核心工作区是否延续视觉身份 | 完整页面、局部细节、真实内容和连续过程的实际观看，必要的用户选择 |

功能已工作而艺术方向尚未兑现时，设计仍有明确缺口；表现鲜明但阅读或操作受阻时，修复受影响的关系。两类结论保留各自的不足、修复和复验。

**Source Fidelity（源设计保真）**另外确认已选定或批准的设计成果是否被保留。明确还原任务可以比较结构、素材、字体、比例、材质和状态，并使用对齐的区域图像差异定位问题。记录显示尺度、字体就绪、内容、时间阶段、遮罩与容差；差异指标需要解释其来源。批准的主动改动应有范围和理由。

**Perceptual Quality（感知品质）**判断当前结果的构图、光学平衡、阅读、材质、细节和动态关系。图像接近度支持对既定目标的还原判断，设计成熟度与艺术方向仍由实际观看和任务情境评价。借鉴成熟产品形成独立表达时，比较所继承的关系；对已经采用的资产和确认的试装，则保护其重要细节。

## 9. 以具体问题修正，保留已确认方向

发现问题后，连接可见现象、可能的感知或任务影响、原因假设、负责的资源或机制，以及修改后的结果。动态素材影响输入，可以调整运动位置、输入期间暂停或交付方式；正文与背景竞争，可以研究裁切、局部明度、材质层级和文字布局。每次修正重新检查体验与表达。

资源本身不适用时重新选型；适配损失时恢复有价值关系；真实内容暴露缺口时共同调整内容和结构；多个资源冲突时回到视觉系统。若当前条件确实无法支持承诺，明确差距及可选方向，再由相应授权决定调整。

成熟资源优先贯穿艺术表达。创造力可以体现为选材、跨领域参照、组合、构图与高质量适配；定制承担独立身份和已确认缺口。研究、试装、实际采用与最终验证保留各自状态，依靠真实成果收敛。

## 10. 将有效判断保留为可继续的经验

简洁记录目标、来源角色、实际观察、选定关系、采用实现、修改范围和结果。业务使用量、客户评价、案例与服务承诺来自已确认事实；概念或演示内容保留清楚标记。

Skill 的改进需要在具体任务中查看实际产物：是否展开了适当的跨领域研究，哪些成熟成果真正进入实现，艺术方向是否持续存在于核心区域，以及体验与表达分别验证到了哪里。方法文字、研究篇幅和素材数量各自描述工作，不能代替这些结果。不同产品、创意页面和动态作品按自己的目标形成证据，保留尚未覆盖的环境与用户条件。

## 方法来源与适用范围

以下一手页面于 2026-10-26 查阅文字内容。它们支持对应方法；本次查阅不构成对页面像素、视频过程或组件运行的实际视觉检查。

- [Pentagram：Intrinsic](https://www.pentagram.com/work/intrinsic) 描述以生成式机械臂抽象、字体和图标构成的品牌表达。它提供专业技术语境中的表达参照，所述品牌与网站案例不能直接证明工作界面的可用性，作品展示也不等于资产采用许可。
- [IBM Developer：Typography](https://www.ibm.com/brand/experience-guides/developer/brand/typography/) 为表现性场景安排 Plex Mono Light，为信息与支持性文字安排 Plex Sans。这里继承字体角色分工的方法；具体字体与语言策略仍按当前产品选择。
- [Carbon：Motion](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview) 将 productive 与 expressive motion 用于同一界面的不同情境，并说明整体编排由产品团队负责。它支持多种运动角色协同，具体强度与节奏需要当前方案验证。
- [W3C：Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide) 解释 Level A 的 SC 2.2.2：满足自动开始、持续超过五秒、与其他内容并行等条件的运动信息需要相应控制，并保留 essential 例外；自动更新信息另有控制要求，没有相同的五秒条件。[Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions) 解释 Level AAA 的 SC 2.3.3，针对交互触发的非必要运动。适用范围与项目符合性目标需分别确认。
- [Playwright：Visual comparisons](https://playwright.dev/docs/test-snapshots) 提醒截图会受浏览器与运行环境影响；[Clock](https://playwright.dev/docs/clock) 提供对受支持时间机制的控制。这些能力帮助建立可重复的诊断，具体渲染机制的覆盖与自然运行品质需要另行验证。
