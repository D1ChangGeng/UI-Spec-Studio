# UI Spec Studio｜内容设计、UX Writing 与文字视觉

文字内容是产品信息、交互行为与视觉构图的共同材料。新的内容设计方法以用户任务和真实事实为起点，决定用户何时需要理解什么，哪些页面和组件承担信息，采用怎样的语言风格，以及排版如何与实际布局协同。

## 专业能力

| 维度 | 决策对象 | 预期效果 |
|---|---|---|
| 内容需求 | 用户已有认知、目标与所需事实 | 信息在关键决策点可获得 |
| 信息分布 | 页面、区块、标题、标签、帮助和状态职责 | 连续的 UX 阅读与操作路径 |
| 产品语言 | 同类产品术语、内部业务概念与用户心智 | 熟悉、准确、一致的表达 |
| Voice & Tone | 稳定品牌个性和情境语气 | 有辨识度且适合各类操作 |
| UX Writing | 标签、动作、说明、反馈和错误恢复 | 用户知道下一步能做什么 |
| Typography | 文字长度、字体、换行、密度和视觉重量 | 自然的阅读节奏及空间平衡 |
| Localization | 各语言实际语义、语言长度和界面变体 | 内容与构图在多语言下完整可用 |
| 内容维护 | 数据与模板来源、单项覆盖、角色表达及语言版本 | 内容更新后仍能准确呈现实际业务 |
| 真实验证 | 行为、权限、价格、状态与呈现事实 | 界面语言与实际结果一致 |

## 在实际产品中怎样运用

内容设计围绕用户正在作出的判断组织信息。例如，商品介绍帮助比较用途与差异，结账内容说明当前价格与交付条件，操作反馈则说明实际完成了什么。重要条件可以在多个决策节点再次出现，并由同一业务来源维护；各节点的表达根据其职责调整。

异步操作需要区分已收到请求、已保存数据和已完成服务。请求超时后，系统可能暂时无法确定最终结果，此时文案应说明已知状态，并提供真实可用的查询或恢复方式。部分成功应说明已完成的范围与剩余项；输入错误、服务故障和权限条件，也分别采用适合其任务影响的说明与入口。

多语言内容以完整语义和具体情境为翻译单位，保留变量含义、数量规则和语序调整空间。中文与英文分别检查自然度、标点、换行、字体及组件占位。可见标签、图标按钮名称和状态播报共同进入本地化与验证，使视觉界面和辅助技术表达同一操作。

持续运营的内容需要明确来源、编辑责任及实际生效结果。根据产品需要管理共享模板、单项覆盖和语言回退，并在实际页面预览最终内容。消费者和运营人员可以获得适合各自任务的说明，两者依据同一业务事实；存在草稿、保存和发布阶段时，分别准确表达各阶段的结果。

## 与现有 Skill 的关系

第八份共同参考 [`content-design.md`](../skills/ui-spec/references/content-design.md) 负责具体判断方法；其他参考只保留其对应层次的责任。它与成熟设计资源探索、素材工程和视觉原则一起工作：优秀产品提供内容表达参照，当前产品提供真实语义与业务事实，页面设计和实际渲染共同决定最终结果。

**Init** 恢复业务语言与内容来源；需要方向探索时，通过可选的 **Shape** 确定内容需求、分布和写作方向；**Iterate** 写入真实文本，协调视觉并进行状态验证；**Audit** 检查阅读路径、跨页面一致性及完整状态；**Finish** 连接真实事实、服务结果和本地化内容。

专业资料分别提供可迁移方法和明确适用条件：品牌风格指南帮助区分 Voice 与 Tone；W3C 国际化资料支持完整消息与文字空间设计；中文排版需求提供仍在发展的专业参考；WCAG 的文本间距要求用于检查用户调整后的可用性，具体界面的默认排版仍由产品设计确定。

## 本轮验证范围

样例验证用户可见标题、操作标签、字段说明、校验错误、正在处理、保存结果、失败恢复，以及中文、英文和跨视口排版。示例使用真实浏览器本地存储边界，业务后端与实际使用者理解仍需在具体项目中验证。检查记录见 [本轮审阅文档](REVIEW-v1.6.0.md)。
