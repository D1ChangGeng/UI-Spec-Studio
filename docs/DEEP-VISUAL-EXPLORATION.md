# 证据驱动的深度视觉探索与设计决策

UI Spec Studio 将 **Evidence-Driven Deep Visual Exploration** 作为贯穿设计工作的专业能力：Agent 通过实际发现、观看、操作、比较和验证优秀设计，不断扩大对可选设计空间的认识，并使重要选择拥有相称的视觉证据。

**设计信心来自当前判断究竟有多少可信的视觉依据、是否经受实质性替代方案的比较，以及尚未观察到什么。** 熟悉一种设计原则、记得某个组件的名字，或找到一个看似完整的案例，并不代表已经了解该问题下可达到的最好品质。

本方法适用于产品 UI，也适用于文档、展示作品、图表、品牌视觉与动态媒体。它与既有的 `init → iterate → finish`、可选 `shape` 和贯穿其中的 `audit` 同时工作，不增加固定研究阶段或每轮必做的搜索配额。

## 01｜由设计影响决定探索投入

决定研究强度时，先判断三件事：

| 判断 | 关键问题 | 对下一步的影响 |
|---|---|---|
| **设计影响** | 这个对象多大程度决定产品的辨识度、构图品质、核心任务与连续体验？ | 决定其是否值得投入独立研究与试装 |
| **认知不确定性** | Agent 实际看过哪些成熟作品、状态和实现？哪些判断还只凭常识或文字？ | 决定需要扩展来源、深入观察还是补齐缺失状态 |
| **潜在改进空间** | 新发现是否可能明显改善品质、改变艺术方向或避免大规模返工？ | 决定继续探索的价值与优先级 |

一个高品质摄影、标题字体、特殊背景或核心动画，即使面积不大，也可能具有极高的设计杠杆，因此值得跨多个来源和轮次持续研究。已有可靠成熟实现的常规控件则可以直接适配和复验。

深度探索可以涉及数十甚至数百次合理的搜索、浏览、操作和比较；**规模是高价值研究的结果，而不是质量指标或规定的最低数量**。搜索次数、页面数量、时间和笔记长度都不能独立证明研究充分。

## 02｜目标体验与实现资源持续配对

研究同时服务于两类问题：

**目标体验：** 当前产品应该呈现怎样的清晰度、视觉层级、艺术气质、素材质量、组件细节、交互反馈和时间节奏？参照不仅来自同类产品，还可以来自编辑出版、摄影、建筑、展览、工业设计、三维艺术与动态图形。

**可实现性：** 哪些实际存在的页面、设计系统、区块、组件、字体、素材、程序化视觉和动画实现能够承接这些品质？哪些可以直接复用、定向二开或通过专业工具制作？具体版本、许可、运行条件和集成成本是什么？

两类探索往返进行。发现字体关系可以转向字形作品与实际字体包；发现成熟动态资源可以反向改进页面叙事；一次局部试装还可能揭示最初的视觉参照并不适合当前内容。

同一来源可以提供设计参照、实现技术或素材，但必须分别说明它实际承担了哪个角色。**研究了优秀作品、获得了可复用资源、最终在产品中保留了其品质，是三项不同事实。**

## 03｜从实际线索扩展搜索路径

用可改变设计选择的问题发起搜索，再让观察到的特征引出下一轮问题。

例如：任务型工作台 → 页面布局范式 → 编辑式信息层级 → 特殊字形与旁注 → 可采用的字体和排版实现 → 局部试装 → 重新检查工作台整体构图。

搜索入口可以在产品、设计案例、资源索引、作者作品、官方示例、开源仓库、交互 Demo、视频、素材库和专业社区之间切换。初始查询由功能或素材类别出发；进一步查询可以细化为排版、边界、光学关系、材质、形状、运动语义或精确实现。

当连续看到同一类卡片、背景或动画时，应该识别搜索空间的重复，而不把相似结果累加为独立候选。可改变媒介、关键词、领域、作者或实现技术，主动寻找真正不同的表达方式。

每一轮都回答：**这次实际看到了什么？它改变了对品质或可行性的哪一项认识？下一项最有价值的证据是什么？** 新搜索由这些发现驱动，而不是机械延长清单。

## 04｜同时保证证据广度与观察深度

五个维度共同评价研究依据：

- **Coverage Breadth（覆盖广度）：** 有无覆盖重要页面、对象、状态、视口和实质不同的设计方向。
- **Inspection Depth（观察深度）：** 是否深入到构图、字体、边界、空间、材质、光学关系及具体实现机制。
- **Temporal Coverage（时间完整性）：** 是否观察足以理解该行为的触发、变化、结果、反向操作或循环衔接。
- **Evidence Relevance（证据相关性）：** 观察是否直接帮助回答当前产品的问题，而非只是漂亮但无关。
- **Evidence Reliability（证据可靠性）：** 来源、版本、展示条件、编辑情况和实际观看范围能否支撑所作结论。

从实际观看尺度理解整体焦点和阅读顺序，再观察区域与关键细节，随后回到整体。放大和裁切用于理解微观关系，但结论必须回到实际场景。时序资源需要视频、实时操作或具有真实时间标记的连续画面；一张海报或几帧剪辑不能代表完整过程。

还应区分四个观察对象：**设计参照、候选的原始演示、当前产品中的局部试装、最终整合后的连续使用**。任何一个对象的成熟感都不能自动覆盖其他对象。

资料已经获取、实际打开查看、操作了关键状态、检查了代码、验证了真实运行结果，应分别记录。未获得的画面和无法确认的动态效果是研究缺口，不是可以用模型常识补齐的事实。

## 05｜主动挑战最初的好方案

找到一个可用而精致的候选，只代表发现了一个可行起点。重要选择还需要受到有意义的挑战。

先说明当前首选的真实优势，再寻找**具有另一种实质优势的可行替代方案**。它可能采用不同的视觉题材、字体性格、信息组织、材质、组件机制或运动叙事，而不只是换色或调整圆角。

候选应在相近的任务、真实内容、呈现尺度、交互状态和制作完成度下进行比较。对比“已精修的传统方案”和“只有文字草图的艺术方案”，无法公平评价两者。

比较之后可以保留原方案、改选新方案，或者进一步细化研究问题。**能够被新证据修正的专业判断，比不断确认最初印象更可靠。**

对于已有批准方向，候选挑战服务于局部质量、采用途径与可验证的改进，不自动覆盖用户既定的审美选择。

## 06｜访问受限时扩展证据获取途径

先判断真正缺失的是图片细节、原始交互、视频片段、源码还是合法的产品素材，再从可用来源补齐：

- 官方演示、作者项目、公共仓库、发布视频或技术文档可以回答不同问题。
- 交互 Demo 适合检查真实状态与回退；视频适合研究已经呈现的运动与构图；源码适合解释实现方式。
- 重要资源必须通过登录、官方客户端或授权下载才能观察时，可在充分自主探索后请求用户完成**具体的一次性取材**，说明页面、状态、片段与研究目的。

这些方式相互补充，不能混淆宣传片和真实应用、播放器界面和视频中展示的工作界面，也不能把研究访问等同于商业使用许可。访问、授权、保存、引入产品分别遵循来源及宿主权限。

## 07｜把视觉认识转为实际资源采用

研究结论要继续连接可用实现。对于重要区块，优先找可继承完整排版、空间和动态关系的成熟结构；对于特殊素材，研究可交付资产、适配方式或专业制作方法。

先查看候选原始演示和重要状态，再用当前项目的实际字体、内容、容器、语言、主题与反馈进行局部试装。对照其目标参照，判断哪些关系保留了、哪些因集成而失真。

若真实页面暴露重大品质落差，需要定位是源资源不合适、二次开发破坏了机制、素材与内容冲突、组合关系不协调，还是目标需要重新审视。根据原因，返回选型、调整构图或修改实现。**不要在错误的设计基础上依靠无限的局部修饰代替新的研究。**

## 08｜何时继续探索，何时进入实现

重要设计问题在进入大范围开发前，应形成足够成熟的决策基础：

| 决策条件 | 当前需要知道什么 |
|---|---|
| 目标 | 明确的任务体验、设计成熟度和审美交付要求 |
| 观察 | 实际看过哪些相关页面、状态、细节、连续过程及其条件 |
| 多样性 | 是否有真实差异的候选，有没有被初始查询局限 |
| 比较 | 选择为何优于最有力的替代方案，什么新证据可能推翻它 |
| 实现 | 可采用的真实资源、局部试装结论及适配边界 |
| 缺口 | 哪些未观察事实仍可能明显影响方向或造成返工 |

继续搜索有望显著改善方案时，应允许深入；已有多种有效比较、关键状态与适配路径得到验证，新增发现趋同或收益不大时，就应进入试装与实现。

研究收敛是一个**对当前设计风险有充分回答**的判断，不是完成固定次数或用文字宣告“已充分研究”。

## 09｜以少量可检查证据替代冗长检索日志

关键设计记录只需让审阅者理解：研究的问题、最具价值的来源、实际观看范围、候选差异、选择理由、采用的实现、试装结果、重要未解问题及下一步。直接展示代表性截图、原始 Demo 或运行片段，比堆叠工具轨迹更有效。

保留设计事实的来源与版本。区分“已发现”“已比较”“已试装”“实际采用”“已在最终界面检验”和“用户批准”。后续可以从结果回溯到实际资源，而不必重走整个搜索过程。

对于长期研究，可以在重要转折处压缩保留：当前已排除什么、为什么排除、最有希望的候选与证据缺口、下一步需要验证的假设。这样支持多轮深入探索而不使执行上下文被重复发现淹没。

## 10｜以真实产物检验探索能力

UI Spec Studio 自身的回归检查应区分三个层次：

1. **规则与工程检查：** Skill 入口、参考文件、模板、引用和安装包是否一致；这只能证明方法已写入可用分发物。
2. **Agent 行为检查：** 在冻结输入、技能版本和可比执行条件的实际任务中，是否探索过实质不同的来源、实际查看重要内容、发现最初可能错过的资源，并据此改变选择或明确保留理由。
3. **产物品质检查：** 新选择是否真正进入代码与素材，最终页面是否在真实内容、交互、视口、语言和时间过程里达到预期品质；主观判断、使用数据与工程测量分别报告。

比较可以采用改动前后的同类任务，也可以设计高影响未知资源与低影响常规控件两种情形，检查探索强度是否合理。应分别记录探索成本、重要新发现、实际采用与最终体验。**不能用 Skill 文本数量、网站数量、测试通过数或风格命名直接代替 Agent 能力与用户感知品质。**

## 11｜默认执行原则

面对重要问题，先了解产品与已有可复用成果，再主动寻找可能更优秀的方向。每次新观察都改进设计认识；每个重要首选都允许受到有意义的替代方案挑战；每个缺失证据都应明确其范围和价值。研究与实现相互往返，最终以真实使用与视觉结果确认。

**探索的目的不是让 Agent 浏览得更多，而是让它发现本来可能错过的优秀设计，并有能力证明这些发现如何改变最终选择与实际作品。**
