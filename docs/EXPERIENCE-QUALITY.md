# UI Spec Studio｜完整产品体验的设计与验证

高质量 UI 由视觉表现、信息表达、交互行为、运行体验与业务结果共同形成。UI Spec Studio 将这些关系落实到既有设计流程，使 Agent 能够发现问题所在的设计层面，选择适合当前产品的方法，再通过实际结果确认改善。

## 九个相互关联的设计维度

| 维度 | Agent 作出的具体判断 | 主要方法位置 |
|---|---|---|
| 产品与交互模型 | 用户操作什么对象、有哪些真实选择、如何继续任务 | [分析](../skills/ui-spec/references/analysis.md) |
| 视觉设计与艺术指导 | 哪些层级、材质、比例和视觉关系形成产品气质 | [视觉原则](../skills/ui-spec/references/principles.md) |
| 视觉素材与资产工程 | 寻找或制作哪些素材，怎样保留母版、变体与应用关系 | [资产方法](../skills/ui-spec/references/visual-assets.md) |
| 内容设计与文字排版 | 用户应理解什么，何时出现，如何表达和呈现 | [内容方法](../skills/ui-spec/references/content-design.md) |
| 布局与空间构图 | 如何安排空间、运动范围、内容增长和滚动 | [视觉原则](../skills/ui-spec/references/principles.md)与[交互](../skills/ui-spec/references/interaction-and-variants.md) |
| 组件与完整状态 | 组件语义、材质、操作关系和各状态是否一致可用 | [交互与变体](../skills/ui-spec/references/interaction-and-variants.md) |
| 动效与交互连续性 | 对象怎样变化、何时反馈、如何处理往返和中断 | [交互与变体](../skills/ui-spec/references/interaction-and-variants.md#motion) |
| 性能与体验工程 | 哪段执行链路产生等待，哪些准备与调度有实际收益 | [交互](../skills/ui-spec/references/interaction-and-variants.md#preserve-the-primary-loop-and-perceived-responsiveness)、[接线](../skills/ui-spec/references/integration.md#prepare-data-with-correct-authority-and-lifetime)与[测量](../skills/ui-spec/references/verification.md#measure-performance-across-the-complete-task) |
| 运营体验与内容维护 | 内容由谁更新，共用与覆盖如何生效，批量操作如何恢复 | [内容](../skills/ui-spec/references/content-design.md#maintain-content-through-roles-and-updates)与[接线](../skills/ui-spec/references/integration.md#support-content-maintenance-and-operational-work) |

九个维度描述需要管理的设计对象；八份共同参考组织专业方法。它们共同参与 `init → iterate → finish`，`shape` 按需使用，`audit` 贯穿检查。任务决定需要深入的维度，已有项目记录可以继续沿用。

## 内容、结构与素材共同设计

内容先回答用户在当前节点需要理解什么，再选择标题、按钮、比较区域、帮助或状态反馈等载体。实际文字长度、字体、语言和视觉素材共同影响构图。一个更准确的名称可以简化导航，一项重要条件可以改变页面之间的信息分工，一个主视觉可以决定文字留白。

成熟设计资源也包括优秀产品的信息组织和语言范式。Agent 研究它们如何帮助用户理解，再结合当前产品的事实、品牌风格和使用任务进行适配。必要条件可以在多个决策节点重复出现，具体事实仍由同一权威来源维护。

## 从连续操作反推性能设计

以用户希望快速打开多个对象为例，先追踪输入、计算、请求、资源解码、状态更新、渲染与结果确认。由此判断哪些工作适合页面进入时准备，哪些能并行，哪些结果可复用，以及直接操作如何获得优先级。

提前准备的采用条件包括使用概率、有效期、资源成本和业务副作用。准备工作采用适当并发，避免重复请求，失效后重新核实；已准备对象可以即时响应，尚未就绪的对象提供准确状态，并让其他对象继续操作。创建报价、消耗配额、保留库存和正式提交分别遵循真实业务契约。

验证区分三种时间：**用户得到反馈、结果可供使用、权威操作完成**。同时观察额外请求、传输、渲染与内存成本。浏览器响应指标和任务完成时间分别记录；在等价条件下比较冷启动、缓存复用、连续输入和异常路径。

## 让动态界面保持位置感与可信状态

翻面、展开和切换都需要保留对象身份，检查正向、反向、中断与恢复。动态素材按完整运动范围参与空间分配。动画终点显示当前有效状态，业务结果由相应系统事实确定。

滚动结构由页面职责和内容增长方式决定。长文可以自然滚动，工作区可以保留导航并滚动内容，复杂工作台可以有职责明确的多个区域。检查新内容到达、展开、焦点移动、返回与缩放时的位置和阅读连续性。

## 让设计适应长期内容与运营工作

识别真实内容的来源、维护者、更新频率与复用关系。根据产品需要定义共享模板、分类默认值、单项覆盖和恢复继承；区分缺失值与有意留空。修改后预览实际生效内容及其影响对象。

批量操作由频率、规模和差异化需求决定。明确筛选和分页下的选择范围，逐项验证实际权限与结果，分别报告完成、失败、跳过、等待或结果未知的范围，并提供适当恢复。消费者与运营人员根据同一事实获取符合各自任务的说明。

## 将项目经验保留为有条件的方法

| 具体问题 | 可以迁移的判断 | 新项目需要重新决定的内容 |
|---|---|---|
| Favicon 辨识度不足 | 研究轮廓、负空间、光学平衡和实际小尺寸 | 当前品牌的独立图形 |
| 头像缺少整组品质 | 同时评价素材本身和组合后的裁切、颜色与识别 | 摄影、抽象、雕塑或其他艺术方向 |
| 文案重复、生硬 | 按信息职责、认知顺序与出现时机整理 | 具体词语、语气与页面分工 |
| 商品信息与动作分散 | 围绕实际业务对象组织内容、反馈和操作 | 卡片、列表、表格、消息或其他载体 |
| 翻面失去对象连续感 | 保持身份和往返、中断后的状态一致 | 当前任务需要的动画形式 |
| 连续操作需要等待 | 追踪关键依赖，判断提前准备、并行与复用 | 可提前执行的工作及其有效期 |
| 动态背景挤压文字 | 按完整运动范围安排空间与视觉层级 | 振幅、裁切、遮罩与布局 |
| 滚动与页面职责不符 | 从阅读、工作和内容增长决定滚动结构 | 页面滚动、局部滚动及区域数量 |
| 组件状态与材质脱节 | 将可辨状态、语义、焦点与材质一起设计 | 具体视觉处理和组件来源 |
| 操作地位或控件数量不合理 | 先判断操作关系和真实选择空间 | 主次、同级、顺序及选择器形态 |
| 内容与配置难以维护 | 明确来源、复用、覆盖、角色及恢复 | 模板层次、字段、格式和批量能力 |

## 如何确认本轮结果

在真实页面中检查关键文案、状态、布局和交互，在对应业务边界核实结果。截图用于观察画面；交互执行用于检查路径和连续性；任务计时与跟踪用于解释性能；真实维护操作用于验证运营效率。实际用户理解需要相应的用户观察。

仓库提供内容、素材、产品场景与时序观察的可运行样例。它们建立各自已执行范围的证据，具体产品仍依据自己的内容、设备、服务和用户任务验收。各版本的执行与观察范围见对应版本审查记录；持续观察的方法见[视觉观察指南](VISUAL-INSPECTION.md)。
