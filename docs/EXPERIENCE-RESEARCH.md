# 从用户意图到真实体验：研究、判断与实现

UI Spec Studio 以 **Intent-Grounded Experience Research & Evidence-Driven UI Design**（以用户意图为基础的体验研究与证据驱动设计）组织工作。先理解用户期待怎样使用产品，再规划重要证据；通过真实研究拓展和修正认识，采用适合的成熟实现，并回到实际使用检验品质。

**用户意图 → 体验假设与证据问题 → 研究和观察 → 候选比较 → 试装与适配 → 完整体验验证。**

这条关系可以反复往返。新资源可以改善构图，新操作证据可以改变产品模型，集成后的问题可以重新打开选型。它融入既有 `init → iterate → finish`，`shape` 处理重要方向，`audit` 随时检查相应范围。运行方法由现有八份公共参考承担；这份指南解释各项判断如何连接。

## 1. 把概括性期待展开为可研究的体验

当用户说「像某个成熟产品」，先理解它代表的使用经验：如何开始任务，操作什么对象，怎样阅读、编辑、切换、继续和获得结果，以及哪些视觉或动态细节形成了期待。

产品名称、业务能力和界面模型分别回答不同问题。一个具备文档检索与自动执行能力的「研究工作台」，可以由对话发起任务，也可以围绕文档编辑或项目管理展开。第一项操作、持续工作的对象、主要反馈及结果位置，才决定应研究哪些界面范式。

同时区分三类依据：

| 依据 | 可以建立的认识 | 使用条件 |
|---|---|---|
| 当前用户的意图 | 已表达目标、提供的参照、历史反馈、选择和授权范围 | 保留来源，明确仍在推断的部分 |
| 目标用户的经验 | 熟悉的操作惯例、常见任务及群体差异 | 结合真实研究或公开材料；适用性需要判断 |
| 参考产品的表现 | 实际页面、流程、状态、视觉语言及运行条件 | 标明相关版本、平台、角色和观察条件 |

群体惯例帮助提出假设，当前用户决定自身期待，产品证据说明参照实际如何工作。用户可能熟悉旧版本的阅读方式，也可能只希望继承某个局部交互。采用的参照范围应能解释这种具体需求。

建立可修正的体验假设时，分清已明确的目标、有依据的认识、推断和待研究问题。优先处理可能改变产品模型、主要任务、页面结构、艺术方向或资源选择的问题。常规细节由 Agent 自行研究和判断；只有影响较大且存在合理分歧的方向，才需要用少量实际候选帮助用户选择。

## 2. 围绕体验结构规划证据

体验结构包含页面、功能区域、工作对象、状态与任务之间的关系，还包括内容增长、角色、设备和时间变化。证据规划从这些关系展开，再选择合适的来源与工具。

| 研究对象 | 需要回答的问题 | 合适的证据 |
|---|---|---|
| 产品与用户 | 为什么使用，熟悉什么工作方式 | 用户需求、产品资料、用户研究、教程和有上下文的反馈 |
| 核心任务 | 怎样发起、持续、切换与完成 | 实际操作、代表性流程、交互演示 |
| 页面与信息架构 | 导航、内容与辅助区域怎样协作 | 完整页面、跨页面浏览、结构说明 |
| 视觉语言 | 什么关系形成所需气质与成熟度 | 真实渲染、局部细节、设计系统、相关艺术作品 |
| 状态与动态 | 输入、加载、展开、返回怎样连续发生 | 可操作演示、录屏、完整片段、连续帧 |
| 历史体验 | 哪些关系对应用户熟悉的版本和环境 | 有日期的版本资料、历史画面、实际使用记录 |
| 成熟实现 | 哪些资源可以承接已观察到的品质 | 模板、组件与素材原始演示、文档、源码、授权条件、局部试装 |
| 整体结果 | 真实任务是否清晰、流畅、稳定并保有表达 | 集成界面、连续操作、跨视口检查、性能与业务验证 |

观察一个输入区时，内容增长、附件、按钮状态、键盘操作、等待与回复可能共同决定它的品质。观察一个辅助工作区时，空间分配、主要输入位置、阅读宽度、焦点和返回路径可能共同影响整个产品模型。独立页面或组件的数量只能描述部分覆盖。

规划可以用短段落、已有设计记录或简图表达。其作用是决定下一项值得取得的证据，并在发现新关系时调整范围。

## 3. 让文字、视觉与行为证据互相校准

**文字材料**帮助理解功能语义、使用条件、产品定位、设计原因和历史变化。官方帮助、设计系统与实现文档分别说明其负责的事实；教程和公开反馈补充实际使用情境，并保留作者、版本与样本范围。

**视觉材料**支持对真实外观的判断。完整画面揭示构图、层级、密度和空间；细节观察揭示字形、边界、材质、图标及光学关系。源码与样式可以解释实现，最终感知品质仍由实际渲染确认。

**行为与时间材料**支持对过程的理解。操作、录屏和连续画面说明组件如何打开、增长、变化、恢复或响应新的输入。剪辑宣传展示其呈现的设计关系，实际延迟、失败恢复与连续操作则需要相应运行证据。

三者相互引出问题：文字发现重要机制后寻找对应画面；画面发现特殊结构后研究其用途和适用条件；操作发现不稳定时，再检查视觉关系、状态或工程原因。准确标明实际看见、资料描述、专业判断和仍未观察的内容，才能选择有效的补证方式。

## 4. 按设计价值决定探索强度

投入同时考虑三个因素：当前对象对体验与识别的**设计影响**，认识中仍存的**不确定性**，以及继续研究的**潜在改进价值**。

决定产品气质的字体、背景、三维素材或核心交互，即使体量很小，也可能值得跨大量独立来源、数十个候选和多轮试装持续研究。高价值任务可以进入百步级、小时级探索。常规控件已有成熟且适用的依据时，可以直接适配并检验改动。

研究强度通过实际问题调整。用户给出的时限、范围与运行条件保留约束；重要证据尚缺时，说明它会影响什么，继续能够推进的部分，并决定补证或有限试装。已有投入本身不能证明选择充分。

扩大来源也要扩大实际设计空间。同一作品的多个转载有助于获取材料，其共同出处仍属于同一设计依据。具有不同任务结构、构图、排版、材质或动态机制的成果，才可能带来新的选择。

搜索可以从真实产品转到组件，从组件转到字体或素材，再由新发现返回页面与产品方向。对于明确的艺术目标，相关出版、摄影、动态图形、三维作品和创作者案例也能成为重要参照；研究其能为当前任务提供什么价值。

## 5. 让每轮发现改变下一项行动

研究循环是：**提出问题 → 规划证据 → 搜索 → 实际观察 → 分析和比较 → 更新认识 → 采取下一项行动。**

每轮抓住可能改变选择的发现。例如，候选的成熟感主要来自排版，就继续研究字体、字重、宽度和实际语言条件；组件单独优秀却与页面冲突，就回到构图及邻近区域；关键词始终返回同一种效果，就更换视觉特征、产品类别或实现生态。

主动挑战已经偏好的方案。识别还有什么材料可能推翻当前选择，并寻找具有不同优势的成熟候选。比较使用相近的内容、主题、视口、任务和制作完成度，同时标明有意差异。重要判断包括：

- 是否承接用户期待的任务关系与品质目标。
- 构图、字体、空间、材质和细节怎样共同形成实际品质。
- 状态、反馈、返回、中断与连续操作是否完整。
- 艺术表达如何为当前产品带来有价值的差异。
- 授权、技术、维护和适配条件能否支持采用。

这些维度帮助解释选择，不必合成一个审美分数。比较应决定后续行动：继续寻找、进入试装、组合互补优势，或修改一个尚未确认的假设。

## 6. 判断证据是否足以支持当前决定

从五个相互补充的方面判断观察质量：

| 维度 | 要确认的内容 |
|---|---|
| 覆盖广度 | 重要页面、状态、视口、方向及其关系是否得到研究 |
| 观察深度 | 品质判断是否深入到相关构图、比例、排版、材质与细节 |
| 时间完整性 | 过程证据能否解释相关交互和动态关系 |
| 证据相关性 | 材料是否对应当前设计问题及目标体验 |
| 证据可靠性 | 来源、版本、展示条件与局限是否支持结论 |

使用[人类视觉感知方法](VISUAL-INSPECTION.md)，从正常尺度下的整体印象进入构图、区域与细节，随后回到完整页面。对运动先理解正常过程，再定位关键片段或细节，最后重新判断连续体验。放大、裁切、受控时间与性能测量各自支持对应结论。

据此区分三种下一步：

| 下一步 | 适用情况 |
|---|---|
| **继续研究** | 关键体验仍不明确，候选缺少实质差异，或新的证据很可能改变方向和选型 |
| **局部试装** | 目标和候选已有相关依据，剩余关键问题需要当前项目的字体、内容、主题和状态来验证 |
| **扩大实现** | 重要选择经过比较，关键试装保留目标品质，适配路径清楚，剩余空缺有适当验证位置 |

新增搜索主要返回相似结果时，检查它是否来自真实的候选收敛，还是过窄的搜索方式。已有方案仍明显低于明确的艺术或交互目标时，继续研究仍有价值。扩大实现后出现重大差距，则重新打开对应问题。

## 7. 通过获取韧性补足重要证据

单一来源受阻时，围绕同一个问题寻找正常可用的路径：原作者公开演示、官方说明、项目仓库、其他发布渠道、教程、视频或可运行版本。替代材料应保留其实际来源和展示条件；相似作品可以补充候选，尚未看见的目标状态仍保持未确认。

需要正常人工登录、官方客户端、授权下载或特定环境时，先完成可行的自主研究，再集中提出具体取材请求：哪个来源，执行什么操作，覆盖哪些状态或连续片段，将解决哪项设计选择。例如，一段包含打开辅助面板、继续输入、关闭并返回的录屏，可以同时支持空间、焦点和连续性判断。

取得材料后，Agent 继续负责观察、比较、选型和验证。研究中允许观察的材料，与可以集成或公开分发的资源，分别确认其条件。独立工作在缺口处理期间继续推进。

## 8. 让研究进入实际采用与整体验收

将**目标体验研究**和**实现资源研究**持续配对。前者确定值得继承的品质，后者寻找能够承接品质的页面、系统、区块、组件、字体、素材和动效。优秀实现也可以反过来改善原来的方向。

通用 UI 优先采用适合的成熟实现，通过配置、组合与针对性二次开发保留其价值。独特需求或已验证的资源缺口继续推动研究与适配；只有符合 W1–W3 且具有实际范围授权时才能开展原创，并承担新增部分的制作和验证责任。设计关系的继承、代码或资产的实际采用，分别保留依据。

关键部分先用真实内容、字体、主题和状态试装，再检查完整页面和连续任务。原始演示、局部试装与组合结果分别回答资源品质、当前适用性及整体协调性。适配引起的字形变化、内容增长、材质冲突、动态干扰和累计性能成本都应回到相应层面处理。

最终验收回到用户的任务，分别检查体验对齐、视觉成熟度、独立表达和工程可靠性。性能检查连接首次反馈、可用结果和权威完成；视觉检查连接整体、细节和时间过程；实际业务检查确认相应结果。每种结论保留其真实证据范围。

## 9. 保留能够继续工作的设计依据

重要决定应当让人看懂：用户目标是什么，研究了什么，观察到什么，比较过哪些差异，为什么选择这个实现，以及当前项目中的结果怎样。

沿用项目已有记录，配合代表性的截图、片段、链接或可运行预览即可。记录反映结论如何形成和影响实际采用；用户无需阅读逐次检索日志。相同条件下的常规组件可以共同引用已验证的体系，关键例外保留自己的依据。

研究结论还应说明哪些认识已被修正，哪些限制仍可能影响后续工作。这样，下一轮可以从当前证据继续，而不必依赖对先前方案的笼统信心。可选[设计决策记录](DESIGN-DECISIONS.md)和[资源复用指南](RESOURCE-REUSE.md)提供组织方式。

## 10. 三个应用情境

以下是方法示例，各自说明需要怎样的证据；其描述不代表已经执行的产品研究。

**具有研究能力的对话应用。** 先从用户如何发起、阅读、追问和回到资料判断主要工作模型。文字资料解释任务与附件，真实画面检查长内容和辅助区域，完整操作观察打开、继续、关闭和恢复。比较不同辅助工作区关系后，选择成熟结构试装；结果再检验是否保持主要任务连续性。具体产品名称提供入口，界面结构由这些依据逐步确定。

**承担品牌识别的动态背景。** 先确定它在输入、阅读和结果中的表达职责，再搜索跨领域作品及可采用素材。完整运动揭示亮度峰值、运动范围、循环接缝与注意力变化；试装让背景面对真实文字、控件和降低动态效果条件。资源投入可以超过普通组件，因为它决定整体感知；选择仍需兼顾实际表达、交互和运行表现。

**发布在 GitHub 的 README。** 先确认新读者需要判断用途、安装并完成首次使用。研究同类成熟文档的阅读组织，结合宿主原生标题、文字、链接、代码和图片能力。观察真实渲染、窄屏阅读和主题变体，再将结构与素材适配到当前内容。这种复用以宿主能力、成熟阅读关系和已有资产为基础，完成条件包含命令、链接和最终发布呈现。仓库已有的 [README 设计记录](design/README-SPEC.md)保留其实际研究与观察范围。

## 运行知识与使用入口

入口、工作组织和专业方法仍有明确分工：[SKILL.md](../skills/ui-spec/SKILL.md)建立默认行为；[analysis](../skills/ui-spec/references/analysis.md)负责体验理解与证据规划；[component-sourcing](../skills/ui-spec/references/component-sourcing.md)负责探索、比较与采用；[principles](../skills/ui-spec/references/principles.md)和[verification](../skills/ui-spec/references/verification.md)负责感知判断、证据质量与复验；其余公共参考承接内容、资产和交互。具体项目保存自己的体验目标、选择与实际结果。

最终评价关注四件事：是否理解正确的体验，是否发现原先可能错过的优秀成果，证据是否实际改变选择，以及产品是否因此获得符合目标的视觉与交互品质。
