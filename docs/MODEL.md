# 理解模型：低指导成本的设计与工程交付

本文是 UI Spec Studio 1.9 的维护者设计依据。Agent 运行时以 `SKILL.md` 和其参考文件为工作指令；本文解释这些文件为何这样组织。

## 1. 产品目标

以 Product UI Experience Alignment（产品 UI 体验对齐）组织设计目标：当前用户、任务、内容与运行条件需要怎样的实际体验。成熟参照建立品质目标，适合的成熟实现承接目标，局部试装、适配与整体审阅确认最终结果。Agent 承担理解、探索、选择、实现和验证，用户通过目标、实际结果和必要确认推动工作。指定产品、仅提供功能、升级现有产品与探索新颖交互，都应形成有依据的下一步。

成功取决于设计质量、用户任务完整性、可控迭代成本和真实接线结果。页面数量、规则数量、读取次数和测试数量分别只是工程观察量。

## 2. 五个相互连接的层次

| 层次 | 决定什么 | 权威位置 |
|---|---|---|
| 产品与用户 | 为什么做、谁使用、什么结果有价值 | 用户需求、产品资料与业务事实 |
| 体验与视觉 | 页面职责、状态路径、视觉方向和共享规则 | 项目设计记录、批准范围与 SPEC |
| 工作组织 | 何时理解、探索、实现、审查和接线 | workflow.md |
| 专业判断 | 如何分析、构图、选型、交互和验证 | 八份通用参考及 integration.md |
| 实际执行 | 当前有什么、做了什么、实际效果如何 | 源码、运行结果、画面与连续片段、测试与审批来源 |

各来源按职责使用。现有代码说明当前实现，用户目标说明预期结果，批准设计约束需要保留的体验。事实与意图发生冲突时，在相应职责层协调处理。

## 3. 用户引导与自主判断

常规设计和实现由 Agent 主动推进。用户提供方向时将其转成具体约束；方向开放时，Agent 从产品特征、内容、用户任务和可用素材形成推荐，用可运行的结果支持评价。

对不确定性进行分类：产品问题通过任务与内容分析处理，审美问题通过小范围视觉探索处理，技术问题通过实现验证处理，重要业务承诺通过权威规则和授权处理。选择行动时综合影响、可逆性、证据和验证成本。

这一方法保留专业主动权，也保留用户对方向和重要承诺的控制。它是工作方法设计，实际效果由具体模型与任务共同决定。

## 4. 流程是可组合能力

主线采用 init、iterate、finish；audit 贯穿执行；shape 按需出现。

**Init** 建立足以正确继续的初始理解。**Shape** 处理会影响下一步的重要方向问题，以有限分析、参考研究和代表性实现收敛。**Iterate** 围绕一个可评价结果小步推进。**Finish** 完成全面接线，包括现状对齐、契约、顺序、连接、双轨验证和交付。

阶段不是必须逐个执行的审批程序。设计已明确的局部请求可以直接迭代；批准范围完整的项目可以进入 finish。一个项目中的不同页面可以同时处于不同成熟度。

## 5. 上下文契约

八份高度相关、篇幅受控的通用参考完整读取：workflow、analysis、principles、component-sourcing、interaction-and-variants、verification、visual-assets、content-design。其目标是为无法预先穷举的设计判断提供充分依据，减少用户反复强调设计原则的负担。

Integration 在真实业务边界工作中必读。Examples、Sources、项目接口和实际组件文档按专业需要补充。完整读取与执行全部操作是两个概念：参考提供判断能力，当前任务决定行动深度。

Skill 能规定阅读要求、引用关系、专业方法和成果检查。Agent 运用这些内容。Harness 控制激活、工具、消息、上下文保留和压缩。读取记录只能证明其记录的动作；内容正确运用需要结合结果判断。

当前上下文已有且有效的材料可以复用；资料缺失、读取截断或版本不明确时重新读取。项目记录用于保存权威事实，Git 保存源码历史。此设计保持普通文件工作流和宿主中立。

## 6. 文件分工

| 文件 | 职责 |
|---|---|
| SKILL.md | 入口、共同读取契约、来源职责、基本边界和交付行为 |
| workflow.md | 组织 init、可选 shape、iterate、audit、finish 的内部活动 |
| analysis.md | 用户、产品、UX、优先级、不确定性与自主判断 |
| principles.md | 视觉关系、层级、尺度、构图、共享结构和适用条件 |
| component-sourcing.md | 组件职责、研究深度、候选适配、素材与授权 |
| interaction-and-variants.md | 语义、焦点、语言、主题、动效和状态连续性 |
| verification.md | 范围、证据、真实渲染、任务检查、修复复验 |
| visual-assets.md | 视觉素材的职责、制作路径、母版到交付、资产族验收及界面整合 |
| content-design.md | 用户认知、信息分布、Voice/Tone、实际文案、文字视觉、本地化与内容维护 |
| integration.md | 已批准设计与真实业务能力之间的差量接线 |
| examples.md / sources.md | 场景说明与研究出处 |

入口引用专业规则，工作流安排运用时机，参考文档保存详细方法。复用必要概念，保持每项详细规则的主要来源明确。

## 7. 设计原则的强度

职责约束定义正确性；设计原则支持判断；默认偏好提供起点；示例解释某个应用。它们采用不同指令强度。

通用要求包括可读、可操作、真实状态、任务可达和共享结构连续。字体、色彩、材质、表现强度与布局形式结合项目确定。紧凑任务的居中或略偏上是适用偏好，阅读流与工作台采用符合用途的空间规则。

## 8. 一轮工作的完整性

每轮需要有明确结果、可运行范围和可评价效果。完成后，呈现实际入口、重要选择、观察证据和下一项推荐。用户可以仅确认继续，也可以提出模糊或具体反馈。

模糊反馈首先转成可检验的问题解释。例如“偏低”涉及内容重量与留白，“切换跳变”涉及共享框架、组件身份、滚动和动效。用实际证据选择修复层级，再复验关联影响。

## 9. 真实接线与验收

批准设计、当前代码、业务契约和运行结果共同决定接线范围。每项重要动作可以追踪到真实权威与结果。可复用能力直接使用，所需差量在当前架构中实现。

视觉轨验证批准体验在真实数据和状态下的表现；产品轨验证权限、规则、持久化、失败恢复和实际结果。静态、本地和服务端产品分别按自身边界验证。发布授权与功能实现状态分别记录。

## 10. 发布保证的适当范围

本版本采用逐文件审查、逻辑情境推演和确定性工程测试。包结构、引用、工具行为、安装、构建及发布可以得到直接证据；模型理解、审美质量和项目效果由实际使用观察。

大规模 Agent 对比评测属于可选研究。实际 UI 任务的浏览器观察与真实接线验证，仍然是相应任务完成条件。两者具有不同对象和成本。

## 11. 专业能力：从意义到可控实现

专业模型连接四项能力：理解与观察、构思与表达、制作与控制、判断与改进。它们通过一条设计推导关系相互作用：

**任务与事实 → 所需理解 → 表达概念 → 信息/视觉/交互语言 → 素材与实现 → 实际结果。**

这是一条推理关系，而不是新增阶段或强制报告。每个环节回答不同问题：用户为何行动、需要什么信息、怎样组织才能理解、如何形成具体形式、怎样准确制作、实际效果是否支持判断。

八个补强方向包括内容与表达策略、艺术指导与概念生成、具体视觉语法、信息表现与交互范式、素材与媒介策略、时间编排、分层观察与因果诊断、可编辑表达与四层保真。通用方法融合进八份共同参考，专项技法由 patterns.md 提供条件明确的示例。

## 12. 屏幕表达的通用性

产品页面、README、文档、图表和演示材料都具有受众、注意力顺序、信息关系与交付环境。按媒介实际能力实现：README 的标题、链接和代码块本身就是阅读与行动界面；视频的作者时间与实时 UI 的用户/服务时间分别处理。

流程仍然是可选 Shape、连续 Iterate 和全面 Finish。静态发布以真实内容、链接、资产和最终宿主呈现完成接线；服务型产品进一步验证权限、业务规则和持久化。

## 13. 专业知识的积累单位

保存能够解释效果的方法：问题、机制、适用条件、可编辑实现与观察证据。项目偏好留在项目中，可迁移方法通过明确授权的维护更新进入 Skill。案例提供有边界的判断依据；这一过程是知识维护，不是模型训练或宿主自我修改。

## 14. 资源生态参与设计和实现

资源发现拓展表达与实现的选择空间，评估明确采用价值，适配与组合形成产品表达，实际验证确认品质，使用记录支持后续复用。

将需求驱动检索与机会驱动探索共同纳入工作。前者为已知需求寻找可靠实现，后者在重要设计尚有空间时发现更好的表达。项目目标和已批准方向保持约束，现有组件、原生能力与外部资源一起参与判断。

通用 UI 职责优先由合适的成熟实现承担，通过直接集成、配置、组合和必要二次开发完成。研究形成的设计认识继续指导实际资源采用；技法迁移提供设计依据，其重新实现部分仍承担相应的制作与验证责任。定制针对候选无法满足的具体缺口，优先在成熟基础上扩展。判断同时考虑必要行为、视觉契合、技术、使用条件，以及发现到维护的总成本。Agent 对组合后的项目结果负责。

通用方法留在共同必读的 component-sourcing.md；资源目录提供定位与来源；具体采用记录留在项目。八份共同参考和原有阶段保持连续。目录检索是可选的本地只读工具，实际外部访问、安装、写入和运行由宿主授权能力完成。

## 15. 产品体验对齐组织研究与判断

产品 UI 体验对齐确定当前项目的目标体验；参考产品对齐借助一个具体产品展开该目标，是更广泛的设计参照选择与适配的一种应用。设计系统、组件演示、素材作品和平台惯例也可以独立提供参照。

通过第一项操作、主要工作对象、重复循环、继续方式和结果位置识别产品模型。用户给出的名称是压缩的体验描述：进一步研究其相关页面、流程、品牌气质或局部交互。没有名称时，从任务与关键组成主动寻找成熟依据。升级保留经验证的语义与工程资产；新颖交互可继承成熟的局部关系，再验证整体组合。

多层参照覆盖产品与任务、页面与区域、组件与状态、素材与语言、时间与连续性。每个高影响问题获得充分依据，统一体系中的常规实例继承适用规则。主导设计语言协调各来源。重要且仍有合理分歧的方向用少量实际方案帮助用户确认，已有明确意图与授权支持继续推进。

## 16. 主动探索连接成熟决策与可运行方案

设计知识提出问题；主动探索获得实际对象；时序观察理解连续体验；工程分析解释实现条件；资源适配形成当前产品。搜索围绕任务、模式、组件职责和实现需求演进。播放、滚动、切换和展开由相关线索触发，新的发现可以改变搜索与原有判断。

区分承载页面、播放器、演示内应用与作品内容，分别说明观察对象及其能支持的判断。既有演示与主动录制按证据缺口配合；工具选择服从问题、实际能力与授权。观察、解释和待验证原因各自保留依据。

复用包含成熟设计决策的继承和工程实现的采用，两者可以来自不同来源。新页面从最高适当层级研究整页、设计系统或功能区块，再补足局部需要。重要品质应能指向实际采用的代码、结构、组件或素材，以及适配后保留的机制；依赖数量和代码比例分别只是工程观察量。适配代码属于复用驱动实现。现有资产通过明确接受或实际适用性继续保留。

重要记录连接目标体验、来源和相关片段、观察条件、设计关系、采用调整、实现位置及复验。关键组成在扩大整合前，用当前字体、内容、主题和状态完成局部试装；已验证且条件相同的常规实例可以继承相应证据。适配先考虑内容、配置和组合，内部修改按具体缺口展开，验证范围跟随实际变化。关键品质得到确认且适配路径清楚时推进整合，其余空缺按影响继续处理。

重要来源受访问条件限制时，先完成可行研究，再集中请求正常登录、取材或授权下载所需的用户协助；专业比较和判断仍由 Agent 完成。目标暂时无法达到时，记录差距、影响和路径，必要的范围或品质调整成为显式选择。详细说明见[资源复用指南](RESOURCE-REUSE.md)、[产品对齐指南](PRODUCT-ALIGNMENT.md)与[设计决策指南](DESIGN-DECISIONS.md)。

## 17. 素材参与的设计工程

页面结构、交互和视觉素材共同构成设计。素材复用层级描述范围，而不是重要性：一个核心图形、字标或空间化资产可以成为整个构图的起点。第七份共同参考 visual-assets.md 保证相关判断在一般设计工作中可用，专项来源与记录模板按实际任务使用。

从用途和观看条件决定素材，研究候选及制作路径，保留可编辑母版与交付变体，再在真实页面检查。制作方法与交付模式分别选择；静态、预制和实时输出有不同的质量、性能和维护要求。工具知识、宿主能力、实际生产和结果验收分别记录。

## 18. 内容设计、用户语言与文字视觉协同

内容设计、UX Writing 与字体排版共同决定用户在什么时候理解什么，并直接影响页面的结构与视觉节奏。产品事实与业务规则是语言表达的依据；同类成熟产品提供术语和内容组织的参照；品牌 Voice 与场景 Tone 共同决定写作方式。标签、按钮、状态、错误、帮助、关键条件和多语言版本，分别在其用户任务节点发挥作用。

第八份共同参考 content-design.md 负责整体方法；分析、工作流、视觉、交互、验证和接线参考仅保留其职责下的调用。需要追溯的重要文字与状态有可选记录模板。实际浏览器示例通过多语言、布局与交互检查核实局部效果。自动化机制、人工内容审阅、真实用户理解和业务授权属于不同的证据。

## 19. 完整产品体验与长期运营

九个设计维度共同描述实际体验：产品与交互模型、视觉设计与艺术指导、视觉素材、内容与排版、布局与空间、组件与状态、动效连续性、性能体验、持续运营。维度用于识别应作出的判断；八份共同参考负责提供方法，integration.md 负责真实业务接线。

从用户连续操作反推输入、计算、请求、渲染和确认链路，再决定准备时机、并发、缓存及反馈。通过实际条件下的观察判断收益与成本；界面反馈、可用结果和权威完成分别验证。内容来源、模板、单项覆盖、角色任务和批量恢复共同决定长期维护方式。

专业原则继承其机制和适用条件。某项目采用局部滚动、同级购买操作或卡片翻面，只说明当时的任务选择；新项目从真实对象、选择空间和内容增长重新判断。完整方法与案例映射见[体验质量指南](EXPERIENCE-QUALITY.md)。

## 20. 视觉观察连接知识、资源与实际体验

Visual Reasoning & Visual Inspection 是贯穿八份共同参考的工作能力。产品目标决定观察重点，实际画面提供可分析的对象，专业知识解释视觉关系，工程证据帮助定位原因，再通过查看调整后的结果验证判断。成熟参照、候选原始演示、当前项目局部试装和整合后的使用流程分别拥有观察依据。对齐关注当前任务需要的设计成熟度，品牌表达、外形与参数按产品确定。

观察同时覆盖整体画面与局部细节、具有时间关系的连续片段，以及跨页面的用户旅程。Temporal Visual Inspection 根据行为确定窗口：微交互覆盖触发到稳定结果，循环效果覆盖周期和接缝，异步任务覆盖等待与结果，复杂流程连接出发、过渡、到达和继续操作。必要的反向、中断、连续输入、加载变化与减少动态效果条件随任务纳入。

记录建立可检查的判断关系：看到的现象、可能的感知影响、适用的设计原理、需要检验的原因、采取的调整与实际复验。采集完成、像素已查看、操作已执行、工程测量与用户批准分别表达其事实。普通播放、逐帧定位和受控时间实验各有用途，结论跟随其实际证据范围。

入口建立默认行为，工作流安排使用时机，视觉与交互参考提供判断维度，verification.md 负责观察窗口与证据方法。专项说明见[视觉观察指南](VISUAL-INSPECTION.md)。原有主线、八份共同参考和任务决定执行深度的原则保持连续。
