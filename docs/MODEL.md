# 理解模型：低指导成本的设计与工程交付

本文是 UI Spec Studio 1.15 的维护者设计依据。Agent 运行时以 `SKILL.md` 和其参考文件为工作指令；本文解释这些文件为何这样组织。

## 1. 产品目标

以 Product UI Experience Alignment（产品 UI 体验对齐）组织设计目标：当前用户、任务、内容与运行条件需要怎样的实际体验。先将用户意图转成可修正的体验假设，再按任务、页面、状态及其关系规划文字、视觉与行为证据。成熟参照建立品质目标，适合的成熟实现承接目标，局部试装、适配与整体审阅确认最终结果。Agent 承担理解、探索、选择、实现和验证，用户通过目标、实际结果和必要确认推动工作。指定产品、仅提供功能、升级现有产品与探索新颖交互，都应形成有依据的下一步。

成功取决于设计质量、用户任务完整性、可控迭代成本和真实接线结果。页面数量、规则数量、读取次数和测试数量分别只是工程观察量。

任务要求与明确的审美目标共同决定交付。专业应用可以拥有鲜明的艺术表达；产品类型提供任务和使用条件，视觉语言由用户意图、研究与真实结果确定。以熟悉的对象、操作和反馈支持独立构图与材质，通过体验成立性和表达完成度分别检查结果。

## 2. 五个相互连接的层次

| 层次 | 决定什么 | 权威位置 |
|---|---|---|
| 产品与用户 | 为什么做、谁使用、什么结果有价值 | 用户需求、产品资料与业务事实 |
| 体验与视觉 | 页面职责、状态路径、视觉方向和共享规则 | 项目设计记录、批准范围与 SPEC |
| 工作组织 | 何时理解、探索、实现、审查和接线 | workflow.md |
| 专业判断 | 如何分析、构图、选型、交互和验证 | 八份通用参考及 integration.md |
| 实际执行 | 当前有什么、做了什么、实际效果如何 | 源码、运行结果、画面与连续片段、测试与审批来源 |

各来源按职责使用。现有代码说明当前实现，用户目标说明预期结果，批准设计约束需要保留的体验。事实与意图发生冲突时，在相应职责层协调处理。

## 3. 用户引导与自主判断

常规设计和实现由 Agent 主动推进。用户提供方向时将其转成具体约束；方向开放时，Agent 从产品特征、内容、用户任务和可用素材形成推荐，用可运行的结果支持评价。

对不确定性进行分类：产品问题结合任务、内容与实际使用研究处理，审美问题通过视觉探索和有实质差异的比较处理，技术问题通过实现验证处理，重要业务承诺通过权威规则和授权处理。研究强度综合设计影响、不确定性和潜在改进价值；行动同时考虑可逆性和验证成本。高影响问题可以需要跨大量来源的持续研究，已有依据的常规部分可以较快推进。

这一方法保留专业主动权，也保留用户对方向和重要承诺的控制。它是工作方法设计，实际效果由具体模型与任务共同决定。

## 4. 流程是可组合能力

主线采用 init、iterate、finish；audit 贯穿执行；shape 按需出现。

**Init** 建立足以正确继续的初始理解与证据问题。**Shape** 处理会影响下一步的重要方向，通过适当深度的研究、比较和代表性实现收敛。**Iterate** 围绕一个可评价结果推进。**Finish** 完成全面接线，包括现状对齐、契约、顺序、连接、双轨验证和交付。继续研究、局部试装和扩大实现分别需要相应成熟度的证据。

阶段不是必须逐个执行的审批程序。设计已明确的局部请求可以直接迭代；批准范围完整的项目可以进入 finish。一个项目中的不同页面可以同时处于不同成熟度。

## 5. 上下文契约

八份知识完整、分工明确的通用参考完整读取：workflow、analysis、principles、component-sourcing、interaction-and-variants、verification、visual-assets、content-design。其目标是为无法预先穷举的设计判断提供充分依据，减少用户反复强调设计原则的负担。

Integration 在真实业务边界工作中必读。Examples、Sources、项目接口和实际组件文档按专业需要补充。完整读取与执行全部操作是两个概念：参考提供判断能力，当前任务决定行动深度。

Skill 能规定阅读要求、引用关系、专业方法和成果检查。Agent 运用这些内容。Harness 控制激活、工具、消息、上下文保留和压缩。读取记录只能证明其记录的动作；内容正确运用需要结合结果判断。

当前上下文已有且有效的材料可以复用；资料缺失、读取截断或版本不明确时重新读取。项目记录用于保存权威事实，Git 保存源码历史。此设计保持普通文件工作流和宿主中立。

## 7. 设计原则的强度

职责约束定义正确性；设计原则支持判断；默认偏好提供起点；示例解释某个应用。它们采用不同指令强度。

通用要求包括可读、可操作、真实状态、任务可达和共享结构连续。用户明确提出的艺术性、视觉冲击力与差异化同样进入交付要求；常见配色、容器形态和行业外观仍可重新研究。字体、色彩、材质、表现强度与布局形式结合项目确定。紧凑任务的居中或略偏上是适用偏好，阅读流与工作台采用符合用途的空间规则。

## 8. 一轮工作的完整性

每轮需要有明确结果、可运行范围和可评价效果。完成后，呈现实际入口、重要选择、观察证据和下一项推荐。用户可以仅确认继续，也可以提出模糊或具体反馈。

模糊反馈首先转成可检验的问题解释。例如“偏低”涉及内容重量与留白，“切换跳变”涉及共享框架、组件身份、滚动和动效。用实际证据选择修复层级，再复验关联影响。

## 9. 真实接线与验收

批准设计、当前代码、业务契约和运行结果共同决定接线范围。每项重要动作可以追踪到真实权威与结果。可复用能力直接使用，所需差量在当前架构中实现。

视觉轨验证批准体验、艺术方向与感知品质在真实数据和状态下的表现；产品轨验证权限、规则、持久化、失败恢复和实际结果。体验成立性与表达完成度各自保留结论，源设计保真另行保护已经采用或批准的设计细节。静态、本地和服务端产品分别按自身边界验证。发布授权与功能实现状态分别记录。

## 10. 发布保证的适当范围

本版本采用逐文件审查、逻辑情境推演和确定性工程测试。包结构、引用、工具行为、安装、构建及发布可以得到直接证据；模型理解、审美质量和项目效果由实际使用观察。

大规模 Agent 对比评测属于可选研究。实际 UI 任务的浏览器观察与真实接线验证，仍然是相应任务完成条件。两者具有不同对象和成本。

## 11. 专业能力：从意义到可控实现

专业模型连接四项能力：理解与观察、构思与表达、制作与控制、判断与改进。它们通过一条设计推导关系相互作用：

**任务与事实 → 所需理解 → 表达概念 → 信息/视觉/交互语言 → 素材与实现 → 实际结果。**

这是一条推理关系，而不是新增阶段或强制报告。每个环节回答不同问题：用户为何行动、需要什么信息、怎样组织才能理解、如何形成具体形式、怎样准确制作、实际效果是否支持判断。

八个补强方向包括内容与表达策略、艺术指导与概念生成、具体视觉语法、信息表现与交互范式、素材与媒介策略、时间编排、分层观察与因果诊断、可编辑表达与四层保真。通用方法融合进八份共同参考，专项技法由 patterns.md 提供条件明确的示例。

艺术指导将主题和注意力转成构图、字体、素材、组件及动态关系。视觉系统通过角色分工和共同规则维护这种表达；成熟实现承接通用职责，专业制作完成有价值的差异。表达性反差让熟悉任务与跨领域视觉语言共同进入已填入真实内容的核心界面。完整说明见[艺术指导与表达性反差](ART-DIRECTION.md)。

## 12. 屏幕表达的通用性

产品页面、README、文档、图表和演示材料都具有受众、注意力顺序、信息关系与交付环境。按媒介实际能力实现：README 的标题、链接和代码块本身就是阅读与行动界面；真实产品、代表性产品演示与独立动态作品分别确定交互、事实和输出边界。固定舞台及确定性时间轴适合相应的作者输出，实时 UI 仍以用户意图与真实服务状态推进。

流程仍然是可选 Shape、连续 Iterate 和全面 Finish。静态发布以真实内容、链接、资产和最终宿主呈现完成接线；服务型产品进一步验证权限、业务规则和持久化。

## 13. 专业知识的积累单位

保存能够解释效果的方法：问题、机制、适用条件、可编辑实现与观察证据。项目偏好留在项目中，可迁移方法通过明确授权的维护更新进入 Skill。案例提供有边界的判断依据；这一过程是知识维护，不是模型训练或宿主自我修改。

## 14. 资源生态参与设计和实现

资源发现拓展表达与实现的选择空间，评估明确采用价值，适配与组合形成产品表达，实际验证确认品质，使用记录支持后续复用。

将需求驱动检索与机会驱动探索共同纳入工作。前者为已知需求寻找可靠实现，后者在重要设计尚有空间时发现更好的表达。项目目标和已批准方向保持约束，现有组件、原生能力与外部资源一起参与判断。

通用 UI 职责优先由合适的成熟实现承担，通过直接集成、配置、组合和必要二次开发完成。研究形成的设计认识继续指导实际资源采用；技法迁移提供设计依据，其重新实现部分仍承担相应的制作与验证责任。定制针对候选无法满足的具体缺口，优先在成熟基础上扩展。判断同时考虑必要行为、视觉契合、技术、使用条件，以及发现到维护的总成本。Agent 对组合后的项目结果负责。

通用方法留在共同必读的 component-sourcing.md；资源目录提供定位与来源；具体采用记录留在项目。八份共同参考和原有阶段保持连续。目录检索是可选的本地只读工具，实际外部访问、安装、写入和运行由宿主授权能力完成。

## 15. 产品体验对齐组织研究与判断

产品 UI 体验对齐确定当前项目的目标体验；参考产品对齐借助一个具体产品展开该目标，是更广泛的设计参照选择与适配的一种应用。设计系统、组件演示、素材作品和平台惯例也可以独立提供参照。

通过第一项操作、主要工作对象、重复循环、继续方式和结果位置识别产品模型。用户给出的名称是压缩的体验描述：进一步研究其相关页面、流程、品牌气质或局部交互。没有名称时，从任务与关键组成主动寻找成熟依据。升级保留经验证的语义与工程资产；新颖交互可继承成熟的局部关系，再验证整体组合。

当前用户意图、目标群体经验和参考产品事实分别建立依据，再判断它们如何支持当前选择。用户可能熟悉某个历史版本，公开反馈可能来自不同角色或平台；记录相关条件，用适当证据解释体验预期。产品名称和能力提供领域事实，实际操作循环决定界面模型。

多层参照覆盖产品与任务、页面与区域、组件与状态、素材与语言、时间与连续性。每个高影响问题获得充分依据，统一体系中的常规实例继承适用规则。主导设计语言协调各来源。重要且仍有合理分歧的方向用少量实际方案帮助用户确认，已有明确意图与授权支持继续推进。

功能与体验参照、艺术与表达参照、成熟实现资源共同发展方案。明确追求艺术表达时，研究延伸到相关跨领域作品，并以实际题材、构图或动态语言形成有实质区别的候选。比较保持内容、条件与制作成熟度相称；原有任务关系并不自动固定页面位置或容器外形。

## 16. 主动探索连接成熟决策与可运行方案

设计知识帮助形成体验假设与证据问题；文字研究解释语义和背景，真实视觉观察理解品质，行为与时间研究确认连续体验，工程分析解释实现条件，资源适配形成当前产品。搜索围绕任务、模式、组件职责、艺术表达和实现需求演进。每轮发现应改变认识或确认有用关系，并驱动下一项实际研究、试装或实现行动。

探索强度由设计影响、不确定性和潜在改进价值共同决定。关键字体、素材或交互可以投入百步级、小时级研究；已验证的常规部分沿用适当依据。主动寻找能挑战首选的候选，按实际构图、排版、材质、行为和动态差异比较。多个转载保留其共同来源，避免用网址数量替代设计空间覆盖。

区分承载页面、播放器、演示内应用与作品内容，分别说明观察对象及其能支持的判断。既有演示与主动录制按证据缺口配合；工具选择服从问题、实际能力与授权。观察、解释和待验证原因各自保留依据。

复用包含成熟设计决策的继承和工程实现的采用，两者可以来自不同来源。新页面从最高适当层级研究整页、设计系统或功能区块，再补足局部需要。重要品质应能指向实际采用的代码、结构、组件或素材，以及适配后保留的机制；依赖数量和代码比例分别只是工程观察量。适配代码属于复用驱动实现。现有资产通过明确接受或实际适用性继续保留。

重要记录连接用户目标、研究问题、来源和相关片段、观察条件、候选差异、采用调整、实现位置及复验。判断目标理解、证据覆盖与深度、比较质量、实现路径和剩余不确定性，再决定下一步：可能改变核心选择的缺口继续研究；已有依据的候选进入当前条件下的局部试装；关键适配得到确认后扩大整合。已验证且条件相同的常规实例可以继承相应证据。适配先考虑内容、配置和组合，内部修改按具体缺口展开，验证范围跟随实际变化。

重要来源受访问条件限制时，沿原始演示、作者发布、文档、仓库、视频或其他合法渠道补证，再集中请求正常登录、取材或授权下载所需的用户协助；专业比较和判断仍由 Agent 完成。替代材料说明其实际支持范围，未观察的关键状态继续保留为空缺。目标暂时无法达到时，记录差距、影响和路径，必要的范围或品质调整成为显式选择。完整因果与例子见[体验研究指南](EXPERIENCE-RESEARCH.md)，专项方法见[资源复用](RESOURCE-REUSE.md)、[产品对齐](PRODUCT-ALIGNMENT.md)与[设计决策](DESIGN-DECISIONS.md)。

## 17. 素材参与的设计工程

页面结构、交互和视觉素材共同构成设计。素材复用层级描述范围，而不是重要性：一个核心图形、字标或空间化资产可以成为整个构图的起点。第七份共同参考 visual-assets.md 保证相关判断在一般设计工作中可用，专项来源与记录模板按实际任务使用。

从用途和观看条件决定素材，研究候选及制作路径，保留可编辑母版与交付变体，再在真实页面检查。制作方法与交付模式分别选择；静态、预制和实时输出有不同的质量、性能和维护要求。工具知识、宿主能力、实际生产和结果验收分别记录。

研究参照、探索概念与可集成产品资产分别确认用途。关键艺术素材与业务组件提前共同试装，在真实文字、状态和视口下检查表达、可用性和累计成本。专业制作保留来源及允许用途，并验证最终导出与实际位置。

## 18. 内容设计、用户语言与文字视觉协同

内容设计、UX Writing 与字体排版共同决定用户在什么时候理解什么，并直接影响页面的结构与视觉节奏。产品事实与业务规则是语言表达的依据；同类成熟产品提供术语和内容组织的参照；品牌 Voice 与场景 Tone 共同决定写作方式。标签、按钮、状态、错误、帮助、关键条件和多语言版本，分别在其用户任务节点发挥作用。

第八份共同参考 content-design.md 负责整体方法；分析、工作流、视觉、交互、验证和接线参考仅保留其职责下的调用。需要追溯的重要文字与状态有可选记录模板。实际浏览器示例通过多语言、布局与交互检查核实局部效果。自动化机制、人工内容审阅、真实用户理解和业务授权属于不同的证据。

## 19. 完整产品体验与长期运营

九个设计维度共同描述实际体验：产品与交互模型、视觉设计与艺术指导、视觉素材、内容与排版、布局与空间、组件与状态、动效连续性、性能体验、持续运营。维度用于识别应作出的判断；八份共同参考负责提供方法，integration.md 负责真实业务接线。

从用户连续操作反推输入、计算、请求、渲染和确认链路，再决定准备时机、并发、缓存及反馈。通过实际条件下的观察判断收益与成本；界面反馈、可用结果和权威完成分别验证。内容来源、模板、单项覆盖、角色任务和批量恢复共同决定长期维护方式。

专业原则继承其机制和适用条件。某项目采用局部滚动、同级购买操作或卡片翻面，只说明当时的任务选择；新项目从真实对象、选择空间和内容增长重新判断。完整方法与案例映射见[体验质量指南](EXPERIENCE-QUALITY.md)。

## 20. 视觉观察连接知识、资源与实际体验

Visual Reasoning & Visual Inspection 是贯穿八份共同参考的工作能力。产品目标决定观察重点，实际画面提供可分析的对象，专业知识解释视觉关系，工程证据帮助定位原因，再通过查看调整后的结果验证判断。成熟参照、候选原始演示、当前项目局部试装和整合后的使用流程分别拥有观察依据。对齐关注当前任务需要的设计成熟度，品牌表达、外形与参数按产品确定。

Human-centered Visual Inspection & Perceptual Design Analysis 将这一能力展开为可执行方法：从正常尺度下的整体印象与产品气质开始，分析构图和空间关系、功能区域、组件与素材细节，再返回完整界面与使用流程。按对象选择注意力、空间、排版、色彩、材质、形态、素材、动态及系统一致性等感知维度。它们帮助识别关系，不构成固定打分表。参数提供可控实现，实际观看判断光学重量、质感与完成度。

观察同时覆盖整体画面与局部细节、具有时间关系的连续片段，以及跨页面的用户旅程。Temporal Visual Inspection 根据行为确定窗口：微交互覆盖触发到稳定结果，循环效果覆盖周期和接缝，异步任务覆盖等待与结果，复杂流程连接出发、过渡、到达和继续操作。正常速度理解完整体验，细读关键过程，再回到正常速度判断；实际能力不足时保留相应证据边界。必要的反向、中断、连续输入、加载变化与减少动态效果条件随任务纳入。

证据充分性结合覆盖广度、观察深度、时间完整性、相关性和可靠性判断。丰富截图仍可能缺失连续操作；细致单帧仍可能缺失完整产品关系。缺口应改变下一项获取或验证方式，设计信心与实际观察及比较质量同步调整。

记录建立可检查的判断关系：视觉事实、可能的感知效果、设计关系或原因假设、当前产品适用性、对应资源与适配、实际复验。放大与局部裁切帮助研究细节，正常尺度和相邻环境确认其效果；细节改变后重新检查完整页面。采集完成、像素已查看、操作已执行、工程测量、真实用户反应与用户批准分别表达其事实。普通播放、逐帧定位和受控时间实验各有用途，结论跟随其实际证据范围。

明确还原任务可借助结构和区域图像差异检查源设计保真，保留视口、字体、内容、事件阶段与容差。感知品质继续通过实际观看判断。确定性时间轴用于相应的重复比较和输出检查，自然运行用于真实响应与时序；关键帧集合、完整播放和性能测量各自支持对应结论。体验问题在具体资源、层级或机制上修正，并重新确认已承诺的艺术方向。

入口建立默认行为，工作流安排使用时机，principles.md 负责多尺度方法与感知分析，交互参考负责动态品质，选型参考将判断落实到采用与适配，verification.md 负责观察条件和证据方法。专项说明见[视觉观察指南](VISUAL-INSPECTION.md)。原有主线、八份共同参考和任务决定执行深度的原则保持连续。

## 21. 多尺度证据与下一步行动

L0 产品目标、L1 旅程、L2 页面结构、L3 功能区域、L4 感知细节与 L5 实现验证连接不同观察尺度；L5 为其他层级提供落地关系。状态时间、使用条件、共享依赖与来源关系补充纵向结构。用户任务和真实成熟参照共同修正覆盖范围。

重要设计决策的目的、问题、实际证据、专业判断、候选选择、实施适配和验证行动形成可追溯联系。原有记录可以承载，JSON 只是可选表达。已获取、已观察、已试装、已采用与已验证分别按对象条件记录，用户批准另有来源。关键缺口改变依赖它的承诺和下一步，并允许独立推进。

完整说明见[多尺度设计证据地图](DESIGN-EVIDENCE.md)。三组实验区分基准、结构与行动约束；实验准备、结构测试、真实 Agent 行为和 UI 品质各自需要证据。

## 22. 结构观察、专业判断与持续演进

设计证据地图维护当前认识；结构检查器描述字段、ID、引用与理论类别是否被明确记录；Agent 判断这些信息的适用性、专业意义与下一步；独立的视觉、交互、功能、性能和工程验证负责相应对象与条件下的实际结果。结构信息不认证研究充分、设计正确、实现就绪或任务完成。

区分声明内引用缺失与理论候选覆盖提示。理论体系帮助扩展观察视角，实际范围由任务决定。结构检查器只读展示 Agent 已记录的行动，不根据候选数量、证据类型、全局版本或缺口状态裁定动作。

当前有效模型、重要修订、原始证据三层相互链接。当前视图保存实际采用与有效判断，修订解释变化及影响，档案保存原始观察。局部变化按对象、依赖和条件审视；全局版本变化不自动使全部历史观察过期。体验研究与资源实现两条主线都能被新证据修订，结构成功和阶段标签不产生不可逆推进。


## 23. 复用成熟视觉工艺，而非只复用基础功能

复用范围描述来源能够承担的页面、区块、组件或效果职责，视觉完成度则来自对实际构图、排版、材质、状态与动态关系的观察。两者独立。功能基础、视觉实现与整合后的感知品质也分别需要依据。专业知识首先用于提出更准确的资源问题、发现和选择成熟实现，再通过配置、组合与必要定制保留其品质。

[Finesse 研究](FINESSE-ADAPTATION.md)贡献具体的工艺分析与表达方式，不引入固定风格、产品类别的表现强度上限或大型内置实例库。[本轮方法](VISUAL-CRAFT-REUSE.md)强化开放的来源探索与实际采用，仍由 Agent 作专业判断；结构检查器的职责与实现保持不变。
