# 可观察的设计执行

UI Spec Studio 让重要设计工作随实际发生而可见。Agent 继续负责研究、判断、选型、实现与验证；对话呈现其中真正影响当前 UI 的认识、选择、首次成果和剩余差距。完整项目记录支持追溯，对话提供可以直接理解和审阅的设计成果。

## 什么时候会看到输出

重要事件可能是正式 SPEC 的目标确定、改变认识的研究发现、承担关键品质的资源选择、首次可以实际判断的局部实现、需要重新处理的重大偏差，或正式增量交付。它们可以在现有任一操作中发生，也可以合并呈现。

范围与结果需要清楚。复杂工作中，重要对象刚形成有意义的真实成果时就应展示，使其能够影响接下来的适配和整合。一项小修可以在一次简洁交付中说明目的、修正与验证。普通搜索、样式微调和已验证方案的继承由 Agent 自主完成。

| 设计事件 | 直接可见的内容 | 帮助解决的问题 |
|---|---|---|
| 范围与品质责任 | 当前体验目标、继承基础、必要关系和范围理由 | 重要对象获得适当工作深度 |
| 研究发现 | 实际观察、设计关系、判断与影响 | 研究能够改变实际方向 |
| 关键选择 | 真实候选、具体差异、选定原因与待验证条件 | 资源与品质责任相连 |
| 首次真实成果 | 项目中的实际结果、目标对照、已体现品质及缺口 | 在广泛继承前发现失配 |
| 重大偏差 | 观察到的问题、影响、原因假设、修正及复验范围 | 差距继续推动当前行动 |
| 正式交付 | 可操作或可渲染结果、采用资源、观察范围与产品贡献 | 为下一增量保留可靠基础 |

这些内容由实际设计影响、用户观察价值和品质兑现价值决定。表格既不规定顺序，也不要求每轮出现六条消息。

## 一段有用的输出表达什么

输出优先说明设计对象的实际关系。例如，输入区试装表明，多行增长仍保持操作行排列，但消息区阅读位置在展开附件后发生变化。这里可直接展示当前试装，说明已经保留的关系，区分已观察现象与原因推断，再继续检查滚动锚点。

这种表达选择性连接“实际发现 → 专业判断 → 设计行动 → 当前结果与差距”。它呈现已形成的结论及必要依据，不要求四个固定标题，也不转录全部内部分析。

## 看清材料属于什么

**目标参照**说明希望达到的品质；**候选原始演示**说明某个实现原本提供的效果；**项目局部试装**确认当前内容、字体和状态下的适配；**整合产品**确认这些关系在真实任务中是否成立。

一张优秀的原始 Demo 不能证明当前产品已经采用相同效果。局部试装成功也不能代替完整使用检查。输出使用自然语言标明材料身份，并把重要品质连接到实际采用位置和已观察结果。

静态构图、排版和材质可用真实截图及细节对照。滚动、拖拽、异步变化和连续 Motion 需要相应的真实时间证据；逐帧样本帮助定位，自然速度下的操作和播放支持连续体验判断。

## 看到差距之后如何继续

重要失配可能发生在目标理解、资源、适配、内容、构图或运行机制中。Agent 应根据证据回到负责层，执行修正，再检查原问题与实际受影响的关系。原目标内的品质问题继续归属当前 SPEC；必要的范围重划保留原承诺、未解决问题及当前责任。

源材料、试装和最终界面可以采用不同的观察范围。研究是否充分、选择是否合理和结果是否成熟仍由专业判断及真实验证支持。结构检查器继续报告声明与引用，节点数量和文件完成度都不替代品质结论。

## 展示、审阅与批准分别成立

展示让信息可用；审阅意味着实际查看；批准来自具有明确范围的真实决定。已有执行授权支持继续合理工作，并不意味着用户已经接受新成果。Agent 在展示日常选择和修正后继续工作；真正涉及重大方向分歧或承诺变化时，才请求必要决定。

## 一个当前模型，多种表达

Overview、Design Detail 和 Execution & Assurance 继续使用同一份当前有效认识。对话按事件取出重要部分，项目记录保存完整依据。新的证据可以推翻已展示的选择：更新当前判断、说明重要变化，并将旧输出保留为历史。

设计执行说明与真实产品文案具有不同受众。执行说明可以解释资源与品质判断；产品界面通过实际空间、内容、组件和反馈帮助用户完成任务。证据分类不会自动成为产品布局。

## 验证本轮方法

评估分别检查用户可观察性、实际设计行为和最终 UI 品质。三个对照条件共用 v1.17.0 的自适应粒度基础：既有输出、增强事件可见性、事件可见性与品质兑现联动。实际发出的说明与当时源码可以核对；原实验媒体在归档时保留，已发现的图片覆盖限制与后续记录器修正单独说明。产品审阅与对话审阅分别进行。
