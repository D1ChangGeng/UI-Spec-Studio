# Build on mature visual work

UI Spec Studio uses **Default-Deny Original UI Construction with a Closed Exception
Allowlist**. A formal interface's visible design normally comes from mature external
implementations or validated reusable project work. The agent discovers, studies,
selects, configures, connects and adapts that work, then verifies what the actual
product retains.

The rule changes the permitted implementation route. It does not reduce the value
of professional visual judgment, distinctive art direction or necessary new code.
Those capabilities serve source selection, coherent composition, faithful adaptation
and explicitly authorized original responsibilities.

## What counts as original construction

Original construction independently determines a visible structure, shape,
material, composition, motion mechanism or their combination without an adoptable
mature implementation, an applicable established design system, or a complete
authorized design basis. Building that decision with a few containers and style
rules can be original construction just as a large custom component can.

The relevant question is which source carries the design relationship. A data
adapter, event handler, responsive connection or compatibility patch can be new
code while preserving a mature component. Replacing its defining proportions,
surface or movement with a newly invented treatment creates new visual
responsibility, even when the original component name survives.

| Normal mature-resource work | Boundary to preserve |
|---|---|
| Direct adoption | Use the selected source, variant and relevant states. |
| Configuration | Use public parameters, themes and supported extension points. |
| Composition | Coordinate mature sources through a sourced layout/system and art direction. |
| Integration | Connect truthful content, data, authority, events and runtime. |
| Focused adaptation | Resolve an observed fit problem while retaining defining craft. |
| Design-system inheritance | Apply established type, color, space, material and motion roles. |

Accurate new text, translations and business data remain normal product content.
Their typography and presentation inherit the relevant visual system. Native host
rendering can supply a defined foundation: a README uses its host's heading,
table, code and narrow-width behavior. Added artwork or a custom presentation
layer has its own source responsibility.

## Cover every visible level without searching for every element

The policy covers pages and workspaces, containers, backgrounds, surfaces, cards,
type, icons, borders, decoration, state feedback, motion, micro-interactions and
2D/3D assets. Simple implementation does not make a visual relationship unimportant.
A plain background can determine contrast and material across most of a page.

**Visual Provenance Obligation** belongs to design responsibilities. One complete
input block can provide type, internal controls, attachments, borders and growth
feedback together. One validated token system can provide background, spacing and
surface roles throughout the product. The agent does not search independently for
each node or declaration, and an invented token name does not establish a source.

Existing project work can remain a mature source when actual quality and fit have
been established. The policy does not require replacing suitable work merely
because it predates this release. Its historical presence alone does not validate it.

## Discover externally first, select for the current product

The discovery priority is **usable external mature work, then existing mature
project work**. Both are assessed against the current target. A stronger established
project source can be retained; external priority does not require unnecessary
replacement. Routine work under matching conditions can inherit an already
researched family.

Judge two different properties:

- **Reuse Scope** describes the responsibility supplied by a page, block, family,
  component, effect or asset.
- **Visual Completeness** describes the actual coordination of composition, type,
  material, states and motion within that responsibility.

A large template may have weak craft, and a small effect may be highly resolved.
Functional primitives provide valuable semantics, focus and state machinery;
renderers and animation engines provide technical mechanisms. They do not provide
unrelated visual design merely through their installation.

## Original work has three qualifying classes

| Class | What can qualify | What stays outside that permission |
|---|---|---|
| **W1: product identity and original art** | Explicitly requested unique marks, brand graphics, illustration or a dedicated 3D subject. | General pages, navigation, ordinary cards and other surrounding UI. |
| **W2: unmet product-specific expression** | A distinctive domain meaning or interaction that relevant mature implementations cannot reasonably express. | A broad claim that the product is special or an unsuccessful familiar-library search. |
| **W3: necessary specialized extension** | A concrete missing visible mechanism that configuration and focused adaptation cannot supply, while mature work retains the main responsibility. | Rebuilding the whole component or replacing its defining design. |

Each requires actual necessity, appropriate source research, concrete candidate
limits, a narrow original boundary, retained mature work, actual user authorization
and scoped verification. These relationships can live in the existing decision
record. There is no new approval lifecycle or required set of forms.

An explicit request for an original brand mark can already authorize W1. The agent
uses that existing permission without asking again. General instructions to build,
finish or continue do not authorize an unspecified original exception. When a
decision remains necessary, the agent completes useful independent work and
presents the concrete gap and proposed original scope for the user's decision.

Resource unavailability, license incompatibility, integration cost, apparent
simplicity, deadline pressure and familiarity with CSS or motion mathematics do
not qualify by themselves. The agent is not required to prove that no resource
exists anywhere, but must substantiate its actual search, candidate limits and
why supported composition or a different reuse scope cannot carry the needed relation.

## Design translation and technical probes retain their own boundaries

A task to implement a complete, explicit user-supplied or confirmed design can
faithfully translate that existing design. Preserve its source, revision, scope and
fidelity evidence, using suitable mature implementation where available. This
does not create a fourth exception for inventing unspecified relationships. A vague
screenshot or product analogy remains a reference, not unrestricted construction authority.

A temporary technical probe can use simple structures to answer a specific
feasibility, data, state or layout question. A plain box might reveal how composer
growth affects scroll anchoring. That useful observation does not make the box a
finished input component. Formal delivery still needs the mature implementation
or an authorized qualifying exception and its actual verification.

## Resource gaps change the next work

Broaden relevant source discovery; try an appropriate page, block, family or
component scope; inspect supported parameters and themes; diagnose dependencies,
fonts, CSS, state and container assumptions; and trial another coherent combination.
Continue independent authorized work while consequential gaps remain visible.

If neither a qualifying resource nor an authorized exception is available, the
visual responsibility stays unresolved. A rough custom substitute, a new SPEC
number or a polished explanation does not complete it. Source discoveries can
still improve the formal increment's scope, with the complete product goal and
remaining obligations preserved.

## Verify the actual retained result

**Acquisition** means obtaining the resource. **Adoption** means using its concrete
implementation in the product. **Craft Retention** means that the valuable visual
and interaction relationships remain in the integrated result.

Inspect the target reference, original source demo, current-project trial and
assembled task at their relevant boundaries. Keep corresponding content, type,
scale, theme and event phase where possible. A copied card may lose its light and
material; a block may lose its rhythm through broad overrides; an imported
transition may be replaced by different state logic. Those losses remain findings
even when the file name and import are intact.

Check whole-product coherence and engineering burden separately. More mature
resources can still produce conflicting typography, competing movement, duplicated
state or excessive payload. Improve selection, composition and adaptation rather
than treating the number of imports or copied lines as a success measure.

Important choices, first actual results, material mismatches, original exceptions
and formal delivery appear through the existing observable-design events. The
same current model supplies project records and concise conversation evidence.
Structural inspectors remain read-only descriptions of declarations and references;
they do not certify maturity, exception necessity, retained craft or final quality.
