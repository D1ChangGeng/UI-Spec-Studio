# 产品 UI 体验对齐与主动视觉探索

UI Spec Studio 以 **Product UI Experience Alignment**（产品 UI 体验对齐）组织设计工作：从当前用户、任务、内容、业务条件与审美目标出发，研究成熟成果中值得继承的关系，选择能够承接其品质的实际实现，再通过局部试装、针对性适配与整体验证形成当前产品的体验。

用户指定产品时，参照名称成为探索入口；只描述功能时，Agent 主动寻找适合的产品范式、设计系统和实现资源。两种情况都以当前产品的实际需要与可观察结果作出选择。

**品质目标 → 参照与资源配对研究 → 局部试装 → 保留价值的适配 → 整体体验复验。**

重要选择通过[证据驱动的深度视觉探索](DEEP-VISUAL-EXPLORATION.md)判断研究投入与设计信心：分别考察设计影响、认知不确定性和潜在改进空间，再依据实际观察的广度、深度、时间、相关性与可靠性选择下一步。优秀的首选方案也可以受到来自不同领域的候选挑战；研究完成度不是检索次数。

这条推理关系融入 `init → iterate → finish`。重要方向可以使用 `shape` 收敛，已有范围可以随时 `audit`。研究深度由设计影响和剩余不确定性决定。

对齐目标是适合当前任务的设计成熟度。局部检查字体、比例、边界、材质、状态与运动节奏，整体检查构图、信息层级、设计语言和连续任务。具体品牌、颜色和形态由当前产品决定；品质判断保留这些维度及其实际依据。

明确区分要继承的任务关系、要重新表达的视觉语言，以及必须兑现的品质。专业工作软件可以采用鲜明艺术方向；用户明确要求的冲击力与差异化进入交付目标。常见导航形态、配色和排列方式是可以重新验证的候选。详见[艺术指导与表达性反差](ART-DIRECTION.md)。

## 能力各自回答什么

| 能力 | 负责的判断 |
|---|---|
| 产品 UI 体验对齐 | 当前产品需要形成怎样的视觉、内容、交互与运行体验 |
| 参考产品对齐 | 一个成熟产品的哪些页面、流程或关系值得继承，适用到什么范围 |
| 主动视觉探索与设计研究 | 还需要理解什么，怎样通过浏览、操作或媒体观察获得证据 |
| 面向人类视觉感知的观察与设计分析 | 如何从整体、构图、区域和细节理解品质，并把判断用于资源与适配 |
| 艺术指导与视觉系统 | 怎样让主题、素材、构图和角色规则形成可持续的独立表达 |
| 时序视觉观察 | 这些视觉关系在操作、运动和状态变化中如何发展，过程证据支持哪些判断 |
| 复用优先 | 默认由哪些成熟实现承担通用 UI，如何适配并保留其价值，哪些实际缺口需要定制 |
| 实际验证 | 这些选择在当前内容、技术与使用条件下是否成立 |

参考产品是设计参照的重要来源。功能与体验参照、艺术与表达参照、成熟实现资源共同发展方案：分别研究可理解的操作关系、跨领域的感知方式与实际采用路径。设计系统、组件演示、摄影、编辑出版、素材作品和平台惯例可以在相应层面提供依据。一个来源可以承担多个职责，结论仍归属于实际观察对象。

## 从产品意图提出研究问题

先确定目标用户在操作什么对象、第一步是什么、怎样得到和继续使用结果。然后把模糊参照展开为具体研究范围。

| 输入 | 有用的展开方式 |
|---|---|
| “像某个对话式 AI 产品” | 识别所指的是官网、应用入口、输入与附件、长内容阅读、历史组织，还是对话与工作区协同 |
| 只有功能与使用场景 | 从主要任务寻找成熟范式，比较其信息组织、操作循环与内容关系 |
| 升级已有产品 | 保留已验证的语义和工程能力，针对实际体验缺口研究参照 |
| 新颖交互 | 在局部任务、组件、素材和反馈层继承成熟关系，用原型验证新组合 |

例如，“增加一个辅助工作区”可以展开为：打开后主要输入是否仍可发现，阅读行宽如何变化，焦点移到哪里，返回后怎样继续任务。品牌名帮助定位入口；后续搜索应加入任务、交互模式、组件职责、视觉关系和实现条件。新的观察也可以改变问题本身。

会显著改变产品类型、核心流程或整体视觉方向的分歧，先形成少量有实际参照的方案供用户判断。表达方向通过题材、构图、字形、材质或动态语言的实质差异呈现；以相称的完成度、代表内容与观看条件支持比较。明确目标下的常规细节由 Agent 继续研究和推进。

## 覆盖组成、状态及其关系

从三个角度检查研究是否足够：页面由什么构成，各部分在相关状态下怎样表现，它们如何在空间、时间、信息层级和任务中相互影响。

参照可以跨越五个层级：产品与任务、页面与区域、组件与状态、素材与语言、时间与连续性。不同层级可以采用不同来源，再通过统一的字体、密度、色彩、材质、操作与运动规则形成整体表达。

重点深入会影响核心任务、产品辨识度或重要动态体验的关系。统一设计系统中的常规控件可以共同继承已研究的规则。研究完整性体现在关键问题获得依据；记录清楚已经理解、仅局部观察、仍可能改变方案的部分，便于安排下一步。

观察从正常尺度下的完整感知开始，再深入构图、功能区域和关键细节，随后返回完整界面及相关流程。按对象组合感知维度，解释哪些关系形成焦点、层级、材质与完成度。放大和裁切用于定位，正常显示尺度及周围内容用于判断实际影响。方法详见[视觉观察指南](VISUAL-INSPECTION.md)；它同样用于成熟参照、候选演示、局部试装和最终产品。

## 让界面线索决定下一步操作

页面既提供已显示的结果，也包含继续研究的入口。选择能回答当前问题的行动，并随发现调整。

| 看到的线索 | 可以采取的行动 | 需要得到的认识 |
|---|---|---|
| 演示入口、视频封面或播放按钮 | 播放相关过程，重放关键片段；需要时查看连续画面 | 展示了哪些界面、动作、状态和关系 |
| 页面下方、横向轨道或局部滚动区 | 实际滚动，观察进入、停留、离开和反向浏览 | 内容展开方式、位置关系与继续阅读 |
| 标签页、菜单、折叠区、面板或弹层 | 切换、展开、关闭，观察焦点和相关反馈 | 隐藏信息、操作层级及空间变化 |
| 动态背景、3D 展示或交互效果 | 观察代表性运动范围，使用可用控制 | 材质、构图、运动与前景之间的关系 |
| 可调参数的组件 | 比较相关配置与变体 | 哪些配置适合当前产品，哪些需要整体适配 |
| 只有说明、代码或局部截图 | 继续寻找运行示例、实际演示或相关实现 | 补足决定采用所需的视觉与行为证据 |

一次操作的价值是增加理解、改变选择、确认适用性，或明确下一项重要空缺。参照探索与实现资源探索持续配对：发现侧栏展开后出现新的工作区，就研究其宽度、焦点与返回关系，同时寻找并操作能够承载该关系的成熟实现。候选资源提供更自然的任务结构时，也可以反向改善方案，使选型参与设计目标的形成。

## 明确每项观察的实际对象

包含演示的页面可能同时呈现四种对象：

| 对象 | 可以支持的参照 |
|---|---|
| 承载演示的宣传或说明页面 | 品牌表达、内容节奏、版面与媒体位置 |
| 媒体播放器 | 控制、播放状态、可访问性与媒体交互 |
| 演示中的实际应用 | 导航、工具栏、输入、面板和工作流程 |
| 应用展示或编辑的作品 | 字体艺术、内容构图、图片与素材表现 |

说明“在哪里看到、看到的是什么、用于什么判断”。视频内作品的鲜艳配色可以启发内容表达；应用自身的界面语言仍需从其实际控件、面板和反馈研究。宣传页源码解释该页面与播放器；视频内应用的实现原因需要相应的应用、演示、文档或运行证据。

记录媒体性质与重要条件。剪辑演示适合发现作者展示的设计关系；实际操作记录补充真实响应、返回、连续操作和异常条件。关于性能、业务完成或可访问性的结论，需对应的测量与验证。

## 用时序证据理解过程

对运动、状态变化、滚动与异步反馈，观察相关的完整片段：

**触发前 → 操作 → 首次反馈 → 变化过程 → 稳定结果。**

返回、撤销、重复触发、中途改变意图和连续操作按任务加入。微交互覆盖完整过渡；循环效果覆盖代表性的周期和运动范围；滚动变化同时保留位置与方向；异步任务连接等待、反馈与有效结果。

窗口由行为范围决定，采样密度由变化速度决定，分析深度由设计影响决定。工具允许时，先以正常速度理解整体，再暂停、重放或比较局部关键帧，最后回到正常速度判断连续关系。已有演示揭示典型设计意图；主动录制围绕当前问题补齐未展示的条件。

**采集媒体、实际查看或解析媒体、证据足以支持某项结论，分别保留事实。** 起终点画面支持两个状态的构图判断；短暂闪烁、运动轨迹、对象跳变与节奏需要相应的过程证据。视频已保存时，仍需说明实际检查了哪些片段、细节或序列。

[视觉观察指南](VISUAL-INSPECTION.md)说明七个时序品质、采集条件与证据边界。它同时适用于研究外部资源和检查当前实现。

## 让工具服务于具体问题

优先从实际画面与操作理解用户能感知的结果。随后按问题选择宿主提供的能力：页面结构与样式帮助定位布局关系；资源与请求信息帮助识别素材来源和触发条件；媒体检查帮助理解播放器状态；动画检查帮助定位中间过程；运行追踪帮助关联动作、页面状态和网络信息。

浏览器、播放、录制、连续帧、控制台与追踪有不同的覆盖范围。根据实际可用能力和授权选择组合，并把结果返回到画面与任务中解释。重要来源需要正常登录、官方客户端或授权导出时，先利用可用资料，再集中请求能够填补缺口的用户协助：说明对象、操作、需要覆盖的状态或片段，以及支持的决定。Agent 继续承担取得资料后的观察、比较与筛选。研究材料的访问与产品资产的使用条件分别确认。会修改数据、发送信息或产生交易的操作，遵循现有授权与相应确认条件。

## 将感知解释成可迁移的关系

重要研究结论应连接：**视觉事实、感知效果、设计关系或原因假设、当前适用性、实际采用与适配、复验结果。** 研究阶段逐步补足依据，后续实现继续回答相同问题。

例如，辅助面板展开后，任务入口保持原位、正文宽度调整但仍可读、过渡显露出新区域。这支持一个可迁移的判断：增加辅助空间时，保持主要任务入口与阅读焦点的连续性，并让空间变化可理解。当前项目仍需决定合适的布局、断点、材质与时间参数。

“简洁”“高级”“有质感”可以作为初始印象，再通过视觉重量、比例、留白、排版、素材、信息密度和动效节奏解释其形成方式。可见效果与实现原因分别建立依据；真实用户是否理解得更快、任务是否更高效，需要对应的用户观察。

## 让品质目标决定实际采用，再分层复验

复用包括两个相互连接的层次：继承成熟的设计决策，采用可集成的工程成果。产品参照和实现资源可以来自不同来源。通用 UI 默认通过成熟实现的集成、配置、组合和必要二次开发形成；数据接线、状态映射与主题配置属于这条路径。定制集中于候选试用后仍存在的具体缺口，并优先建立在成熟结构或底层能力之上。

从完整页面、设计系统、布局、功能区块、组件、素材和动效中选择最高适当层级，比较视觉、行为、技术、可访问性、性能、维护与使用条件。现有仓库中的成果同样接受适用性判断。实际选型可以采用外形不同但状态、细节和组合表现更适合的资源。

在扩大集成前，先确认关键组成的实际品质：

| 观察对象 | 负责确认的判断 |
|---|---|
| 成熟参照中的相关部分 | 希望达到什么品质，哪些关系值得继承 |
| 候选原始演示 | 资源自身的视觉细节、相关状态和动态能力是否成立 |
| 当前项目的局部试装 | 实际字体、内容、主题、容器和业务状态接入后是否仍适用 |
| 完整界面与连续流程 | 多个组成是否形成协调统一、能够持续使用的体验 |

试装可以聚焦输入、面板或主视觉等高影响组成，使用能够暴露问题的多行文字、长标签、缺失素材、加载与错误等实际条件。按对应的任务、状态、显示尺度与变化过程比较。统一体系中的常规实例可以继承相同条件下已验证的规则。

适配从内容、主题、公开配置与组合方式开始，围绕已确认的差异修改内部结构或行为。字体、品牌色、异步状态等改动分别复验其影响的排版、对比、反馈与连续关系。大范围改写主要机制后，验证范围随改动扩大；原始资源的成熟度提供起点，当前版本由当前证据确认。

整合后的差距需要定位到资源不适合、适配损失、真实内容缺口、资源间冲突或参照目标不匹配，再选择替换、恢复关系、调整结构或重新审视目标。无法达到原定品质时，明确差距、影响和可选路径，必要的标准或范围调整由显式决定形成。具体方法见[资源复用指南](RESOURCE-REUSE.md)。

具体问题应在相应层面修正，并保留已确认方向。例如，移动素材影响阅读时，可以调整局部运动、遮罩、裁切或交付方式。复验同时检查操作改善和艺术表达的保留。完成首次操作、填入长内容与跨页面继续使用后，核心区域仍应具有所承诺的身份。

体验成立性与表达完成度分别评价，再共同决定结果。视觉判断以实际渲染为依据；业务正确性、可访问性、性能与工程可靠性结合操作、源码和运行信息。已采用或批准的成果另有源设计保真要求：保护约定细节，并记录有意改变。专业评审、实际用户反馈与业务验收各自贡献适当证据。

## 何时收敛，交付什么

继续探索应能改变选择、消除重要不确定性或避免较大返工。主要品质已有依据、关键候选完成试装、重要状态得到观察且适配路径清楚时，推进整合。暂时缺少合适资源时，保留候选的实际不足，再决定继续研究、请求必要取材、调整局部方案或有限定制。其余空缺按影响留到相应验证节点。

记录采用最小有用范围：组成职责、品质目标、来源、相关片段、观察条件、实际采用的实现、适配内容与复验结果。研究过、进入比较、完成试装和最终采用分别表达；将记录与代码及实际画面对应。少量代表性证据帮助用户判断主要结构、核心交互与高影响细节是否有适用的成熟实现基础。详见[设计决策](DESIGN-DECISIONS.md)与[资源复用](RESOURCE-REUSE.md)。

最终交付应能说明：**正在对齐什么，依据是什么，实际继承了什么，以及当前产品中的结果是否成立。** 结论随真实观察范围表达；浏览量、截图数和录制时长用于描述工作，不决定设计是否完成。

## 方法来源与适用范围

以下页面于 2026-10-26 查阅。它们支持相应原则；UI Spec Studio 的整合方法与运行效果由本项目及实际任务验证。

- [USWDS Design Principles](https://designsystem.digital.gov/design-principles/)：强调以真实用户需要作决策，并用真实用户检验假设。专业参照研究提供设计依据，用户研究继续承担对真实理解和使用效果的验证。
- [Design Council Framework for Innovation](https://www.designcouncil.org.uk/resources/framework-for-innovation/)：说明发散探索、聚焦行动与非线性迭代。这里继承探索与收敛相互修正的机制，工作仍使用既有阶段。
- [GOV.UK Components](https://design-system.service.gov.uk/components/)：说明组件在不同模式和情境中的复用，并提供使用说明与代码示例。适用性由当前任务判断。
- [GOV.UK Get Started](https://design-system.service.gov.uk/get-started/)：提供样式、组件和模式的研究背景；社区讨论中的想法可能尚未经过测试，采用后仍需本地情境研究。成熟程度按具体来源确认。
- [NN/g：Should You Copy a Famous Site's Design?](https://www.nngroup.com/articles/copying-a-famous-sites-design/)：2010 年文章区分了来源局部设计欠佳和使用情境不同两类风险。这里使用该判断原则，文中历史网站样式与位置偏好各自保留其年代背景。
