# 从意义到形式：UI/UX 专业能力模型

UI Spec Studio 把设计视为一组相互连接的专业判断：**理解与观察、构思与表达、制作与控制、判断与改进**。它们共同支撑一个结果从产品意图进入真实使用。

## 一条推导关系

**任务与事实 → 所需理解 → 表达概念 → 信息、视觉与交互语言 → 素材与实现 → 实际结果。**

这条关系帮助 Agent 判断下一步需要解决什么问题。它不要求每个项目增加固定阶段、候选数量或报告。既有方向明确时，直接延续；重要问题开放时，用小范围研究与实际结果收敛。

## 八项相互连接的专业能力

| 能力 | 关键问题 | 实际执行价值 |
|---|---|---|
| 内容与表达策略 | 用户已知道什么，还需要理解什么，哪些事实支持下一步行动？ | 在布局前确定内容角色、信息顺序、证据和动作语言 |
| 概念生成与艺术指导 | 什么组织思想属于当前产品，并能影响多个具体决定？ | 将抽象品质目标转成可延展的结构、排版、图像与行为方向 |
| 具体视觉语法 | 哪种手段能形成需要的层级、关系和视觉重量？ | 在字号、间距、明度、材质、裁切等手段中作出有因果依据的选择 |
| 信息表现与交互范式 | 用户需要比较、追踪、阅读、理解关系还是直接操作？ | 先选合适表现形式，再选组件实现 |
| 素材与媒介策略 | 哪些材料和表达媒介能提供真正的信息或体验价值？ | 联合选择组件、实际图片、图解、程序化图形和专项制作工具 |
| 时间与动态编排 | 哪些信息先反馈、哪些随后变化、哪些空间关系保持稳定？ | 协调注意力、延迟、动作连续性和用户控制 |
| 参考阅读与因果诊断 | 为什么参考有效，当前结果的主要薄弱关系在哪里？ | 分整体、关系、细节观察，以实际证据修复负责问题的层级 |
| 可编辑表达与保真 | 什么设计关系应保存在源码中，并在真实接线后继续成立？ | 用语义参数和状态结构维护意义、结构、视觉及行为时序 |

## 在现有流程中应用

**Shape** 重点处理所需理解、概念和表现形式，检查承载它们的内容与素材，通过代表性结果形成可继续的方向。

**Iterate** 把方向转成可评价增量，具体运用排版、色彩、构图、媒介和交互方法。观察结果后提出原因解释，再修复并复验。

**Finish** 继承关键设计关系，连接真实数据和行为，同时验证意义、结构、视觉及行为时序。静态文档以内容、链接、素材和发布载体为真实边界；服务型产品进一步核验权限与业务状态。

**Audit** 将事实正确性、任务可用性、表达清晰度、身份一致性和制作细节分别检查。整体指标不抵消关键任务失败。

## 专业判断的三个层次

**要求**确定可读、可操作、真实状态、权限和证据责任。**原则**解释视觉与体验关系。**偏好与技法**在特定条件下提供候选方法。作者风格、行业映射和工具参数都应保留其适用范围。

专业进步意味着 Agent 拥有更多有依据的选择，并能解释为什么此处适用。它不意味着每个项目都需要更多特效、三维、视频或流程文件。

## 从案例中沉淀什么

一个可迁移案例说明：什么问题、什么机制、什么条件、怎样控制实现、实际观察了什么，以及在什么情况下需要换一种方法。项目审美保存在项目中；共有知识由维护者通过明确授权更新。

[技法案例](../skills/ui-spec/references/patterns.md)包含比较、证据阅读、单任务构图、状态连续、发布文档和语义图解六类条件性方法。[README 设计说明](design/README-SPEC.md)展示本版本如何将同一实践用于自己的发布入口。

这里记录的是专业方法与具体应用依据。它们的效果通过真实任务中的观察判断；源码测试和发布检查分别验证工程与分发行为。

## 资源发现与专业复用

成熟的外部实现既能实现已有设计，也能启发更好的表现形式。Agent 将目标转成可检索的效果、行为和约束，理解具体资源的演示与实现契约，再选择适合当前产品的复用深度。

关键关系是：**目标 → 可用优秀成果 → 设计与工程判断 → 适配组合 → 真实结果 → 有边界的经验**。平台知名度、条目适配与项目验收具有不同证据。资源的核心机制值得保留，视觉语言与业务状态则纳入项目权威体系。

[资源方法](../skills/ui-spec/references/component-sourcing.md)是共同基础的一部分；[能力目录](../skills/ui-spec/references/resource-catalog.md)提供开放起点。其组织方式和使用情境见[资源复用指南](RESOURCE-REUSE.md)。

## 用户能够理解的产品交互模型

从第一项操作、主要工作对象、重复循环、继续方式和持久结果建立用户层面的产品模型，
先据此安排信息层级，再确定视觉表达。成熟产品范式与具体实现来源分别支持体验和工程选择，
并在同一份设计依据中连接起来。[设计决策指南](DESIGN-DECISIONS.md)说明适用范围、
确认方式、可检查的选型记录，以及可运行的代表性样例。

## 两类知识共同作用于实际选型

理论知识支持对具体成熟成果的理解、审美判断与工程取舍；资源知识让判断有可研究、
可比较、可复用的对象。以最高适当复用层级继承整体设计关系，再完成产品化适配，
使专业创造力集中在差异化需求、整体协调和体验优化。发现、比较与验证可以持续修正方案。

## 视觉素材与资产工程

素材是与页面结构和交互相互作用的设计材料。共同必读的 visual-assets.md 覆盖品牌与功能图标、字体与字形、2D、空间化和动态内容，将参照研究、制作路线、母版、交付变体、真实位置和验收连接起来。
专业判断既决定采用什么素材，也判断何时应由素材改变布局。详见[资产工程方法](VISUAL-ASSETS.md)。

## 内容设计与视觉构图共同决定表达

文字是内容、交互指令，也是占据画面空间的设计材料。产品理解决定应该讲什么、信息归谁负责；UX Writing 决定如何用适当的 Voice 与 Tone 呈现；Typography 决定文字的可读性和视觉关系；实际状态与语言变体共同验证其有效性。

内容设计与成熟资源驱动相互支持：研究同类产品的术语和表达方式，评估其适用条件，再围绕当前产品的真实事实组织页面。重要信息可以反过来改变区块分工、组件形态与布局比例。具体运行方法在 [content-design.md](../skills/ui-spec/references/content-design.md)。

## 从专业能力进入完整产品体验

这些能力共同作用于九个设计维度：产品与交互模型、视觉设计、视觉资产、内容与排版、布局与空间、组件与状态、动效连续性、性能体验、持续运营。专业能力说明怎样作出判断；设计维度说明判断要作用于什么对象。[完整体验指南](EXPERIENCE-QUALITY.md)将每个维度对应到负责的方法与验收范围。

性能设计从连续用户任务追踪执行链路，比较提前准备、并发、缓存和渲染的收益与成本。运营设计从真实维护频率和对象差异出发，安排共用来源、单项覆盖、角色信息和批量恢复。它们与内容、视觉和状态一起决定最终体验，并通过真实结果检查。
