# UI Spec Studio 1.12.0 — evidence-led exploration review

## Scope

This revision integrates the owner's deep visual exploration method into
the existing Skill, its eight common references, optional design/adoption/review
records and public documentation. It refines how much research a decision
deserves, how evidence is judged, how an initial choice is challenged and
when implementation should proceed or be reopened. The established
`init → iterate → finish` workflow with optional `shape` and `audit` remains.

## Source and behavior contracts

The entry instructs research by design impact, specific uncertainty and
potential improvement. It pairs experience-quality references with actually
adoptable resources; generates new search questions from inspected phenomena;
challenges promising candidates with alternatives that differ materially;
and calibrates confidence using breadth, depth, time, relevance and reliability.

The sourcing reference provides the full iterative decision loop, visual access
contingencies and a concise evidence-to-adoption trace. Analysis, workflow and
verification share these rules with their respective responsibilities. The
optional record templates capture important alternatives and unobserved gaps
without requiring search quotas, mandatory logs or numeric confidence scores.
The Chinese standalone guide explains how this works beyond application UI.

## Verification evidence and limits

The GitHub Actions release workflow runs cross-platform package/unit checks,
installer verification, rendered bilingual README review and existing browser
scenarios. Any completed run must be linked by its exact commit and actual
conclusion before it is reported as passed.

Static contract checks confirm only the existence and consistency of methods.
Existing browser fixtures exercise their own authored implementation, not a fresh
Agent performing multi-source deep exploration. This revision does not claim
that hundreds of resources were studied, that an external design quality
comparison was performed, or that the revised Skill has already improved a
new independent Agent's delivered product.

A meaningful downstream experiment should freeze this Skill and an earlier
baseline, use the same initial design task without preloaded diagnoses, and
inspect actual operations and visual material. It should establish whether the
Agent discovers a consequential candidate it might otherwise miss, whether the
comparison changes selection or its rationale, which source is implemented and
whether the fully integrated result improves at comparable fidelity. A routine
control task should also demonstrate that exploration does not become compulsory
overhead. Costs, user perception, runtime and design-quality conclusions must
retain separate boundaries.

## Release status

The final release result is established by the corresponding GitHub Actions
run, tag, tested commit, downloaded assets and published-source readback.
This record describes the intended test suite without pre-certifying tests
or independent design applications.
