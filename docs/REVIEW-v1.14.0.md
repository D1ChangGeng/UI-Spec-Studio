# UI Spec Studio 1.14.0: multiscale evidence and action review

## Delivered method and open empirical claim

This release connects consequential design decisions to multiscale objects,
revisable coverage, actual evidence, resource adoption, scoped assurance and the
next action. It adds an opt-in read-only checker and a reproducible experiment
preparation kit. **Controlled three-arm Agent trials have not been run in this
session. General improvement in model behavior or final UI quality is unverified.**
The package implements and tests the method's declared mechanics, not that
unestablished empirical outcome.

## Structural mechanics actually tested

The read-only helper checks declared IDs, containment, dependencies, local path
and optional digest integrity, candidate/actual scope, object-condition pairs,
source revision, observed versus acquired evidence, exception provenance,
approval scope, pending coverage and consequential action contradictions.
Remote URLs are never fetched; file presence and declared observation cannot
authenticate actual execution or perceptual quality. Dependency traversal produces
review candidates and is cycle-safe; it does not update evidence or approvals.

Authored tests cover evidence acquired but not observed, text-only visual claims,
demo-versus-integration mismatch, stale source/claim identities, mixed condition
pairs, parent/child scope, meaningful named alternatives, actual trial/adoption
locations, dependent versus independent work, waived versus passed checks,
three read-only views, invalid paths, symlinks, malformed data and CLI behavior.
These fixtures are synthetic declaration tests, explicitly **not Agent runs**.
The existing installation smoke check now also invokes the new helper from its
installed copy against the unfilled optional template, without automatically
creating a project evidence file.

## Experiment status and isolation

[The protocol](experiments/design-evidence/PROTOCOL.md) supplies six ordinary
prompts and exact baseline hashes. Preparation creates 18 `prepared_not_run`
cells and records zero executed models. Each task's prompt is identical across
arms. Baseline content is not weakened; it already includes evidence maturity.
Structure adds the map, while the third arm adds explicit action coupling.
The structure arm omits new action/checker access to avoid treatment leakage.

These are instruction-only ablations, not exact copies of every production
v1.14 integration edit. They isolate the module effect. A deployed-skill
application needs a separate run. Matched task projects, material/access,
model/harness and resource conditions must be frozen before independent fresh
sessions. Output review should be blind to group and preserve costs, failures,
uncertainty and disagreement. A low-impact supported task checks convergence.

The available connected projects did not include an authorized UI Spec Studio
independent-agent runner. Unrelated projects were not used. The preparation
kit, structural tests and the maintainer README self-application cannot replace
the requested real behavior comparisons. This limitation remains visible in
release notes and evaluation guidance.

## README self-application

The current scope retained the established native Markdown design and install
path. One new section explains the map and its action boundary, and links to the
detailed method and experiment protocol. Actual local observation found the
English inline link separator wrapping onto a new line at 1440px. Moving links
to their own paragraph repaired that reading-group issue and aligned the locales.

The final local browser matrix covers English/Chinese × light/dark ×
390/768/1440px. All twelve changed-section crops were actually viewed as four
original-pixel sheets. The inherited renderer's automated checks also passed.
The observation record names source hashes, image identity, crop geometry,
browser version, a failed initial capture command and the eventual viewing
scope. [Decision record](evidence/v1.14.0/readme-decision.md) ·
[Local inspection](evidence/v1.14.0/readme-local-review.json).

This is scoped maintainer self-application on a document surface. It does not
establish fresh-context agent improvement, production app quality, continuous
motion, screen-reader output or user comprehension. Local CSS approximates
GitHub; actual-host publication is checked separately by the exact-commit CI.

## Engineering and publication

[Executed local checks](evidence/v1.14.0/engineering-checks.json) record actual
commands, outputs and their scope. The unchanged release workflow still requires
four OS/Python matrices, local and exact-commit installations, local and actual
GitHub publication checks, product/assets/content/temporal browser fixtures,
verified release-asset readback and published-tag installation. Capture artifacts
are not automatically treated as viewed media.

Source documentation does not predeclare a future CI or release result. The
actual workflow, tag commit, public release status and asset checksums establish
publication. Prior tags and evidence remain intact. Method delivery and package
reliability can be verified while the comparative empirical claim remains open.
