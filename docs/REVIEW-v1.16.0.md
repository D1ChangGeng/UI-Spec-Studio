# UI Spec Studio 1.16.0 — discover and adopt mature visual craft

## Delivery and empirical scope

The change strengthens professional source selection, not a preset visual style or
an example-code generator. The installed Skill now distinguishes reuse scope from
visual completeness, functional foundations from visual implementations and
assembled perceptual quality, and effect from interaction ownership and route.
Actual adoption and inspected outcomes need their own evidence. Structural test
success does not establish improved model performance or user-facing quality.

The baseline is v1.15.0, commit `a89091dfa5754f98b79655c684f978f24fd92716`.

## Finesse: retain mechanism, change default realization path

The useful ideas include type roles and visual tension, coherent surface/light
relationships, effect/route separation and uncertainty in direct manipulation.
They are rewritten as questions for discovering, comparing, configuring and
verifying mature work. Specific font names, fixed palette/contrast recipes,
mandatory grain or vignette, black/white bans, copied gesture constants and
product-category spectacle caps are not adopted. No Finesse example HTML,
JavaScript recipes, pictures or fonts were added to the Skill.

The existing catalogue's `finesse` ID points to **finesseui.com**, an unrelated
design-kit source, not mouse-lin's Finesse Skill. This identity is retained and
explicitly explained rather than silently changing the old resource.

## Catalogue extension and compatibility

There are still 37 resources. Twenty-one receive optional discovery profiles
for documented role, reuse scope and visual form. Classification dates are
separate from original source-review dates. These labels do not attest that
all demos were observed, all variants are mature or any candidate fits a task.
The query helper accepts `--role` and `--reuse-scope`; it remains read-only,
alphabetically ordered and non-prescriptive. Missing classification is not
unavailability. Old catalogue input without the optional facets remains valid.

## Evidence status

Specific research, build, runtime and viewed-visual results are recorded in this
version's evidence directory. A downloaded picture is not treated as viewed;
a loading skeleton is not treated as a finished component; a compiled dependency
is not treated as a successful product integration. Local browser navigation
was blocked by the runtime administrator; that failed attempt is preserved and
not counted as a visual application. Authorized repository CI can build and
exercise the isolated trial applications with its own declared browser scope.

No independent fresh-context multi-agent comparison, blind aesthetic evaluation
or user acceptance is implied by this maintainer work. Prior prepared three-arm
experiments remain unexecuted. Actual current maintainer applications, where
completed, are source-to-trial case evidence, not causal proof of improvement
against v1.15 or universal recommendations for the sources involved.

## Actual maintainer applications

[The application record](evidence/v1.16.0/application-study.json) preserves three
representative task families and exact run/artifact identities. These are current
maintainer Agent applications, **not three independent agents or randomized arms**.
The actual component-adoption sources, authored adapters and original browser
records are distinguishable from later visual interpretation.

**Conversation workspace pilot:** the actual assistant-ui Thread/ThreadList
registry sources supply a mature composer/message/state composition. The project
shell and fixture-only streaming adapter are custom. Initial inspection found that
hiding the sidebar at 390px removed history access. A bounded adapter repair
restored that entry; the later browser run exercised streaming, long content,
fixture failure and cancellation at 1440/390px without page errors or horizontal
overflow. This is not complete product alignment, a real model backend or durable
history acceptance.

**Expressive reading workspace:** exact-version React Bits SpotlightCard and
TiltedCard were tried alongside a plain surface using the same content and task.
All six surface/condition combinations executed note-open, return and no-match
filter paths. Actual inspection of eighteen pointer samples distinguishes stable
text with moving surface light from a changing reading plane. For this reading
purpose the maintainer selected surface light, not a universal ban on spatial
motion. Two conditions cover English dark desktop and Chinese light narrow use;
they are not a complete language/theme/device matrix.

**Direct-manipulation source drawer:** an actual shadcn visual wrapper plus Vaul
mechanism retains the mature interaction rather than rebuilding a gesture recipe.
Initial short-delay measurements left dismissal/focus uncertain. The refined
adapter uses public controlled-state and focus-return hooks and inspects settled
states: both tested viewports report no open dialog after close/Escape, focus on
the trigger and the edited note retained on reopen. Pointer drag/reversal samples
were viewed for the narrow condition. This does not measure hardware touch,
velocity prediction, frame pacing or complete accessibility.

Three initial build attempts failed in the research adapter's path handling;
those failures and subsequent corrections remain recorded. They are not attributed
to faulty upstream components. The prior research branch and its loading-skeleton
capture are kept distinct from these actual runs. A skeleton never established
TiltedCard's visual quality; the current pinned-source trial supplies its own
render evidence.

The raw capture files are unchanged; [the visual review](evidence/v1.16.0/application-visual-review.json)
identifies exactly which frames were subsequently viewed. Result files do not
turn assertions, dependencies or source popularity into a quality score.
