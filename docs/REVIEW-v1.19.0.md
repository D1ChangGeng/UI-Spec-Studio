## Implementation scope

The revision changes the permitted visual implementation route. Mature external
implementations and validated reusable project work provide the normal foundation;
original responsibility requires a qualifying, narrowly scoped and actually
authorized W1–W3 exception. New integration code remains ordinary work when it
retains the selected design's defining relationships.

## Actual execution evidence

The [protocol](experiments/default-deny/PROTOCOL.md) and
[registration](experiments/default-deny/registration.json) freeze complete methods,
identical task-family inputs and six fresh-thread assignments before dispatch.
The comparison covers a complete collection workspace, continuous note-card motion,
and accepted-system typography with narrowly authorized identity/conflict work.
Actual outputs, independent review, counterexamples and limitations are reported
in the [results](experiments/default-deny/RESULTS.md).

The observed outcomes are mixed. T1 B has broader actual page/system provenance
and more readable list text, while A has stronger editorial composition. T2's
near-original component adoption preserves more direct interaction but produces
softer card text and adds a React build; the source-derived vanilla adaptation
remains a legitimate retention route. T3 B synchronizes continuing conflicts and
focus better, while A's mobile comparison is more compact. The review does not
claim a universal visual-quality gain from stricter reuse or more source code.

After the comparison, a separate read-only semantic audit found the two worked
example premises above. The original registration and B archive remain unchanged.
The [exact final delta](experiments/default-deny/final-runtime-delta.json) contains
the old/new text and hashes for the only B-to-release change, `examples.md`.
A separately registered fresh execution used the complete final runtime and the
T3 task with relevant worked examples. Its [completed outcome](experiments/default-deny/followup/RESULTS.md)
records scoped W1/W3 work, participant verification limits and the lack of conflict
draft recovery after refresh, separately from the three matched pairs. The semantic reviewer confirmed that the correction closes
the shortcut without deleting craft knowledge.
