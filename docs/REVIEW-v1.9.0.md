审查日期：2026-10-26（Asia/Tokyo）。本版将成熟参照的品质目标连接到实际采用的
实现、关键组成的局部试装、保留成熟价值的适配，以及整合后的连续体验验证。

## 逻辑情境审查

以下为方法和职责的源码审查，不代表已经观察到模型完成相应任务：

| 情境 | 方法应推动的判断 |
|---|---|
| 常规 UI 看起来简单，模型能够快速重写 | 有适合的成熟实现时，先采用其实际机制；写出第一份代码的速度不足以证明自建必要性 |
| 参照只展示产品关系，没有可复用代码 | 继续寻找实现资源；记录设计继承与实际采用的不同来源 |
| 引入行为 primitive 或图标包 | 按其承担的职责记录复用；主要视觉与结构继续需要自己的成熟基础和验证 |
| 主题或字体更换后原组件不协调 | 在局部试装检查字形、换行、边界、焦点和相关状态，修正适配后再扩大 |
| 对源组件进行了大量内部重写 | 识别仍保留的机制，当前改写范围承担新的品质与工程验证 |
| 同一成熟体系中的普通实例 | 在条件相同的范围继承代表性验证，避免为每个控件重复建试装页 |
| 重要资源需要正常登录或授权导出 | 先用可访问证据，再集中请求具体取材动作，取得资料后继续专业分析 |
| 界面功能可用但整合后的品质未达目标 | 定位资源、适配、内容、组合或目标问题，保留差距与显式的范围选择 |

另一检查者完整读取入口、选型、验证与流程方法并核对公开复用指南的改动，未发现
上述要求之间的行为性矛盾。重点核查了 headless 能力、设计迁移、附带依赖与实际
可见机制的不同责任；这项只读审查没有被计为独立应用成功或产品验收。

### 已有研究笔记：保留实现，改善长文与区域连续性

Agent 先打开现有原型，在 1440×960 与 390×844 观察基线，再在同项目试装阅读尺度、
工具分组和目录。实际实现保留 Tiptap 3.32.0 的文档结构、选区、格式、历史、解析

`store.js`、原有存储测试、数据夹具、依赖声明和锁文件与输入相同。

新增的 `reading-tools.js` 承担阅读模式、17/19/21px 字号、标题目录和当前工具的
焦点适配；原生 dialog、select 与 radio 继续承担各自控件行为。完整 Tiptap React
模板没有移植，因此其阅读宽度、工具分组与正文关系只计为设计参照。采用边界是
