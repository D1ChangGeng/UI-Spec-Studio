## 新增的维护与发布能力

新增 `docs/MODEL.md` 汇总理解模型，`docs/WRITING.md` 约束 Agent 写作，本文记录审查依据。版本说明、贡献指南、安全政策、行尾规则、依赖更新配置、安装验证脚本与新增测试分别支持产品分发和维护。它们属于维护者资料与工具，Agent 运行时仍读取 Skill 内的专业参考。

## 逻辑情境复核

| 情境 | 规则应导出的行为 |
|---|---|
| 用户只有目标 | 主动理解并推荐方向，用代表性结果接受审阅 |
| 用户有精确参考 | 保留明确偏好，补齐开放部分并核查适配 |
| 用户说通过继续 | 记录可识别范围的批准，自主选择下一项有价值的任务 |
| 单个局部修正 | 保留既有方向，按影响范围实施与复验 |
| 用户感觉偏低或空旷 | 转为构图关系的假设，观察完整视口后修复 |
| 共享框架变化 | 在公共层修复并验证关联页面与状态 |
| 语言、主题和真实长内容 | 保持任务上下文，独立检查变体的视觉质量 |
| 已批准 SPEC 进入 Finish | 核查真实差量、契约、接线和双轨证据 |
| 静态或本地产品 | 根据实际内容、路由或本地持久化边界完成验收 |
| 开发中与运营中产品 | 从实际数据、兼容性与可用性义务确定工程工作 |
| 浏览器或看图能力缺失 | 继续可做的工作，视觉检查明确保持待验证 |
| 参考读取截断或资料缺失 | 继续读取实际内容；宿主管理上下文生命周期 |

这些是规则一致性的逻辑检查，未作为模型实际执行成功的记录。具体 UI 质量仍通过产品任务中的实际渲染和操作验收。

## 写作与职责收敛

保留单一权威英文运行文本；将任务对象、判断依据、必要原因和验证方式写清。严格职责与设计自由分开表达，减少多处重复规则。用户报告呈现实际结果、关键选择和证据；内部专业工作由 Agent 完成。
