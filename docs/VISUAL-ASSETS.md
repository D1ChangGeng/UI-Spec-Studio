# 视觉素材与资产工程

UI Spec Studio 将 **Visual Assets & Asset Engineering** 纳入共同专业基础。素材与页面结构、组件和交互共同设计：主视觉、品牌字标、字体、空间图形或动态内容可以影响构图，页面的真实使用条件也会反过来影响素材的选择与制作。

## 一项完整能力，而不是另一份素材清单

工作关系是：**用途与设计目标 → 参照和资源探索 → 审美与技术判断 → 方案与制作路径 → 获取、改造或制作 → 页面整合 → 实际观察与迭代**。

素材既可以来自成熟资源，也可以通过有依据的原创制作形成。复用层级说明采用范围，不代表重要性排序。选用高质量素材，也需要将它的比例、色彩、光影、视觉重量、信息意义和运行方式融入当前产品。

Agent 完整读取新增的 [visual-assets.md](../skills/ui-spec/references/visual-assets.md)。共八份通用参考提供判断依据，实际任务决定制作深度。专项 [asset-sources.md](../skills/ui-spec/references/asset-sources.md) 保留本轮检查的官方资料与适用提醒；原有 37 项资源目录及其历史核查日期保持完整。

## 五类素材与不同的专业判断

**品牌与图标。** 功能性图标优先从成熟体系选择；第三方品牌标识准确表达所属服务并核查官方使用要求；原创品牌符号从产品身份出发研究轮廓、比例、负空间和光学平衡。小尺寸表现、应用图标遮罩和深浅背景分别检查。

**字体、字形与字标。** 阅读字体需要真实语言覆盖、排版与加载质量；品牌文字可以进行笔画、连接、轮廓或空间化创作。艺术表达与普通界面的可读性分别判断。矢量字标不等于具备编码、字距和塑形行为的完整字体。

**2D 图片与图形。** 摄影、插画、图案、纹理和背景围绕具体内容及构图选择。保留可编辑源，处理裁切、焦点、色彩、透明和导出品质。视口变化可能需要不同构图，而不只是缩放。

**空间化与 3D。** 可以复用模型，进行专业建模与渲染，采用参数化流程，将 2D 轮廓或图像转为空间对象，或组合多种方法。制作路径与交付模式分别选择：同一场景可以产出静态图、预制动画或实时模型。导出后在目标运行环境重新检查材质、几何、光照和交互。

**动态资产。** 根据意图选择现有素材、矢量动画、视频、程序化图形或实时渲染。节奏、视觉重量、状态含义与用户控制共同决定质量；处理暂停、减少动效、离屏、加载失败及清理。

## 从母版到真实界面

对于重要资产，在已有设计记录中保留以下关系：

**来源与许可 → 可编辑母版 → 制作及导出方式 → 交付变体 → 使用位置 → 检查与批准。**

[资产记录模板](../skills/ui-spec/assets/templates/asset-record.md)提供提示，现有等效记录可以直接使用。按需要记录尺寸、CSS 显示尺寸、像素密度、主题/裁切、颜色/透明、格式、加载、性能，以及动画或场景参数。它们用于复现设计和管理真实交付，而不是要求每张图都填写长表。

来源授权、品牌使用规则、工具许可、素材可下载和项目批准分别确认。公开发布只包含允许在该目的地分发的文件；受限母版保留在授权位置。用户的重要审美判断通过实际尺寸和真实上下文中的少量方案进行确认。

## 在既有流程中的位置

Init 建立素材与工具现状。Shape 让核心素材参与方向和构图，并确定有价值的制作路线。Iterate 获取或制作、导出、组合、观察和修复。Audit 检查资产本身与整个页面。Finish 将通过的交付变体接入真实加载、内容和状态，并移交可编辑来源与维护责任。

工具文档说明潜在能力，宿主决定当前可用工具；实际执行和导出文件建立制作事实，最终预览与操作建立结果依据。Skill 的职责是做出并执行有依据的专业选择，精确说明尚缺的能力或验证。

## 本版本如何验证

[浏览器样例](../examples/asset-review/README.md)复用当前 README 的真实 SVG 资产和 Lucide 的搜索图标，检查主题与视口变体、实际小尺寸、可访问名称、系统字体内容、资源失败和动态内容控制。其来源与交付关系可以直接检查。

这个样例验证对应的文件与浏览器行为。本轮其他资产路线以专业方法、官方资料与逻辑情境检查覆盖，未将它们表述成已经完成的字体制作、Blender/Cinema 4D/Houdini 工程或真实 3D 运行测试。实际项目根据所选路线补齐对应证据。
