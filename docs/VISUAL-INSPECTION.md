# 视觉观察：让专业判断作用于真实界面

UI Spec Studio 将 **Visual Reasoning & Visual Inspection**（视觉推理与视觉观察）作为贯穿设计工程的基础能力。Agent 实际查看研究对象和最终呈现，运用专业知识解释视觉关系，再让观察结果影响选型、构图、内容、素材和实现。

**理解目标 → 实际浏览 → 观察分析 → 比较选择 → 适配实现 → 查看结果 → 持续修正。**

[产品体验对齐与主动探索](PRODUCT-ALIGNMENT.md)确定研究问题、发现实际观察对象，并将发现连接到资源和实现。视觉观察解释这些对象的品质。这条循环在原有 `init → iterate → finish` 中持续发生；`shape` 用于收敛重要方向，`audit` 可以检查任何已有范围。观察深度由当前设计问题、影响和不确定性决定。

## 从候选资源一直看到真实运行

研究成熟成果时，查看具体页面、组件变体、素材文件或演示状态。沿着相关线索实际播放、滚动、切换、展开与返回，补齐影响选择的组成、状态及其关系。组件的比例、字形、材质和反馈，背景的光影、视觉重心和运动范围，完整模板的信息层级与任务路径，都是选择依据。源码和说明帮助理解实现条件与复用方式。

嵌入演示需要明确观察归属：承载页面、播放器、演示中的应用界面、应用内作品分别提供不同参照。宣传视频中的艺术字可以启发作品内容；应用界面语言要从真实导航、工具栏、面板和反馈研究。页面源码能解释该页面及播放器，视频内应用的行为需要相应证据。

让品质目标与实际实现持续对应，分别观察四个对象：

| 对象 | 需要确认的设计价值 |
|---|---|
| 成熟参照中的相关部分 | 当前任务值得达到的成熟度，以及承载品质的设计关系 |
| 候选资源的原始演示 | 实现本身的细节、状态和动态完成度，以及依赖的展示条件 |
| 当前项目的局部试装 | 引入实际字体、内容、主题和交互后，关键品质是否仍然成立 |
| 整合后的页面与使用流程 | 多个组成是否形成统一表达，真实操作与业务结果是否保留预期体验 |

关键组成在扩大集成前完成局部试装，用长文字、多行输入、缺失图片或真实加载反馈等相关条件暴露差距。原始演示帮助判断资源能力，本地试装确认当前适用性，整体检查继续判断组合关系。常规实例可以继承同一体系在相同条件下已成立的证据。

例如，一个出色的动态背景进入文字密集的区域后，可能需要调整亮度、运动幅度或前景留白。资源本身不适合时重新选型，适配破坏关系时定位改动，内容暴露缺口时共同审阅内容和空间，组合冲突时协调主导设计语言。参照目标与任务不匹配时重新判断产品意图。实际证据决定处理层面；尚未达到的品质保留为明确差距。

## 按用户感知解释视觉关系

先查看完整画面，再研究元素之间的关系，最后检查实际尺寸下的细节。光学平衡涉及形态、明暗、文字密度与留白；排版品质涉及实际字形、字重、行高、换行与阅读距离；材质层次需要结合真实背景、透明度、边界和光影判断。

几何尺寸、对比度与布局规则帮助准确构建和定位问题。最终呈现需要放回产品情境观察：对话入口、阅读页面和数据工作台各有不同的注意力顺序与密度需求。相近成熟度体现于相关任务的可读性、协调性、细节和状态表现；不同品牌、外形和参数可以达到同样适用的品质，判断保留具体维度和证据。

一种有用的分析可以写成：某侧区域因大面积高亮而主导了画面；这可能分散对主要输入区的注意；先比较降低其明度或调整周围留白的效果，再检查实际布局和素材边界。**可见现象、感知解释和实现原因分别建立依据。** 真实使用者是否理解得更好，则由相应的用户观察确认。

## 在空间、时间与旅程中观察

| 观察范围 | 主要判断 |
|---|---|
| 单个画面及局部细节 | 构图、焦点、比例、排版、素材、材质与状态可辨性 |
| 连续视觉片段 | 对象如何变化、反馈何时出现、运动如何影响周围内容 |
| 跨页面的任务旅程 | 共享导航、对象身份、阅读节奏、焦点、滚动与返回方式是否连贯 |

按实际支持条件纳入语言、主题、视口、真实内容和关键状态。页面可以因职责形成合理差异，同时通过统一的文字、组件和操作关系保持产品认知。

## Temporal Visual Inspection：以行为确定时间窗口

**时序视觉观察的基本对象，是具有明确时间关系、交互语义和状态变化的连续视觉片段。** 在参照、候选资源、本地试装和实际产品中比较对应任务与状态：触发前、用户动作、首次反馈、变化过程与稳定结果，必要时连接返回或恢复。容器、字体、主题和业务接入改变了过程时，重新检查受影响的空间与时间关系。

| 行为 | 有意义的观察窗口 | 可能需要扩展的条件 |
|---|---|---|
| 按钮反馈、展开、翻面等微交互 | 触发前到反馈、过渡与可读的结束状态 | 反向、中断、重复输入 |
| 循环背景、粒子或空间化动效 | 足以看到周期、节奏、变化范围和循环衔接 | 最大范围、峰值亮度、多种周期相遇；非周期效果的代表区间 |
| 异步计算或资源加载 | 发起前、等待、阶段反馈与有效结果或恢复状态 | 较早或较晚返回、失败、取消、新意图 |
| 滚动驱动变化 | 同时记录相关位置、方向、进入、停留和离开 | 反向浏览、局部滚动区、返回位置 |
| 导航、弹层与完整流程 | 出发、过渡、到达、继续及返回的相关片段 | 焦点、输入、选择、滚动与共享结构的保持 |

七个相关维度帮助解释这些片段：

| 维度 | 观察的问题 |
|---|---|
| 时间连续性（Temporal Continuity） | 开始、过渡与完成的先后关系是否自然、可理解 |
| 对象连续性（Object Continuity） | 形态、内容、位置与选择是否保留同一对象的身份 |
| 运动品质（Motion Quality） | 速度、缓动、轨迹、节奏和收尾是否符合动作含义 |
| 动态构图（Dynamic Composition） | 运动范围内的文字、组件、光影和素材是否保持清晰层级 |
| 状态与反馈一致性（State & Feedback Alignment） | 动画、文案、可用操作和实际结果是否描述同一状态 |
| 时序稳定性（Temporal Stability） | 加载、内容增长与连续操作时是否保留布局和操作位置 |
| 跨界面连续性（Cross-view Continuity） | 页面、弹层与流程之间是否保持身份、方向感和继续操作的上下文 |

在工具支持时，先以正常速度运行或播放理解整体，再通过暂停、重放、局部细节与相邻关键帧定位问题，最后回到正常速度检查完整关系。调整后重新查看相关区间与前后过程。已有演示提供作者选取的流程；主动操作记录补齐当前问题需要的反向、连续或异常条件。剪辑节奏与真实响应时间分别建立证据。

## 让证据支持它能够回答的问题

视频、有序帧、关键帧和实际操作各有用途。记录能重现重要判断的条件：来源与版本、视口和缩放、语言与主题、内容状态、触发动作、帧顺序和实际时间。比较时对齐有意义的事件，并说明真实加载时长或内容差异。

观察窗口跟随行为范围，采样密度跟随变化速度，分析深度跟随设计影响。连续采样需要能够分辨正在研究的变化。关键帧方便比较位置与状态；相邻画面帮助定位闪烁、遮挡或跳变；完整播放支持节奏判断。采样间隔、遗漏片段、录制缩放和捕获开销都限定观察范围。工具只能提供有序帧时，将结论限定在实际看到的序列，并保留仍需播放确认的部分。

受控时钟、逐帧定位与慢速播放用于分析顺序和中间状态。自然运行的节奏与流畅度需要对应条件下的观察，性能结论还需帧时间、长任务或其他相关运行测量。动画结束、界面出现成功样式和权威业务完成分别检查其实际含义。

最终记录区分**已经采集、实际查看或解析、证据足以支持的结论、已经操作验证、已经工程测量与已经获得用户批准**的内容。图像内容的分析可以支持对应帧的判断；流畅度、真实用户理解和业务完成各需匹配的证据。记录无需使用统一字段模板；已有项目文档只要能让人找到证据、理解判断并继续工作即可。

## 用观察形成可检查的设计决策

重要选型可以展示候选原始效果、局部试装和采用位置，说明实际保留的布局、状态或运动机制；重要迭代呈现相关画面或片段，解释调整目的与复验结果。内部机制显著变化后，当前实现需要承担相应品质验证。品牌气质或主要交互仍有明显分歧时，用可见方案支持用户确认。日常尺寸、排版和参数调整由 Agent 在既有方向下推进。

重要资料需要登录、官方客户端或授权导出时，可以在已有材料仍不足的具体问题上请求用户协助。集中说明访问对象、操作、相关状态或连续过程及其决策用途，随后继续实际观察和专业比较。收到文件建立材料可用性，允许研究与允许集成分别依据其使用条件。

观察应带来具体价值：发现可采用的成熟实现、确认适用性、识别问题、改变决策或确认修正。完整工作方式是：

**Observe → Interpret → Evaluate → Decide → Implement → Inspect → Refine**  
**实际观察 → 专业理解 → 质量评估 → 设计决策 → 工程实现 → 结果检查 → 持续优化。**

这一方法同时适用于应用 UI、README、图表、字体、图标、视觉素材与动态作品。具体媒介决定查看方式，实际使用目标决定品质判断。
