# README design specification

## Surface and task

This is the project's own public reading and installation surface. The primary
reader wants to know what the skill does, whether it fits their work, how to start
and how to judge its claims. Existing users need a quick installation/update path;
maintainers need deeper documentation without interrupting the first-use path.

The delivery medium is GitHub-flavored Markdown, with native headings, text, links,
code, tables, disclosure and theme-aware images. The page uses document scrolling.

## Expression concept

**From meaning to form.** The skill's mechanism is a connected design practice:
understanding, composition, realization and inspection. An editorial design plate
shows intent becoming relationships and a working result. It is an authored
illustration, not a screenshot or a performance claim.

The reading sequence is purpose → installation → first use → capabilities →
continuation/integration → methods → evidence. Each region answers a reader
question. The install command is native copyable text near the start. Detailed
maintainer material uses an optional disclosure section.

## Visual and implementation choices

Warm paper and dark green-black surfaces, a restrained green emphasis and a small
warm connector accent support a calm editorial identity. Display type uses a
system serif fallback inside the authored SVG; essential prose uses the publishing
host's native font. No font files are redistributed. The same color roles govern
light and dark artwork.

A wide plate and a separate narrow composition preserve readable relationships.
The mobile image is not a miniature of a desktop canvas. Essential information is
also present as native text and alt text. The artwork is static, deterministic,
self-contained SVG with editable geometry generated by `tools/readme_art.py`.
English and Chinese pages share the language-neutral identity plate and equivalent
native explanations. All command options and claimed capabilities reflect the
actual distribution.

## Control surface and reproduction

Palette roles live in `PALETTES`; composition geometry and typography live in
`render(theme, compact)`. Regenerate and check:

```bash
python tools/readme_art.py
python tools/readme_art.py --check
```

Optional browser-preview dependencies are in `tools/requirements-preview.txt`:

```bash
python -m pip install -r tools/requirements-preview.txt
python -m playwright install chromium
python tools/preview_readme.py --output-dir /tmp/ui-spec-readme
```

The preview uses Markdown-It with a documented GitHub-like article stylesheet.
It exercises actual Chromium viewports but is a **local renderer approximation**,
not a pixel-identical copy of GitHub. The `--live-commit <sha>` option additionally
captures the real GitHub README rendering at that commit when network access permits.

## Intended verification

Inspect both languages in light and dark at 390×844, 768×1024 and 1440×1000.
Capture the whole viewport and document length, expand the maintainer disclosure,
check internal routes/anchors, image readiness and document-width overflow.
Native code/table regions may scroll within their bounds. Confirm that installation
is discoverable and copyable, artwork retains useful scale and no essential text
requires images. Compare theme/narrow image selection, heading structure and alt text.

Automated checks establish DOM, file and layout facts. Open the captured images to
judge visual composition. Local preview and final-host observation are separately
reported in the generated JSON. The release CI also checks remote GitHub rendering
where available; any missing observation keeps its explicit status.

## Review record

Local Chromium rendering completed for all 12 language/theme/viewport combinations.
The exact SVG bytes were embedded in the local renderer, preserving responsive
picture selection while allowing an offline render. Native installation text,
image readiness, alt text, disclosure and document overflow checks passed. Images
were opened for composition review; the first pass led to moving the explanatory
user-role paragraph below the immediate start path. The revised pages were recaptured.

This record describes the local approximation. The release Actions run supplies
separate actual-GitHub conditions and captures for the committed source. Refer to
its publication-check JSON for remote observations and the exact browser results.
