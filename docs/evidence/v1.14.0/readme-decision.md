# Maintainer self-application: the README evidence-map section

This is actual local publication work by the editing agent. It is not an
independent Agent experiment and has no control group.

## Overview

**L0:** help a reader understand what the method changes before deciding to use
it. Preserve the existing quick install and native GitHub reading experience.
**L1:** understand the method → follow detailed guidance → use the current skill.
**L2/L3:** the README's method section and its link group. **L4:** heading/body
hierarchy, paragraph rhythm and locale-specific line wrapping. **L5:** actual
Markdown and locally rendered observations; exact-host verification is separate.

The established README and renderer form the inherited foundation. No new
component dependency or original artwork was needed for this low-risk scoped
addition. Source roles are the accepted repository content and native publishing
mechanism, not a claim of newly researched external resources.

## Design Detail — D-README-EVIDENCE

**Purpose/question:** make the difference between a map, an actual next action
and a structural checker understandable without a long front-page specification.
Should method links remain inline or form their own reading group?

**Evidence:** the local detail capture records retain the exact source hashes,
viewports, themes, image hashes and crop coordinates. The English inline version
at 1440px put the separator on a new line. The Chinese version already used a
separate link paragraph. These are inspected render findings, not inferred from
Markdown syntax alone.

**Judgment/choice:** separate the guide links from the explanation in both
languages. This preserves native links and consistent paragraph rhythm without
changing the inherited page shell or artwork. Alternative inline placement was
actually rendered and rejected for this observed wrapping condition.

**Adoption:** README.md and README.zh-CN.md use their existing native headings,
paragraphs and links. The only layout repair was an English paragraph boundary.
The result is a publishing surface, not an application component runtime.

## Execution & Assurance

The final local matrix contains English/Chinese, light/dark and 390/768/1440px
conditions. All 12 changed-section crops were viewed in four original-pixel
sheets. The inherited preview tool's DOM/image/overflow/disclosure checks also
passed. No blocking defect remained in the inspected area. The first off-screen
clip command failed and was repaired; this was capture setup, not UI failure.

See [the exact local observation record](readme-local-review.json). Existing
GitHub-host CI performs its own checks for the source commit. Public-host pixels,
clipboard, assistive technology and reader comprehension have separate scope.
The next responsible verification is the exact-host publication readback, not
another broad research campaign for this already supported local change.
