## Transfer decisions

| Useful mechanism | Re-expression in installed guidance | Excluded or qualified material |
|---|---|---|
| Type roles, weight/spacing relationships | principles: actual glyph metrics, optical scale, CJK/wrapping, component trials | Specific family/size defaults, mixed-family bans and universal numeric palettes |
| Surface/light relationships | principles and assets: source material, foreground, crop, dynamic contrast | Mandatory grain/vignette, tinted-neutral mandates, universal pure-black/white bans |
| Effect versus route | interaction: effect, control ownership and implementation route | Fixed engine order as a universal rule, unmeasured bundle/fps promises |
| User-controlled movement | interaction: tracking, resistance, recent velocity, axis and cancellation observations before adopting a mature sheet | Copied constants; cancellation is not automatically treated as a confirmed release |
| Concrete cause/action writing | sourcing and WRITING: visible problem → relationship/mechanism → mature source → adaptation → inspected result | Default code recreation, five mandatory forms or rigid aesthetic constraints |
| Positive examples | sourcing/patterns: external mature work as primary example space, bounded teaching/regression fixtures | Wholesale bundled example corpus or universal inference from one impressive demo |

UI Spec Studio's reuse-scope/visual-completeness model, neutral tool boundary and
product-category-independent expression follow the user's accepted requirements
and existing methods. They are a deliberate synthesis, not a claim that Finesse
already prescribes the same priorities. Subsequent application outcomes retain
their own source, conditions and execution scope.
