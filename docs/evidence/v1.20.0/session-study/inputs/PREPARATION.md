# Four real public-source starters for the session-subagent study

Prepared outside the repository. No Codex/app-server participant was executed, no native event stream was synthesized, and no previous participant output was used as a starter.

## Source selection

The previous default-deny archives were inspected and rejected for this protocol. Their T1 is an almost empty React entry; T2/T3 identify themselves as authored UI Spec Studio fixtures. The previous conversation example likewise does not establish a mature external application foundation. None was substituted for a fresh independent run.

| Task | Actual runnable foundation | Bounded application |
| --- | --- | --- |
| T1 | Tabler complete official settings-page snapshot, v1.7.1, matching compiled framework assets and tagged source | Bilingual profile, notification and privacy coherence over a real browser-local settings contract |
| T2 | assistant-ui cloud-template layout plus its complete unchanged Thread/Composer, attachments, sidebar and component dependency closure | Composer/reading continuity with local deterministic streaming, filename attachments, fail-once and cancellation |
| T3 | Intact TiddlyWiki 5.4.1 server edition, native UI and filesystem plugins | Populated bilingual research-note workspace with an open mature visual direction |
| T4 | Same real Tabler settings application; acquired action-bearing Toast block | Settled source-preserving save-feedback integration, with authoritative state and bounded edit files |

T1/T4 retain upstream gallery navigation as peripheral source context; those unrelated gallery routes are outside the settings contract. T2 replaces the original cloud/Next shell with Vite and a synthetic local adapter; the component source remains mature upstream implementation. Its original Inter and IBM Plex Mono font configuration is retained through pinned self-hosted OFL fonts. T3 retains the whole npm source package so its native UI and real save system require no installation.

The deployed Tabler HTML advertises 1.7.1 but not a deployment commit. Its exact HTML digest and the separate 1.7.1 tag commit are both preserved, without claiming a stronger identity than the source exposes.

## Readiness evidence

`logs/starter-smoke-report.json` records actual T1/T4 save → reload and one-time failure → retry checks, as well as actual T2 rendering/streaming, with no browser page errors. The final smoke has no missing network assets. `logs/t2-contract-report.json` verifies filename attachment rendering, the partial-response failure, retry beyond that failure point, and stop returning to send. `starters/T3/evidence/` contains the native editor → confirm → filesystem → reload check and three actual render conditions. Raw stdout/stderr are retained, including harness-selector failures and corrected runs.

All screenshots were captured from the real local app processes with pinned Chromium 143.0.7499.4, Playwright 1.57, and `FONTCONFIG_FILE=/tmp/ui-spec-fonts/fonts.conf`; the shared font environment includes Noto Sans CJK SC. The starter-preparation agent viewed the actual T1/T2/T4 captures; the T3 preparation agent viewed its light, compact dark Chinese and narrow reduced-motion captures. The coordinator also personally viewed T1/T2 initial composition and the T4 selected source before settling T4. Initial T2 frames captured during the source's entry transitions are retained separately; stable current-font captures use the source transition settling interval.

These are starter readiness observations. They do not establish a study-arm outcome, comparative quality, general accessibility, natural-speed animation smoothness, model ranking, or end-user approval.

## Staging

Frozen participant material is each task's `app/`, `INPUT.md`, exact original `TASK.md`, source/license records, and T4's actual decision. The central `starter-manifest.json` identifies these bytes. Readiness evidence is separate and need not enter a participant context. Preserve identical application/task/source bytes within matched arms.

T2's install cache is under `dependencies/T2-node_modules`, outside frozen inputs. Its original `app/dist` is immediately runnable by a static server. For source edits use the exact lockfile with `npm ci`, or give all matched workspaces the same explicitly recorded host dependency link after staging. Do not include caches in app-source identities. T1/T4 need Python's standard HTTP server; T3 needs Node and its supplied `start.sh`.

No server from preparation is left running. All preparation files are under `ui-study-prep`; no repository source file was modified.
