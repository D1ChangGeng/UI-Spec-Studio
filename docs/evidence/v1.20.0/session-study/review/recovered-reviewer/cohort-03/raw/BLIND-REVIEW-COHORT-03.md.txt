## Visual and product judgment

### A coherent source-family workspace

P07 retains the supplied sidebar, breadcrumb/header, centered conversation column, restrained message actions and anchored composer. The original desktop and compact views show a readable relationship between the question, answer headings, paragraphs, next-step copy and input. The dark condition uses the established dark surfaces and light text, and its Chinese paragraphs remain legible. At narrow width, the collapsed sidebar leaves the reading column and composer as the dominant work area.

This is a meaningful composition with populated content rather than a conclusion drawn from an empty screen. The original light desktop attachment/input image shows several filename items beside the longer question while retaining a substantial reading area. The original narrow image shows how a question that wraps onto many display lines uses internal input scrolling. The source-family typography, surfaces and action hierarchy remain recognizable.

The original captures visibly show native scrollbars for the reading region, attachment strip and long input. The independently generated compact screenshot does not show the same persistent scrollbar chrome. I do not attribute the scrollbar-paint difference to a product redesign: the source comparison did not identify a new scrollbar styling system, and capture/browser rendering can affect that chrome. The actual scrollable regions and their dimensions were separately observed.

### Attachment disclosure

P07 composes the supplied small File family with the existing Dialog. Each item retains the real filename before and after sending; long names are truncated within the horizontal strip. The full filename becomes the dialog title rather than being repeated inside an additional nested file card. In the personally viewed narrow dark dialog, the selected filename wrapped readably over two lines, with the close control separate at the top right. The Chinese description plainly states that only the filename is attached and that file contents are not read or sent.

The narrow dialog fit within the viewport: its observed rectangle was x=16, y=348, width=358 and height=148 in the 390×844 condition. There was no horizontal document overflow in that state. The modal blurs the conversation behind it, so reading context is temporarily obscured while the user inspects the filename. This is a clear tradeoff of modal disclosure.

Four selected files produced a 1,048 px-wide strip inside a 338 px visible area at narrow width. The first view cannot show them all. Focusing and opening the last filename moved the strip to scrollLeft=710 and disclosed its complete name. Thus the tested last attachment remained reachable, although discovery of offscreen files and the usability of much larger collections remain limited by the horizontal model.

### Compact composer

The source adds a maximum input height of 6rem when viewport height is 650 px or less. The fresh 1280×600 screenshot shows the last four lines of the six-line question while the earlier two lines lie above the input's current visible portion. The full six-line value remained in the input and was sent through the runtime; the test did not replace it with shortened content.

That cap reserves additional answer-reading space at compact height, at the cost of internal composer scrolling. It is a defensible relationship for this task, with a real editing tradeoff. The assessment is limited to the representative question and original longer wrapping example. It does not establish that every much longer draft, input method or keyboard-navigation pattern is equally comfortable.

The send/stop action remains visually distinct at the lower right of the composer. Return to latest is the existing circular icon with a localized tooltip/accessibility name. That is less explicit at a glance than a permanently text-bearing control, but its observed action and accessible name were usable in the tested path.

## Core behavior and recovery

### Attachment and focus continuity

The independent run selected notes.txt and three representative long filenames using the native file chooser. It entered a six-line mixed-language question, opened a long filename by keyboard, and dismissed the dialog with Escape. Focus returned to the exact filename trigger. Removing the short attachment returned focus to the composer.

The narrow dark run selected all four files again and opened the last one by keyboard. Its complete filename and filename-only explanation were present in the actual dialog and personally inspected pixels. The underlying adapter was byte-identical to the supplied synthetic adapter; the test did not introduce real uploading or file-content reading.

### Reading while an answer grows

After sending, I used actual wheel input to move away from the latest content. The sampled scrollTop stayed at 91 while content height grew from 1,391 to 1,727 px. This supports preservation of the chosen reading position during the observed growth interval.

Activating Return to latest then reached the bottom and followed continued streaming. The sampled bottom gap was 0 at approximately 150 ms, 500 ms and 1.5 seconds after activation. The runtime remained running at all three samples. Source inspection confirms that the return action explicitly requests instant behavior; the behavior evidence establishes what happened in this run.

These results address a consequential task requirement. They do not prove every possible scroll gesture, viewport change or asynchronous rendering sequence.

### Stop and continuation

Keyboard activation of Stop left the runtime non-running and returned focus to the composer by the first 100 ms observation. The same composer focus persisted in later samples. Body text length was 3,623 at the first recorded post-stop observation and remained unchanged at the later settling and 500 ms follow-up samples.

The source schedules focus restoration to the textarea in the containing form. That implementation detail is consistent with the observed result; the review relies on the actual focus and content samples rather than assuming that the presence of a callback guarantees correctness.

A later one-line follow-up could be sent and stopped. This preserved the user's ability to continue the conversation after the initial stopped answer. The tested path therefore did not reproduce the Stop-focus loss previously frozen for P17. That is a product-level observation, with no attribution to an undisclosed production condition.

### Failure, retry and reload

The synthetic [fail] question failed after partial text. The fresh failure screenshot shows a clear red error surface beneath the partial answer, explaining that the local response failed once and that retry uses the same example. The response remains visible, and the message actions sit next to the error context.

Keyboard Retry completed the full fixed response through Observation theme 7. The recorded run found no remaining message error after completion. A subsequent reload returned to the seeded conversation, matching the supplied in-memory boundary. This is expected behavior for the task; it does not establish persistent remote conversation history.

## Comparison, remaining limits and freeze

Within the previously reviewed T2 products, P07 shares the mature File/Dialog approach used by P04 and P17. Its filename-as-title dialog is concise and the viewed name wraps cleanly. Its compact-height cap preserves more reading space by introducing internal input scrolling. Its Return to latest remains icon-only, whereas P17 exposes a text-bearing action. The tested P07 Stop restored focus; the earlier P17 focus defect remains frozen and unchanged. These comparisons describe observable product differences without proposing a hidden-condition explanation or broad causal generalization.

No material blocker emerged from the exercised P07 path. The main caveats are the horizontally browsed attachment collection, temporary modal obstruction of the reading context, partial visibility of longer questions in the compact composer and the icon-only return control. Full assistive-technology behavior, physical-touch interaction, arbitrary attachment counts, very long unbroken filenames, much longer drafts, all message-edit/branch actions, reduced-motion playback and a browser matrix were not established.

The test used a prescribed headless browser and synthetic local data. It is an independent agent product review, not a human usability study, assistive-technology certification, natural-speed playback review or claim about a real model service. Isolation was maintained by instruction on a shared host, not through a separate security sandbox.

The cohort-03 freeze manifest preserves this report, P07's structured record, metadata and evidence index. The cumulative products.json appends P07 without changing any previous row.
