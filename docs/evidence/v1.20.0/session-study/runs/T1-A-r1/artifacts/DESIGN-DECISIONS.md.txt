# Fieldnotes settings — one coherent settings increment

## Goal and boundary
The current product is the supplied Tabler settings page with browser-local persistence. This single increment owns profile, notification and privacy editing; real validation, pending, failure, retry, cancel and return; English/Chinese; light/dark; desktop, compact height and narrow reflow. The existing Tabler page, card, typography, navigation, form and theme family remains the foundation. Gallery routes are source context and outside this product contract. No original visual construction or W1–W3 exception is used.

## Questions, evidence and decisions
- **Page and task continuity (L0–L2):** the starter capture shows clear inherited card/sidebar grouping, but the mobile settings menu consumes most of the first viewport. Retain the same navigation and apply Tabler's existing collapse pattern on narrow screens. Retain document scrolling for short heights; do not introduce a new fixed workspace.
- **Profile content and type (L3–L4):** the initial 1440×900 capture truncates ordinary organization content in the three-column field row. Recompose the existing grid with wider fields. Use Tabler form-control textareas where name/organization need wrapping, keeping values editable and using source type/surface rules. Move fixture language/theme buttons to the existing page-header action row so profile identity and preview settings have distinct roles.
- **Save state (L1, L3, L5):** `settings-store.js` is authoritative and remains unchanged. The starter's status text cannot associate errors with fields or explain newer edits after a pending snapshot. Use the retained Tabler Alert and form validation classes; bind messages to store events. Keep fields editable during pending, prevent duplicate submission, and distinguish the committed snapshot from subsequent edits. Cancel reloads the last saved value and is disabled during pending because the store has no cancellation operation.
- **Language and themes:** keep Tabler semantic colors and theme implementation. Switch language in place to retain draft, focus and failure-fixture state. Translate core controls, hints, validation and status messages. Preserve entered values.
