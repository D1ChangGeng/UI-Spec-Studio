# Fieldnotes settings — research report

## Decision-useful outcome

The supplied Tabler settings page remains a suitable mature foundation. The consequential gaps are feedback placement, accurate save semantics, field association, and compact navigation. The evidence supports completing those relationships with Tabler’s existing alert, validation, button, grid, and collapse families. No replacement visual system is indicated by this bounded inquiry. Final product decisions and integrated acceptance remain with the primary designer.

## Source-supported candidates and adoption paths

### Persistent form alert versus toast

**Persistent in-flow alert:** Tabler’s alert documentation supplies ordinary error alerts, an action link, and `alert-minor` for reduced emphasis. The retained exact-tag implementation is `sources/shared/ui/Alert.astro`; it supplies the icon, heading, description, optional list, action, and close-button structure. The installed 1.7.1 CSS contains `alert-minor`, `alert-heading`, and `alert-description`. This is the lower-integration-cost candidate for feedback beside Save. Its final footer height and wrapping need direct inspection. [Official alert documentation](https://docs.tabler.io/ui/components/alert)

**Toast:** The supplied `sources/shared/components/demo/Toast.astro` already distinguishes polite status from urgent alert and sets autohide false. Its source-defined header, avatar, timestamp, body, and dismiss control introduce a separate notification hierarchy. Official guidance says actionable toasts must not disappear automatically, and the sole recovery action must not exist only inside a toast. This is a viable supplementary notification mechanism, but it does not remove the need for field errors or a persistent recovery location. No live toast demonstration was successfully viewed in this research. [Official toast documentation](https://docs.tabler.io/ui/components/toast)

**Research judgment:** For this one short settings transaction, one persistent footer alert keeps outcome and next action associated without creating a second notification destination. This is a recommendation, not a final product decision. The parent independently reports adopting this route.

### Validation and pending state

Use the authoritative store’s `fieldErrors` with the existing `form-control is-invalid` and sibling `invalid-feedback` pattern. Tabler documents `aria-invalid`, `aria-describedby`, useful correction text, and focus on the first failed field. Bootstrap independently documents associating feedback IDs and permits multiple described-by IDs. Keep validation semantics at the store rather than changing rules to match browser defaults. [Tabler validation](https://docs.tabler.io/ui/forms/validation) · [Bootstrap validation](https://getbootstrap.com/docs/5.3/forms/validation/)

Tabler’s `btn-loading` hides its label and draws a spinner. Its documented contract also requires an actual disabled control and `aria-busy`; pointer-event suppression alone does not prevent keyboard activation. A spinner beside readable text is another documented candidate. Both relevant CSS classes are present locally. This establishes an available mechanism, not the parent’s final focus or announcement quality. [Tabler buttons](https://docs.tabler.io/ui/components/button)

### Compact navigation and fixture controls

The original settings layout is already a responsive `col-12 col-md-3` / `col-12 col-md-9` composition with a transparent list group. Keep that source responsibility.

Materially different compact candidates within the family are: a disclosed list using existing collapse behavior; smaller `list-group-sm` entries; or horizontal list composition. The list documentation supports compact and horizontal variants. Horizontal labels introduce a different wrapping problem with the existing longer navigation names, and were not trialed here. The parent’s reported `collapse d-md-block` choice preserves the list itself and merits checking disclosure state, keyboard access, section navigation, and the 768px breakpoint. [List group documentation](https://docs.tabler.io/ui/components/list-group)

Moving the language/theme fixture controls into the existing page header has a source-supported composition path: Tabler page headers use a title column, an action column, and `btn-list`. Preserve the established button scale and heading/action relationship. [Page headers](https://docs.tabler.io/ui/layout/page-headers)
