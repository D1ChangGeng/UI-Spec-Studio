# Research report: conversation continuity

## Findings and implications

- **Keep the supplied assistant-ui family as the principal candidate.** Its current source ties a sticky `ViewportFooter`, `turnAnchor="top"`, `ScrollToBottom`, autosizing composer, stop/send and message actions into one thread. Official documentation describes following streaming text only until manual scrolling, and resuming at the bottom or by using the return control. This is documentation for the current public library, not proof of the pinned revision's runtime behavior; test the exact installed revision with streaming and real user scroll.
- **At 1280×600, six lines consume meaningful reading space.** In the observed local baseline, the 1-line composer begins at approximately y=482 and the six-line shell at y=370; textarea height was 152px. The shell overlays the lower reading passage. The visual hierarchy remains coherent (white reading surface, restrained rounded composer, low-weight actions), but text growth reduces the uninterrupted reading field. A compact-height cap is a plausible source-compatible adaptation; check textarea internal scrolling, focus/caret visibility, footer clearance and reading anchor together.
- **Filename discrimination is the salient attachment question.** Source inspection shows 56px generic document tiles whose complete filename is in a tooltip and accessible label; multiple non-image files look identical until disclosure. The draft attachment row horizontally scrolls; sent attachments are laid in a non-wrapping flex row. Test filenames with common long CJK prefixes, keyboard focus, removal, and many attachments both before and after sending. Visible filename disclosure is useful if adopted from a qualified mature source; don't treat this observation as permission to invent an unrelated replacement UI.

## Alternatives and adoption paths

- **Vercel AI Elements / chatbot**: [prompt source](https://github.com/vercel/chatbot/blob/main/components/ai-elements/prompt-input.tsx) and [conversation source](https://github.com/vercel/chatbot/blob/main/components/ai-elements/conversation.tsx). Source inspected via web: textarea uses a 192px maximum, composition guards for IME, Shift+Enter behavior and keeps draft on failed async submit; the conversation return button is conditional on `isAtBottom`. Its maximum does not improve the compact-height issue by itself. Inspect exact revision/license and original rendered attachments before adopting a coherent subcomponent; integration would need to reconcile its state provider with the existing assistant-ui runtime. No local trial performed.
- **MUI X Chat Composer**: [documentation](https://mui.com/x/react-chat/material/composer/). Published anatomy includes resizing textarea, toolbar, attached-file queue and CJK IME guard; compact variants include separator, floating pill, elevated card, minimal and inset treatments. This is a materially different, Material-themed family and alpha API. Useful comparison for compact arrangements, but more costly than retaining the cohesive existing styling/runtime; no actual rendered demo or license/version fit established here.
- **shadcn-chatbot-kit MessageInput**: [documentation](https://shadcn-chatbot-kit.vercel.app/docs/components/message-input). Published component supports attachments, autosizing, stop and configurable Enter behavior; code acquisition via registry command is documented. An interrupt-on-double-Enter is distinct behavior that should not be assumed desirable for this task. Visual quality, source license and runtime compatibility remain unverified.

## Evidence and limits

`w13_initial.png` and `w13_six.png` are actual locally rendered 1280×600 light English baseline screenshots, personally viewed; `w13_research.py` records the capture procedure. `public-sources.json` retains the actual public-source retrieval. Local baseline screenshots establish appearance only, not scroll/cancel/failure/focus behavior. An attempted attachment run could not find a file input; a second attempt could not find the attachment control on the shared preview after it changed, so no attachment episode is claimed. Public pages were read as documentation/source, not visually operated. No product code changed and no candidate adopted. Validate the final integrated product at 1440×900, 1280×600 and 390×844, light/dark and both languages, with scrolling while streaming, return, abort, failure/retry and focus continuity.
