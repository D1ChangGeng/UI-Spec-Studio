## D1 — whole-workspace foundation (provisional)
Question: can a coherent editorial theme carry stronger identity than the baseline without replacing native tasks?
Observed sources: baseline-1440.png; paper-original-1440.png; notebook-original-1440.png, all personally opened via view_image (evidence/views). Original demos have their own content; same-content local trials are next.
Paper 0.10.0: real cream sheet, thin red margin rule, serif titles/body against sans navigation, narrow 68-character reading measure, separately ruled mono editor. Native sidebar and note controls remain recognizable. Stronger source fit to editorial research goal, provisional favorite.
Notebook 1.4.1: centered sheet and persistent top utility strip, with hidden left sidebar; compact sans hierarchy and palettes. Materially different composition and navigation; meaningful challenge to the first preference because it reserves more width and keeps search at hand.
Both MIT sources acquired from original repositories. Paper is actively developed and newer, so compatibility must be established locally rather than inferred from maturity by age. Notebook uses a mobile helper plugin and older source assumptions.
Next action: install unchanged candidate sources into the current wiki, compare the complete supplied interview/editor at equal viewports and font fixture. Failure of Chinese rhythm, native editor or narrow controls would reopen selection.

## Revision — selected Paper after same-content trial
The viewed 1440px interview and editor retain Paper's margin, serif reading, separate sans chrome and ruled mono editing. Notebook's topbar is a useful compact alternative but its sans reading surface creates less distinction between content and operation. Tufte CSS's local original publication demo was viewed as a cross-domain reference: strong measure and typographic roles support sustained reading, but its article/sidenote model does not supply native editable workspace behavior; none of its implementation or font assets are adopted.
Selected: Paper 0.10.0 from revision 031a78d4d4187128c632f8a647fa05408eddc700. The complete theme is installed unchanged under app/wiki/themes/vanilla-paper with its MIT notice. Notebook is retained only as research source, removed from runtime.
Supported configuration keeps note toolbars always visible and titles sticky. Existing numeric text metrics are expressed equivalently in rem/unitless units to respect user scaling without replacing the source type relationships. The existing Day/Night palettes are copied under their original titles with three narrow foreground-role changes to source sidebar-foreground for more legible note actions and timestamps; no new colors are invented.
A narrow editor trial capture after resizing displayed the index at the old scroll offset, rather than the intended editor. This is retained as a failed capture condition, not passed editing evidence. Final checks must set viewport before native navigation/editing and capture the actual draft.
Next: final source selection must pass native persistence, cancel, keyboard search, complete interview/ledger/return, both palettes and required viewports. Sticky titles need assembled inspection, particularly at 390px.
