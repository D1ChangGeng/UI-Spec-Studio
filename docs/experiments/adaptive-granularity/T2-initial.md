# Meridian: conversational research workspace

Use the supplied ui-spec Skill to build `app/` as a working browser-local product
demonstration. `reference-project/` is an available public example, not an approved
product design. You may adopt useful implementation or design relationships and
research other suitable mature sources. Preserve source attribution and distinguish
real adoption from inspiration.

The overall target is a refined conversational workspace where people ask a research
question, read an unfolding answer, inspect its sources and continue a thread.
It should eventually support a history sidebar, a growing multiline composer,
attachments as local filename chips, long streamed answers, stop/retry, source
reading beside the conversation, light/dark themes and compact-width navigation.
Use deterministic synthetic responses and clearly identify their demo status.
Do not send files, questions or content to an external service.

Prioritize a convincing, usable core experience and make the plan for the remaining
target clear. The core should allow repeated questions, visible asynchronous
progress, stopping, recovering from a simulated failure, and reading without
losing one's place. The composer and reading space should feel like one mature
workspace as content grows. Choose an expressive but quiet visual direction with
careful type, surfaces and action hierarchy. Avoid turning the UI into a description
of engineering or design methods. Support keyboard use, 1440×900 and 390×844.
Implement and inspect the actual result; be accurate about incomplete capabilities.
