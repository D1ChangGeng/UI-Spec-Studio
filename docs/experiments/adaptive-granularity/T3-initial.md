# Fieldnote: continuous card motion

Use the supplied ui-spec Skill to refine the saved-note card application in `app/`.
Keep the same basic note task and browser-local persistence. The front/back change
is an important part of the visual identity: it should feel like one object that
keeps its place and weight as editing becomes a saved note, and when it returns.

Study the actual trigger, preparation, motion, settle and reverse sequence. Improve
the card's proportions, typography, material, lighting and movement in the context
of the full composition. Repeated quick actions and editing a long note should
remain understandable. Preserve real save failure, retry and draft behavior; a
failed save must not visually promise success. Provide a convincing reduced-motion
equivalent and keyboard/focus continuity, in light/dark and at 1440×900 / 390×844.
Use suitable mature work where it helps. Keep honest local-demo language while
removing internal design explanations from the main task. Implement, inspect and
deliver the actual experience, including any limitations you could not verify.
