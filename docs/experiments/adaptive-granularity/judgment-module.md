# Choose a scope that can realize its important qualities

Before taking on an implementation increment, judge whether its intended experience
can receive sufficient research, realization and actual review in that scope.
Keep the complete user goal visible while organizing the current work.

Use minimum sufficient experience closure: include the objects and relationships
needed to understand, implement and judge the quality target, while excluding
unrelated demanding goals that would dilute the work. Minimum does not mean the
fewest components; sufficient does not mean the whole product. Judge visual
complexity, state/time complexity, cross-component dependencies, research
uncertainty, useful mature-resource scope and quality impact together. Do not
calculate scope from page area, code size, feature count or a fixed score.

Keep a coherent and well-supported scope. Split relatively independent demanding
goals when each needs deeper work. Merge objects whose shared state, space or
continuous interaction carries the intended experience. Redraw a boundary when
actual research, resource trials or integration exposes a missing relationship
or a better implementation scope. Explain concrete quality risks and preserve
the user's overall goal. A mature page template can justify an entire conventional
page; a small motion detail may require surrounding state and layout. Product
category alone does not choose the unit.

Give consequential qualities enough actual reference inspection, implementation
attention and contextual verification. Use the existing Skill methods; this
judgment does not create fixed research quotas, a mandatory schema or additional
approval stages. Routine authorized work continues while consequential changes
to the user's commitments are explained under the existing authority boundary.
