# Collection increment

The new request extends the same working object from one note to a collection. Preserve the accepted paper, centered flip, native editing, bounded text and reduced-motion relationships. Reuse the verified card family as the collection foundation rather than introduce a different template or framework.

## Decisions before verification

- Prepare the selected note's draft and stored text synchronously before exposing the detail surface. All collection records are already read into memory. Keep drafts, selection and pending attempts keyed by stable note ID; save completions update their own records even after navigation.
- Collection cards and the detail surface share the note number and material. A native same-document View Transition links their rectangles; static root snapshots avoid an unrelated page fade. Guard concurrent callbacks with a generation token and skip an obsolete transition. Reduced motion and unsupported APIs commit immediately.
- Preserve the original scene/object/opposing-face CSS for edit/save. Existing records migrate in memory from the original storage key; the collection is saved atomically as one versioned localStorage value. No automatic write is needed on read.
- The collection restores scroll and focus to the edited card. In-tab drafts are marked clearly and remain reopenable; unsaved text is not promised to survive reload.
- No seed records create false saved content. The fresh collection has a real empty state. Read errors block writes and offer retry. Write errors preserve both drafts and previous stored versions.

Primary API reference read: https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition (2026-10-29). The documented callback/snapshot/finished sequence informed the enhancement. This is a platform technique transfer combined with the existing inspected card family, not adoption of an external collection template. Original card-source attribution remains in app/THIRD_PARTY_NOTICES.md.

Scope: desktop/mobile light/dark, ordinary/reduced motion, short/long notes, legacy migration, repeated open/save/back/switch, pending writes across navigation, storage failure/retry, honest empty/unreadable states. Actual browser observations to be appended after execution; timing and screenshots do not by themselves establish perception.

This was a measurement correction, not an application-data repair.
