## Conditions and causal separation

A uses the complete v1.19 Skill with one main Agent. B uses the same Skill and generic subagents for research. C uses the same Skill and the specialized researcher. B, C, D and E retain product implementation in the main Agent, so researcher instructions are not confounded with delegated coding. D holds C instructions/tools fixed and varies the explicitly declared subagent model. E compares C with the additional on-demand challenger or observer role active one at a time. F-main versus F-integrator uses the same complete candidate Skill and settled T4 input, differing in bounded integration delegation. G-final-runtime separately exercises the complete candidate method with all four roles available for conditional delegation.

The runner installs all four adapter role files in C, D, E, F and G. A and B have no specialized role files. Registration separately records installed roles and the condition's allowed invocation set; `role_names` remains an alias for that invocation set. C/D permit only `ui_researcher`; each E permits the researcher and its named supplemental role; F-main permits no delegation and F-integrator permits only the integrator. G permits all four without requiring any invocation. Review native child logs for actual use and record installed-but-unused roles as a shared prompt-context limitation across adapter arms.

C therefore measures the role increment; it does **not** by itself validate the final v1.20 runtime. G validates the final integrated method's actual behavior, without pretending that all its differences identify a single causal factor. The sample plan is a matrix to fill with model IDs actually available in the authorized environment, not a pre-registered executed campaign. In C the other installed roles must remain unused; E deliberately activates the selected on-demand role. Log actual spawned role identities rather than inferring use from installed TOML files. All four roles are installed by default after an explicit install; challenger and observer remain conditional in real delegation, with no claimed incremental benefit until tested.

## Provision tools without hidden contamination

Use a dedicated experiment account/container where feasible, with an explicitly provisioned CODEX_HOME and the required authenticated model/browser tools. The runner never reads/copies auth files and never changes approvals or uses an unrestricted sandbox flag. It rejects unregistered user role/Skill/AGENTS overrides in that home, hashes non-secret config and reports other global-instruction contamination for inspection. Profile isolation is not an independent OS sandbox. Each participant receives a fresh Git workspace and independent browser context; serialize native desktop control. Confirm actual model availability and native child role discovery with a separately labeled smoke run before the campaign.

If the execution host requires preserving its existing `CODEX_HOME`, use the explicit inherited-profile mode consistently across paired conditions. It leaves the environment unchanged, ignores user config and stores attempt-local runtime state/logs, while retaining a record of known inherited instruction identities and unresolved host/tool contamination. This is a controlled use of the existing authenticated environment, not an empty dedicated profile. Review actual tool and instruction inheritance before drawing causal conclusions.

## Execute and retain failures

The runner invokes `codex exec --json` in a fresh session; there is no simulated participant fallback. Capture raw event JSONL, stderr, command/model/tool conditions, start/end, return code and reported usage. A missing executable produces `blocked_not_run` with zero executions. Failed, timed-out and malformed-event attempts remain failures. Never overwrite an attempt or relabel fixed output as the original trial. A new attempt is separately registered and included in analysis.

Runs are ephemeral at the CLI-session layer. Register installed role paths and descriptions through the native per-invocation configuration, while keeping the condition's narrower call boundary in its task instructions. Native catalog exposure and actual selection are separate observations. A host interface that cannot select custom roles does not satisfy a specialist condition, even if a generic child can read a role file. Preserve that incompatibility as a failed or excluded attempt, and keep a supported main-model/tool interface constant across the relevant paired runs.

The main Agent must genuinely inspect consequential visual evidence and the assembled product. Audit actual child session IDs, tools and viewing behavior from native logs: role files alone do not establish delegation. Do not infer eye-level visual inspection from saved screenshots. Retain source/demo/trial/integrated identities and meaningful time evidence. Sparse frames cannot prove natural-speed smoothness; tool latency is not application latency.
