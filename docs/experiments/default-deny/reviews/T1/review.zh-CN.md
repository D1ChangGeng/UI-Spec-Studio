# T1 / Index 集合工作区：独立产品检查

日期：2026-10-30。对象：`sample-17`（4411）与 `sample-42`（4412）。依据：本目录的 REVIEW.md、REQUIREMENTS.md。本次只运行、观察和操作产品，没有修改两套应用的源文件，也没有查阅开发者自评、制作方法说明或其他工作区。

## 结论

**两套应用都实际完成了“找集合—保存—阅读—返回”的核心闭环，也在模拟存储写入失败时给出了可用、诚实、可恢复的结果。** 没有在已执行的路径中发现会阻断核心任务的稳定故障。

`sample-42` 的编辑式视觉表达更完整：细长衬线标题、细分隔线、节制的暖色、较轻的控件、柔和卡面光感，以及详情侧栏和正文的关系相互呼应。它的主要代价是列表信息偏小：正文实测 12px，分类 9px，Save 11px；在 390px 窄屏仍如此，阅读概览比大标题费力。

`sample-17` 的列表正文与操作更容易读：正文 16px，筛选 16px，Save 14px，明确的选中底色与边框也更容易辨认。它的整体表达较平，卡片主要靠细边缘响应指针，详情右侧的保存说明在主文旁显得空而松散。它对示例参考数量的解释更明确，尤其不会让读者误以为详情内一定有 14 条可打开的参考链接。

因此，不宜把“更鲜明的排版”当成全部产品质量，也不宜因两者功能相似就忽略可见品质差异：**42 在视觉组织与表达连贯性上更强；17 在列表信息的默认可读性上更强。两者核心行为均已被实测，而具体研究资料的深度仍有限。**

## 实际检查范围与运行修正

使用随评审提供的 Chromium，通过 Playwright 驱动真实链接、输入框、筛选按钮、保存按钮、返回控件与键盘。检查了 1440×900 桌面、390×844 窄屏，并另建了支持触摸的窄屏浏览器上下文。截图既有完整页面，也有实际视口；完整页面图的高度超过 900 / 844，并不表示改变了规定视口。所有用于判断构图的关键截图均通过图像工具实际打开查看。

首次按说明同时执行两个 Vite 开发服务器，两者出现空白页；浏览器资源记录显示 `lucide-react`、`motion_react`、`next-themes` 的预优化资源返回 **504 Outdated Optimize Dep**。随后仅把 Vite 的运行缓存分别放入 `review-output/runtime-cache-17` 与 `runtime-cache-42`，保留应用配置的其余部分，两个页面均恢复。这与共享依赖优化缓存冲突相符，**不把该环境冲突记为某一应用的产品缺陷**。初始空白、HTTP 状态和恢复后的画面都保留在证据中。

可复现的独立缓存启动方式：

```bash
bash review-output/start-review-server.sh 17
bash review-output/start-review-server.sh 42
```

两条命令分别在终端运行。浏览器脚本的执行方式为：

```bash
FONTCONFIG_FILE=/tmp/ui-spec-fonts/fonts.conf /tmp/ui-spec-study-venv/bin/python review-output/inspect_initial.py
FONTCONFIG_FILE=/tmp/ui-spec-fonts/fonts.conf /tmp/ui-spec-study-venv/bin/python review-output/run_interactions.py
FONTCONFIG_FILE=/tmp/ui-spec-fonts/fonts.conf /tmp/ui-spec-study-venv/bin/python review-output/edge_checks.py
```

## 可见品质：构图、文字、材质与连续性

### 桌面集合页

两者都实现近黑石墨背景、温暖白字、暖色点缀、衬线展示字与无衬线说明字，并在 1440px 下以三列卡片组织六项内容。卡片底部的参考数与 Save 操作对齐，长标题所在第二行增加高度，不挤压说明和操作。没有在所查画面中看到裁切、文字碰撞或卡片叠压。

17 的首屏以 56px 斜体大标题、20px 引言、横向大搜索框和右侧明显的分段筛选构成。正文尺寸较宽容，信息密度也更直白。42 的主标题约 83.5px，字形更细长；统计采用大号 06 配小字说明，搜索放在右侧，分隔线更细、控件更安静。42 从 logo、页头、卡片标题到页脚都延续同一套字形和暖色节奏，视觉身份更具体。

实际字体观察：42 的浏览器 FontFaceSet 记录 Instrument Serif 与 DM Sans 已加载；17 没有注册网页字体，计算样式虽然声明了 Playfair Display/Georgia 等回退序列，本次不能据此认定 Playfair Display 已加载。比较依据是实际呈现的字形，而非声明的字体名。

### 窄屏与长标题

390×844 下，两者都改为单列、重排搜索和筛选，最长标题完整显示，详情也未出现可见横向溢出。17 首屏使用 40px 展示标题、20px 引言、16px 卡片说明，读字轻松，但首张卡的底部操作需要略向下滚动才完整出现。42 展示标题 59px，卡片更像编辑式目录，首张卡可以较完整地出现在首屏；同时，12px 描述和 9–11px 的分类、数量、操作文字偏小，尤其与醒目的大标题对比明显。

17 的长详情标题在窄屏分成多行，正文更大、页面更长；底部又接保存说明卡，形成较松散的尾部。42 把桌面左侧元信息移到窄屏标题之前，并维持标题、引言、段落和结尾短句的明确顺序。这个结构保持了编辑式表达，但在长标题前占用了一段屏幕高度，用户需要滚动才能进入正文。

证据：[17 桌面](17-desktop-initial.png)、[42 桌面](42-desktop-initial.png)、[17 窄屏视口](17-mobile-viewport.png)、[42 窄屏视口](42-mobile-viewport.png)、[17 长详情窄屏](17-long-detail-mobile.png)、[42 长详情窄屏](42-long-detail-mobile.png)。

### 指针、焦点与减少动态效果

正常设置下，两者的卡片都随指针位置改变暖色边缘；17 的变化主要在细边框，卡片内部保持平静；42 同时出现较柔和的暖色表面光感，仍可读。42 的键盘焦点围绕整张卡片，17 围绕标题链接，两者均能明确指出当前目标。

在 `prefers-reduced-motion: reduce` 设置下，两种不同指针位置生成的 PNG 文件分别完全一致；运行时梯度也说明可见动态响应被抑制。17 的不可见光层仍更新坐标，但透明度为 0，不能把这种内部更新当成用户看见的运动。42 的相应坐标重置且保持不变。这个检查只证明采样状态与减少动态效果的响应，**不证明自然速度下动画流畅，也没有根据少量帧认证连续播放品质**。

证据：[指针图像一致性记录](pointer-image-comparison.json)、`17/42-no-preference-left/right.png`、`17/42-reduce-left/right.png`、[17 焦点](17-keyboard-card-focus.png)、[42 焦点](42-keyboard-card-focus.png)。

## 仍值得改进的具体问题

1. **42 的列表文字过小。** 桌面与窄屏的描述均为 12px，分类 9px，Save 11px。实际窄屏截图中，标题非常醒目而辅助信息需要更仔细辨认。触控 Save 高度达到 44px，问题主要在文字尺度而非没有触控面积。17 以更大的正文与控件文字降低了这一负担。
2. **17 的保存结果反馈与动作位置距离较远。** 一般反馈位于列表后的段落。重试成功后，在顶部视口中看到的是警告消失与状态保留，具体“已写入浏览器”的文字在页面更下方；42 的通知更直接出现在当前视口。17 的失败警告本身醒目且可操作，不能把此项表述为缺少错误处理。
3. **两套详情的研究内容深度有限。** 所检查长标题详情有三段通用研究说明，但没有具体参考链接。17 明确写明参考数来自样例数据、单独链接未提供；42 显示 14 references 并在页脚标注 sample collections，但在详情正文没有同样直接的数量解释。需求要求可读详情，两者已达到这个最低结果；作为长期研究工具，参考数量与可访问资料仍有距离。
4. **17 的详情空间组织较松。** 桌面主文右侧只有一张短保存说明，之后留出很大空区；窄屏时这张说明落在返回动作之后，又拉长结尾。42 的元信息侧栏与正文互相补充，在详情上的组织更连贯。

以上是基于实际画面与操作的产品判断，不涉及采用何种来源、库或制作方法的优劣。

## 不确定性与边界

- 页面可见内容均为英语，未发现主题或语言切换控件；测试了系统 light scheme，产品仍保持暗色表达。本需求本来就指定暗色身份，没有把不存在的明暗切换记为失败。
- 输入包含中文的无结果查询只验证输入与布局稳定，不代表中文内容数据、多语排版或翻译已支持。
- 已验证当前浏览器中的刷新持久化，没有测试跨设备同步、跨浏览器、跨标签冲突、清除站点数据或真实磁盘满。存储失败是明确的浏览器写入异常注入。
- 只抽查了代表性的长标题详情与另一条进入/后退路径，没有逐字核验全部集合正文，也未检查外部研究资料的真实性。
- 未运行完整屏幕阅读器测试或自动无障碍认证；键盘与焦点结果不能代替全面无障碍合规结论。
- 没有录制并观看自然速度完整视频；关于动画，只报告实际采样与设置变化，不声称帧率、流畅度或长期性能已验证。
