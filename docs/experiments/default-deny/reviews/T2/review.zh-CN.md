# Fieldnote 两个候选的独立产品检查

## 结论

两者均保留了可用的笔记任务：编辑、即时预览、浏览器本地保存、保存等待、失败提示、重试、已存笔记查看、返回编辑、语言与主题切换都在本次实际操作中成立。保存等待期间继续输入时，两者都正确区分“已经提交保存的旧版本”和“尚未保存的新修改”。测试没有发现失败时错误宣告成功或覆盖已有保存内容的情况。

本次可见差异主要在阅读质量、构图与交互覆盖。sample-17 的纸色背景、较大的标题、细边卡面、编号与背面底部横线形成更一致的研究手记表达；卡内文字在实际截图中较清楚，桌面长笔记预览空间也较大。sample-42 的整体排版更紧凑，并实际提供了卡片直接键盘操作和拖动翻面，但卡片内文字相对同屏编辑框明显偏软，此现象在桌面、手机、浅色与暗色都可见。不能把这些静态差异当作对自然速度运动体验的全面排序。

两者的普通翻面、约一秒内七次按钮反转都保留同一张卡片的区域与最终状态；中间截图确实出现卡边、明暗变化与地面投影。连续 rAF 记录支持角度没有每次重置到正面的判断。录像与逐帧证据已保存，但本检查未以自然速度观看完整影片，因此不认证“自然播放流畅”或某一个弹性节奏更好。

## 范围、环境与证据性质

仅在本 T2 工作区内检查 `sample-17` 与 `sample-42`。读取了 REVIEW.md、REQUIREMENTS.md、候选端口和启动用 package.json，没有读取来源方法说明、其他工作区或开发者自评，也没有编辑两份应用。两个应用按指定方式在 4413、4414 运行。

实际使用指定 Chromium、Playwright 环境和 FONTCONFIG_FILE，桌面视口 1440×900、手机视口 390×844，设备像素比 1。所有保存、重试、翻面、主题、语言、返回、导航、暂停装饰操作均通过实际控件执行；故障测试只在页面运行时把 Storage.setItem 暂时替换成抛出 QuotaExceededError，随后恢复，产品文件未改动。没有通过改 DOM 替代产品动作。

证据包括 PNG、浏览器状态 JSON、实际运行脚本与两段约 6.3 秒的 1440×900、25 fps WebM。关键截图已用图像查看工具逐张检查；录像本体未在自然速度下观看。`run_review.py` 首次因录像工具默认 ffmpeg 路径不对而中止，之后使用指定浏览器目录中的已有 ffmpeg 完成独立补录。另一次脚本在超限禁用的保存按钮上等待超时，修正检查方式后完整重跑；这是测试脚本对已正确禁用按钮的处理问题，不列为应用故障。

## 任务行为：两者均实测成立的部分

| 检查 | 实际输入与操作 | sample-17 | sample-42 |
|---|---|---|---|
| 长笔记 | 432 字，中英混排、8 段换行、时间、ΔT、°C、结尾标记 | 预览同步，长内容可滚动，保存后可查看 | 同样成立 |
| 保存等待 | 点击保存后约 180ms 抓取 | 显示 Saving in this browser，保存禁用，文本框仍可编辑 | 同样成立 |
| 保存完成 | 继续等待超过约 900ms 演示延迟 | 显示本浏览器保存成功，localStorage 中有对应文本 | 同样成立 |
| 等待中继续修改 | 提交 A，约 170ms 后输入 B | 本地只保存 A；B 留在编辑器；提示需再次保存新修改 | 同样成立 |
| 已存笔记与草稿 | 在 B 尚未保存时查看已存笔记，再返回 | 已存区显示 A，返回后仍是 B；返回焦点在编辑框 | 同样成立 |
| 本地写失败 | 先存 432 字旧笔记，改为 352 字草稿，注入写失败后保存 | 明确失败；352 字保留；已有 localStorage 内容不变 | 同样成立 |
| 重试 | 解除故障，点击 Try saving again | 保存 352 字草稿成功；刷新后可恢复 | 同样成立 |
| 超限 | 输入 690 字 | 显示 690/600 并要求缩短，保存禁用 | 同样成立 |
| 返回编辑 | 卡片背面点击返回 | 翻回正面，焦点进入 note-text | 同样成立 |
| 键盘 | Tab 顺序、翻面按钮 Enter | 隐藏背面控件未进入正面 Tab 序列，按钮可翻面 | 同样成立；另有卡片自身的焦点位置 |
| 语言与主题 | 英文浅色、中文暗色，两个尺寸、两面 | 关键任务文案、失败/未保存等状态能切换 | 同样成立；卡片键盘/拖动说明也有中文 |
| 页面宽度 | 读取根元素 scrollWidth | 桌面1440、手机390，无横向溢出 | 同样成立 |

两者都没有把一般未保存草稿持久化到刷新之后：输入 432 字但不保存，刷新恢复默认 80 字文本。这是实际边界；需求明确要求失败时保留草稿，本次失败时在当前页面确实保留，不能把“未实现自动草稿持久化”擅自解释为同一项检查失败。未专门测试在失败后直接刷新。

sample-42 的额外输入方式另有实际验证：卡片获焦后 Enter 翻至背面、Space 翻回正面；在卡片图形区域水平拖动约 190px 后翻至背面。该能力不是仅凭界面声明推定。sample-17 依靠外置翻面按钮，卡片本身不在初始 Tab 序列；这并不妨碍本次要求的按钮翻转任务。

## 可见构图与阅读质量

### sample-17

1440×900 下，主标题为 53px，卡片占 512.5×392px，编辑框为 483.48×214px。主标题、卡片左缘与页面开头建立明确的纵向关系；右侧的“02”与研究笔记标题呼应卡片中的编号。纸色背景、米白表面、橄榄色图形、深绿文字与棕橙细节形成较完整的材料关系。翻至背面时，标题、正文、分隔线、当前笔记说明与返回入口仍属于同一边界明确的卡片。

可见优势是卡内阅读更清楚、正文行距更舒展。桌面背面预览容器 clientHeight 约 197px，手机约 108px；长笔记在桌面可见较多行。390×844 下卡片缩为 350×260px，主标题 32px，编辑框仍保持 16px 字号、145px 高；保存按钮从 y≈781 开始，仍能在首屏内完整出现。顶部语言与主题控件没有互相挤压。

需要改进的是手机背面仍只能一次看约四行长正文，超过区域的内容边缘被截断，滚动能力主要依赖用户尝试与聚焦；默认截图里没有明显的“后面仍有内容”提示。手机翻面按钮文字降到 12px，底部辅助文字也偏细小。长内容并未破坏卡片尺寸或返回入口，但阅读需要较多局部滚动。

### sample-42

1440×900 下主标题为 36px，卡片 461.06×360px，编辑框 426.94×184px。白底、圆角卡面、绿色主按钮和较紧凑的文字构成清楚的编辑工具；右侧输入与保存逻辑容易理解。卡片背面的返回链接是清楚的文字动作，直接键盘/拖动的翻面能力得到验证。

主要视觉问题是卡片中文字有明显软化：同屏右侧编辑框与页面主标题清楚，卡内标题、正文和小标签更像被整体缩放后的字形。此观察来自原尺寸截图，未仅依据缩小拼图；暗色中文和手机英文截图中同样出现。无法仅凭浏览器观测确定根因，也不应将其归因于未审查的实现方法。

长笔记预览桌面只有约 150px，手机约 101px，文字较拥挤且更容易在下一行中间截断。390×844 下卡片为 358×280px，编辑框只有 110px 高、14px 字号；大卡片和较长的卡片后留白，让研究笔记编辑区从 y≈586 才开始，文本框 y≈631。与 sample-17 的 y≈597、145px 高文本框相比，手机上给实际写作的可视空间更少；两者保存按钮却都在 y≈780 附近。卡片下方较浓的投影与大块白色间隔使“悬浮卡片”感觉更强，纸张手记的材料暗示较弱。这是可见表达差异，不是保存功能缺陷。

## 连续状态与运动的可验证范围

两者在一次正反翻面中都保留同一固定布局区域，结束后中心位置不变。sample-17 桌面卡片区域中心为 (436.25, 464.36)，sample-42 为 (470.53, 432.59)。中间截图实际呈现侧面厚度、倾斜透视、卡面光带与变化的投影，而不是只切换两张静止图片。返回后表单没有重新排版，长笔记不撑大卡片。

第一次正常翻转和四个反转中间截图都已经查看。补充记录在不穿插截图的条件下，以真实翻面按钮在约 1 秒内点击七次，分别取得 126、128 个 rAF 样本，采样间隔最大约 16.8ms。角度在反转之间继续从当前值变化，没有观察到每次跳回 0° 再播放；最后都停在背面，符合奇数次操作。两者都存在小幅越过 180° 后回落的采样结果。JSON 保存的是计算样式/几何的连续观测，不能证明最终显示链路的实际帧率；headless 环境也不能代表所有真实设备。

减少动态效果下，静止背面、正文、返回编辑及保存状态仍可操作，装饰显示暂停。实际还检查了运行时切换该偏好的组合状态，发现长正文滚动后的布局状态需单独说明。

### 组合状态异常与复核

在主测试较长的自动操作序列中，两者的 `mobile-reduced-back.png` 均出现卡片内标题移出顶部、下方多出空白的状态。此前同一序列还包含桌面到手机尺寸切换、长正文 End/PageDown 和定位器点击返回。不能忽略这两张实际截图，也不能据此直接断言减少动态效果本身破坏布局。

为区分产品动作与自动滚动影响，随后在全新的 390×844 页面复测：输入同样长笔记，翻面，聚焦正文并按 End，使用可见位置的真实鼠标坐标点击返回，切换减少动态效果，再用鼠标坐标翻面。两者均保持标题、正文区与返回入口的正常位置；正文滚到底部后结尾标记可见，卡面祖先的 scrollTop 为 0。关闭减少动态效果后仍正常。对照 `sample-*-reduced-repro-reduced-back.png` 与 `sample-*-reduced-repro.json` 可以复核。

因此，本次把原自动序列中的异常列为“组合状态/自动滚动影响尚未隔离”，而不是已确认的减少动态效果缺陷。经过可见坐标点击复核的基本减少动态效果路径成立；完整历史序列的根因未在工作时限内确定。

## 尚未覆盖的边界

没有真实手机触控/软键盘、屏幕阅读器语音、浏览器缩放、跨浏览器、GPU/低性能设备、长时间稳定性或真实配额耗尽环境的验证。故障来自受控 Storage.setItem 异常，能验证错误处理与重试路径，但不覆盖所有浏览器权限策略。没有研究实现来源、授权材料整合或构建路线；这些不属于本次产品检查结论。截图与数据支持所述具体行为，不能升级为完整可访问性、所有设备兼容性或自然速度运动质量认证。
