# T3 独立产品检查：Fieldnote 的字体、标识与并发编辑

## 结论

两套应用都实现了本次最容易直接验证的要求：品牌显示为 **Fieldnote**，中英文、明暗主题下的标题输入框与正文占位文字都是 **14px**，实际输入都是 **15px**，两套对应控件的尺寸一致。正常保存、必填错误、模拟写入失败与重试，以及「保留本页草稿」「采用另一版本」两条基本冲突路径都实际运行成功。未处理的冲突草稿在本标签页刷新后也都能恢复。

并发状态的表达质量存在具体差别。**sample-17 的比较内容会随远端连续保存即时更新，并把较早版本留在历史区；sample-42 会先显示“又有更新”的通知，但正文仍是前一个版本，直到用户第一次点击选择才刷新比较内容，第二次点击才完成选择。** sample-42 有防止直接采用过期版本的保护，因此不能把这个现象说成已经丢失数据；但画面与通知不一致、选择动作临时变成刷新动作，增加了理解成本。

视觉上，sample-42 的版本标题条、等宽比较区和集中排列的选择按钮更紧凑，手机首屏更容易同时看到双方。sample-17 把按钮直接放在各自版本内，归属清楚，但长标题与长正文会把另一版本推到手机首屏之外，需要分别滚动正文与整个弹窗。这两种组织各有收益；本次不据外观紧凑程度推定功能优劣。

## 检查方式与范围

- 工作范围仅为本 `T3/`；读取 `REVIEW.md`、`REQUIREMENTS.md`、两套的端口、启动元数据和页面入口，没有读取其他工作区、开发者自评、构建方法说明或资源来源评估。没有修改任何应用文件。
- 按指定端口用静态服务器运行：sample-17 为 `127.0.0.1:4415`，sample-42 为 `127.0.0.1:4416`。浏览器为提供的 Chromium，使用提供的字体配置。
- 每套均在 **1440×900**、**390×844** 打开。空态实际切换中文/英文与浅色/深色，共 **16 个候选×尺寸×语言×主题组合**。这是运行时 CSS 像素视口，没有把全页截图高度误当成视口高度。
- 使用页面上的语言、主题、保存、比较、版本选择、稍后处理、模拟失败、延迟保存、长标题和清除数据控件；通过真实第二标签页保存触发 `storage` 冲突。没有人工派发伪造冲突事件。
- 中午 12:04 UTC 开始，本报告与证据在 15 分钟窗口内完成。截图实际通过 `view_image` 打开检查；空态全部组合另制成两张对照图检查。
- `capture_review.py` 是基础流程；`probe_conflicts.py` 复核连续更新、选择、刷新和删除；`probe_slow_race.py` 在全新上下文单独检查保存竞争；`probe_mobile_scroll.py` 检查真实滚轮可达性，并补桌面英文深色失败/恢复。

### 运行时尺寸和内容边界

两套全部空态的页面 `scrollWidth` 都等于视口宽度：桌面 1440、手机 390，没有测到横向页面溢出。中文空态全页高度为桌面 941px、手机 1153px；英文因为标题和说明换行，分别为 1027px、1274px。这是需要纵向滚动的布局，不是内容被丢掉。

长内容基础用例实际输入了 121 字符标题和 2880 字符正文，包含中文、英文、换行、长 URL 与无空格片段。比较区能换行，长正文可滚动，没有观察到长 URL 撑宽整个页面。输入框本身维持单行，长标题在焦点位置横向显示局部，这是其现有控件行为；比较窗能展示折行的完整标题。

没有变更前的运行版或基准截图，所以这里只能确认当前两套的字号关系和尺寸一致，不能历史性认证“相对于原版绝对没有变化”。

### 连续更新的关键复现

1. A 标签页保存基础笔记，然后在 A 输入未保存草稿 `LOCAL L1`。
2. B 保存 `REMOTE B1`；在 A 打开比较。
3. 比较窗保持打开时，B 再保存 `REMOTE B2`。
4. 等待 700ms，并在桌面和手机重新截图。
5. 点击采用另一版本，记录选择前后编辑值、弹窗开闭和焦点，再刷新确认保存值。

sample-17 在第 4 步已展示 B2。sample-42 在第 4 步的侧栏是 B2，但比较正文还是 B1，上方已提示远端又更新。sample-42 的第一次点击没有关闭弹窗，也没有替换本页草稿，而是把正文更新成 B2；第二次才采用 B2。最终刷新读到 B2。证据为 `conflict-probes.json` 的 `b2_open`、`first_choose`、`second_choose` 和 `choice_reloaded`，对应截图见后文。

## 二、可见构图、文字与材质

### 共有的表现

主编辑器、最近保存区、顶部品牌与工具保持明确关系。桌面左编辑、右预览，细竖线分隔；手机按编辑器、最近保存、演示设置顺序堆叠。浅色以接近纸白的底色、深绿按钮与细边框为主；深色换成低亮度绿黑背景、较浅文字与浅绿主按钮。两套的主页面构图、密度、边界与留白高度相近。

中文大标题相对紧凑，英文标题采用衬线字并换行，英文页面整体更长。14px 占位提示在视觉上退到次一级，输入内容保持清晰；没有看到为了缩小提示而同时缩小输入内容或压缩控件的迹象。

两套标识均能在当前品牌位置形成清楚的色块并适应两主题。sample-17 的纸页外形更明确，内部 F 与细线细节较密；sample-42 的 F 更直接，折页意象主要由右上角的小三角表达。这里评价的是实际看见的辨识与造型关系，**没有检查创作来源，也不认证原创性**。

### sample-17 比较窗口

桌面两个版本各为独立卡片，版本名、保存状态、正文、对应动作和后果说明在同一卡片内，按钮归属直接。长标题全部留在卡片上方，正文区域独立滚动；当前版本与历史版本区别可读。两边动作都使用实心主色，视觉权重对等。

手机变成竖排，长标题本身占用较多高度。长内容截图中，首屏几乎只展示本地卡片，远端卡片及其动作需继续滚动。实际将鼠标放在正文内滚动时，只有正文滚动；移到卡片侧边滚动整个弹窗后，能看到远端内容与“使用另一版本”。远端按钮从视口下方约 y=916 移到 y=615，随后选择成功。不存在已证实的不可达，但有两层滚动的操作负担，且首屏对双方不对称。

打开比较时焦点放到标题，有利于先读说明；中文浅色截图中标题出现大块黑色默认轮廓，与编辑器的绿色圆角焦点环不完全一致。完成选择后焦点回标题输入框，下一次 Tab 到正文，继续编辑路径连贯。

### sample-42 比较窗口

版本名与保存状态放在浅色/深色的标题条中，正文单独滚动；动作集中于底部，两个保留选项并列，“稍后决定”另列。桌面卡片更齐整，手机仍能同时看到双方卡片及选择按钮。长标题会占据本地滚动区的大部分，正文需在该区内继续阅读，但远端短版本不会同时被推离首屏。

冲突到达时的横幅与现有色系、细边框和按钮语言一致，先说明草稿仍在，再给比较入口，没有强行打断正在输入的焦点。底部全局动作比 sample-17 的卡片内动作更节省纵向空间，代价是动作与各自内容的物理距离更远。

首次连续更新后的通知能被看到，但其下正文并没有同时更新，导致这套本来清晰的分区表达失去同步。修复这一点比继续调整阴影或圆角更有实际价值。

## 三、需要处理的具体问题与权衡

### 1. sample-42：连续更新时，通知与正在比较的文本不一致

这是已复现的状态表达缺陷。通知要求用户检查下面的新版本，下面却仍是 B1。用户点击“采用另一版本”后，按钮实际先执行刷新，必须再点击一次。存在保护逻辑，最终没有错用 B1；问题在于当前版本标识、通知与动作语义不连续。可优先让最新版本与通知同步更新，或明确标示当前比较已过期并提供单独刷新步骤。

证据：`42-desktop-conflict-continuous.png`、`42-probe-b2-mobile-en-dark.png`、`42-probe-first-choose.png`、`conflict-probes.json`。

### 2. sample-42：完成版本选择后焦点停留于隐藏弹窗按钮

采用版本后，运行时 `document.activeElement.id` 仍为 `use-other`，但该元素已不可见；下一次实际按 Tab 跳到页面的 `skip` 链接。保留草稿的基础流程也记录到隐藏的 `keep-mine` 焦点。选择结束后的键盘继续编辑路径因此中断。sample-17 同一操作返回 `note-title`，下一次 Tab 到 `note-body`。这是键盘连续性问题，不是仅凭截图猜测。

证据：`conflict-probes.json` 的 `second_choose`、`tab_after_choice`，以及 `observations.json` 的 `keep_local`。

### 3. sample-17：手机长内容下两份版本不能同屏充分比较

本地长标题、正文预览和卡片内动作使第一张卡片过高，另一版本在首屏下方。正文和弹窗均可滚动，实际验证可以到达远端并成功采用，所以不应标记为功能阻断。不过用户很容易先在本地正文内滚动而迟迟看不到远端，比较任务的来回定位成本较高。

证据：`17-mobile-conflict-long.png`、`17-mobile-comparison-scrolled.png`、`17-mobile-comparison-outer-scrolled.png`、`mobile-scroll.json`。

### 4. 两套的删除冲突说明还有轻微语义错位

远端已清除笔记时，卡片确实说明“已清除”和采用后清空当前编辑器，但弹窗顶部仍采用“新保存版本/另一标签页保存了这份笔记”的通用措辞。关键后果是清楚的，现有操作也能保留草稿；标题说明可以更准确地区分更新与删除。

## 四、来源引用支持综合笔记的未来视图

实际浏览界面中没有找到引用列表、引用标识、支持关系或对应关系图的入口，也没有把评审输入中的 URL 或引文样式文字自动当作已验证关系。这与需求所说“现有记录只有标题和自由文本”没有直接矛盾。

这项需求要求先调查表达方式并说明数据缺口，不等于必须在当前产品中伪造已有的引用关系。本次按独立产品检查的限制，没有查阅开发者研究说明或自评文件，因此 **不判断其研究是否充分，也不把没有图形入口直接记为实现失败**。本次能确认的边界是：当前浏览器可操作结果没有可验证的引文身份或支持关系；未来方案与证据来源的质量需另行查看其研究交付物。

## 六、未验证的范围

1. 没有完整验证所有状态与语言、主题、尺寸的笛卡尔积。空态覆盖完整 16 组合；冲突重点为中文浅色与英文深色的两尺寸；失败/恢复重点为手机中文浅色与桌面英文深色。
2. 没有使用真实手机、触摸手势、软键盘、屏幕阅读器、浏览器缩放、其他浏览器或系统高对比度设置。键盘结论限于实际跑过的 Tab、焦点恢复与可见性。
3. 没有对浏览器关闭后的会话恢复、浏览器崩溃、配额耗尽或真实磁盘写入异常作承诺。失败检查使用产品提供的模拟失败控件。
4. 没有成功录制视频：环境缺少 Playwright 所需的 ffmpeg。记录了保存中、稍后、完成等连续状态截图和真实事件次序，**不据稀疏帧认证自然速度播放、动画节奏或无卡顿**。
5. 没有执行来源溯源、图形原创性审查、完整网络审计或研究文档评审。存储确认来自隔离浏览器中实际读回的本地记录；不把界面的“不外发”文案当作完整网络审计结果。
6. 两套基础流程都未捕获页面脚本错误；这不等同于对所有边界输入和未来变化的可靠性保证。
