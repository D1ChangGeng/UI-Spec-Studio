# Observable execution — actual study results

**The clearest observed benefit is earlier, more explicit presentation of actual
design results. This study does not establish a general final-UI quality advantage
for the full enhancement.** All three methods perform real resource adoption and
corrective work. Independent review finds meaningful tradeoffs in T1, an actual
intermediate-state keyboard problem in A/C in T2, and identical applications in T3.
The confirmed C problem receives a separate continuation; its repair is not used
to rewrite the original comparison.

## What actually ran

Nine isolated Agent executions used three task families and three complete
instruction conditions. Each began from the same application bytes within its
family. The frozen source and all original messages remain available.

| Condition | Method supplied | What the comparison means |
|---|---|---|
| A / s8 | Full v1.17.0 plus common host communication requirements | Strong existing design/verification baseline; not silence or no research |
| B / v5 | A plus event-driven visibility guidance | Early actual-result presentation and useful causal expression, retaining baseline methods |
| C / k2 | Full frozen v1.18.0 candidate, matching the released 37 runtime files | Visibility further connected to evidence roles, adoption, retained qualities, correction and reinspection |

| Task | Responsibility | Nominal maximum window per cell |
|---|---|---:|
| T1 — Index | Editorial collection workbench, mature card light, search/save/read/return | 24 minutes |
| T2 — Fieldnote | Same physical card through continuous front/back interaction, draft/save/retry | 18 minutes |
| T3 — placeholder hierarchy | Accepted form, hints one step smaller with entered text and geometry preserved | 10 minutes |

These are instructed ceilings, not measured equal effort. The
[execution spans](execution-spans.json) record first-to-final outward-message times,
not precise launch-to-stop time or token cost. T1 uses the same supplied MIT source
candidates and dependency lock; T2/T3 use existing fixtures. All conditions already
include adaptive SPEC granularity. That mechanism is held common, not separately
ablated here.

The [protocol](PROTOCOL.md), [registration](registration.json), exact runtime/input
archives and [replay guide](REPLAY.md) describe the setup. Registration was completed
after T3 began; the original collection error and its evidence-backed correction
remain visible. This is not a fully preregistered or statistically replicated study.

## Three outcomes, kept separate

| Outcome | Observed result | Limit |
|---|---|---|
| User observability | In recorded deliberate messages, B/C show actual T1/T2 interfaces before delivery. C/T1 first identifies a local source trial, then the integrated product. A mainly describes these results before its final image or links. | Does not establish that a human viewed the output, nor cover every tool-result surface exposed by the host |
| Actual design behavior | All three adopt the MagicCard mechanism and make specific later repairs. C's palette correction, B's transition/scroll restoration and A's density/material/return-action refinements have source evidence. | Does not establish that disclosure caused correction or that C uniquely closes the loop |
| Final UI quality | T1 has different useful strengths without a supported overall ordering. T2-B avoids one actual mid-turn focus problem found in A/C. T3 final application bytes are identical. | No general superiority, population-level effect or full natural-speed motion judgment follows |

The [independent process audit](reviews/process/review.md) reconstructs actual
adoption and adjacent source changes. It independently verifies all 46 original
message source packages, nine initial/final snapshots and their received relays.
This is source and communication integrity, not a design-quality score.

## T1 — earlier visibility, with strong work in every condition

C's message 003 presents a clearly identified local candidate trial; message 004
then presents the integrated workbench while noting the green-biased surface.
Contemporary source snapshots show the shared background changing from `#111412`
to `#121313`. B's message 003 exposes a working first product before its detail
positioning fix; subsequent source adds restoration after the view transition,
relative card anchoring and a persistent error notice. A also performs real source
comparison and later compresses the desktop composition and corrects storage
language. Its absence of an early embedded image is not an absence of design work.

The independent reviewer receives R7/T4/M2 without method labels or participant
prose. All three perform actual search, saved filtering, persistence, detail entry,
keyboard navigation, recovery and return. In the stable mobile test, list positions
return exactly and the three reading positions all return from 600 to 600px.

| Original condition / anonymous product | Observed strength | Observed tradeoff or gap |
|---|---|---|
| A / T4 | Desktop cards begin around y=335; all six almost fit the 900px viewport | Mobile detail save status relies on an icon, despite a usable accessible name |
| B / R7 | Compact mobile titles; an actually downloaded JSON copy supports storage failure | Mobile detail hides its update date when the desktop side column disappears |
| C / M2 | Persistent local-browser boundary and mobile Saved text | Desktop cards begin around y=437, requiring more scrolling to inspect the second row |

The reviewer sees restrained pointer-responsive light in all three and does not
find enough evidence for a material-quality winner. See the
[original T1 review](reviews/T1/review.md) and [actual gallery](GALLERY.md).
The initial R7 white screen was diagnosed as shared Vite-cache 504 output; isolated
review caches resolve it without changing source. Failed observations and the
diagnosis remain available rather than being charged to the product.

## T2 — useful early results still miss a temporal relationship

B/C show first integrated results before final delivery. All three make real
changes to the card's type, surface, spacing or behavior and exercise actual native
localStorage quota exhaustion, retained drafts and retry. Their different assertion
counts are not comparable quality measures; some final changes receive targeted
checks rather than a whole-suite rerun.

Independent actual operation finds a consequential difference during rotation.
In A/C, the target face immediately drives `aria-hidden` and `inert`. Early in a
flip, Shift+Tab can therefore enter the back-side note while the card still faces
front. B updates semantic exposure from the actual transform and avoids that
particular case under the same operation. A/C's settled checks and target
`data-face` values had not established the intermediate relationship.

This is a concrete counterexample to treating more visible execution or a larger
test count as sufficient assurance. It does not imply B wins every visual or
interaction dimension. The original endpoint stays frozen for all three.

A/P8 makes long-note overflow and the return-to-edit action easier to discover;
C/L6 and B/N3 fit the initial mobile save button within the tested viewport. B/N3
also has two isolated near-edge aria/matrix differences during reversal, limiting
any claim of strict frame synchronization. These are distinct tradeoffs, detailed
in the [independent T2 review](reviews/T2/review.md) and [gallery](GALLERY.md).

### Same-SPEC continuation, outside the comparison

The confirmed C gap is returned to a separate copy of the same Fieldnote increment
with the same frozen Skill. The original comparative application, source snapshots
and messages remain unchanged. This continuation receives additional review feedback
and time, so its eventual repair cannot be counted as the original condition's
result or a causal method advantage. The [continuation plan](continuation-plan.json)
preserves that boundary.

Independent old/new operation reproduces the invisible-focus failure in the
original at both specified sizes and confirms that the repair keeps early keyboard
focus on a visible control. It also checks departure from the visible back, one
midpoint reversal and reduced motion. Some isolated near-edge attribute windows
remain in the raw samples, without hidden-body focus in those observations; a
strict all-frame synchronization claim is unsupported. The [continuation report](CONTINUATION.md)
preserves the actual source change, participant checks, separate independent
findings and their limited scope. The runtime instructions are unchanged.

## T3 — proportionate work and the same product

The three final application file sets are byte-identical. The single placeholder
rule changes to 14px and full opacity of the existing muted color; entered text
stays 15px. Independent review first views all anonymous products, then uses exact
source equality to avoid redundant testing. Representative language/theme/viewport
and actual save/retry checks preserve geometry and behavior.

C embeds the actual focused-field image in its final message; A/B provide image
links. This presentation difference is not a UI-quality gain. No separate resource
comparison, new formal increment or design approval is introduced for the small
repair. See [T3 independent review](reviews/T3/review/review.md).

## A real media-provenance gap and its correction

The first recorder preserved exact text and source, but not each referenced media
file at emission. The audit finds a concrete overwrite: C/T1 message 004 points to
`desktop.png`, whose archived pixels now match the later background rather than
that message's earlier source. The study can establish the message, its image
reference, contemporary implementation and subsequent code change; it cannot call
the current generic image immutable evidence of the original early pixels.

The [instrumentation correction](INSTRUMENTATION.md) retains this limitation and
hardens the experiment-only recorder to preserve referenced local media independently.
It does not backfill original messages, alter the frozen common input recorder,
or add any installed Skill document, field, lifecycle or approval requirement.

## Limits that affect interpretation

- One execution per cell, no random repeated samples or statistical effect estimate.
- Additive instructions with different lengths, a common recording procedure and
  host progress rules; this is not a length-matched ablation.
- Rolling dispatch and shared machine load; T2-C finishes before A/B begin.
- Same host/model configuration requested, without a complete private execution
  trace proving every internal reading choice or cost.
- Received outward samples, not complete private-thread or permission logs. No
  evidence that a human approved the early results or supplied corrective feedback.
- Original media is fixed at archive time, with the specific early overwrite above;
  original source-time identity is stronger than early pixel identity.
- Headless desktop Chrome at specified CSS sizes, not real mobile hardware,
  cross-browser coverage, screen-reader sessions or comprehensive accessibility.
- Timed images, actual actions and measurements do not replace full natural-speed
  perceptual playback. No general smoothness or frame-rate conclusion is claimed.
- Supplied resource candidates and bounded tasks do not test all open-ended
  discovery, expressive contrast or whole-product situations.

The release therefore carries a supported execution principle and specific observed
visibility gains, together with real counterexamples and a correction path. It
does not claim that an output mechanism alone guarantees high-quality UI.
