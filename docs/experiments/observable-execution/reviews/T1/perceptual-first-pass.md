## T4

桌面有强烈的刊物索引感：较大的 Index 与 Collections，细横线、编号、稀疏暖色点缀，衬线标题配小号无衬线正文。内容与搜索在上半部很快进入，六张卡片在 900px 高视口几乎完整呈现，作为集合工具比较直接。卡片是克制的平面深色矩形，边界足够清楚；静态初始状态材质/光照较弱，需要操作后判断。短标题大而清楚；长标题缩小到三行，正文、底部元数据均有空间，没看到裁切。

手机页头、说明、搜索、筛选依次堆叠，第一张卡片起点约 y=451。第一张卡片文字留白合理，首屏还能看到第二张的题头和标题开端；没有横向溢出。卡片内容仍以文字为主，内间距与桌面一致。索引细字较小，主标题可读性明显更强。页面右侧有 15px 滚动条槽，实际内容区比视口窄一点。

## M2

桌面具有同样完整的深色编辑感，顶栏、主标题、工具栏、结果行分段较明显，暖色很节制。标题 “Collected thinking.” 与右侧大号 06 增强品牌感，代价是卡片下移到约 y=437，900px 视口只看到第一排和第二排上半。相较 T4，卡片内部的元数据分隔线更显物体轮廓，但尚未呈现明显空间材质；仍需指针操作后判断。标题、正文的对比层级清楚，整页显得安静而略松。

手机工具栏改变为先筛选再搜索，主标题保持一行，第一张卡片从约 y=458 开始，与 T4 接近。第一张高约 287px，正文底部留白比 T4 多，分隔线提供稳定锚点。顶部明确写 “Local to this browser”，可见的本地边界比 T4 的 “Local edition” 更直接。没有横向溢出，正文无需缩放。

## 暂时结论

T4 的桌面信息效率更高；M2 的分段节奏和卡片底部结构更明显。这不是总体排序。两者初始静态图同属稳健、克制的编辑式深色列表，尚无足够证据判断动态光照或完整使用质量。

## 首次详情阅读感知

已查看 T4、M2 的桌面/手机长标题详情顶部和手机阅读中段截图（detail-top、detail-reading）。两者长标题都没有裁切，手机为五行，正文宽度适合连续阅读。T4 桌面把分类、日期和保存放在左栏，正文较早开始；M2 的大标题区更宽且占高更多，保存操作在标题下方，更容易在阅读轴线上发现。手机两者布局都回归单栏。T4 手机保存变为无可见文字的小书签，M2 保留 “Saved” 文本；M2 操作状态更明确。两者字体样式与集合页一致，没有突然换成通用弹窗的感觉。

## 指针、键盘、减少动态效果的实看记录（组件源码阅读之前）

已查看三者 normal-pointer-left、normal-pointer-right、normal-keyboard-card，以及 reduce-pointer-left 原始截图。三者指针移至第一张卡片左上/右下时，暖色表面光与邻近边缘均随之改变，文字仍然是视觉主体；没有观察到明显过亮光斑或妨碍文字阅读。只查看了操作后静帧与样式坐标，不宣称观看了自然速度的连续动画或测了帧率。三者的光照感受很接近，不据细微色温差异排总名次。

键盘实际 Tab 到集合、Enter 打开、Shift+Tab 至返回链接再 Enter，三者都完成了这个路径，并在返回后聚焦原集合。R7 的暖色外侧双边界更醒目；T4 是明确的内侧矩形焦点框；M2 是较细的暖色边界，截图能看见但远观比另两者弱。这只是焦点显著程度的差异，不是键盘不可用。

reduce 模式的静帧中，R7 保留边界反馈并移除随指针的表面光；T4 保留固定在卡片上部的柔光；M2 则让全部卡片保留淡淡的静态层次。样式记录确认三者光源都不再跟随移动。三者都保留键盘操作，不能因为动效关闭就认为其未完成任务。

## 详情与存储收尾观察

R7 初次打开详情后约 100ms 的截图捕获了列表/详情重叠的转场中间帧。另存并查看了等待 600ms 的稳定详情，文字与布局正常；稳定后鼠标滚轮可滚至手机 y=600、桌面底部 y=487。故早期中间帧和过早 scrollTo 读数保留为测量局限，不当作稳定布局或滚动故障。未自然速度播放，不能由这些静帧判断转场的主观流畅程度。

R7 稳定手机详情保留大标题、摘要、带文字的保存、正文，字体与另两者不同：正文为无衬线，段落更紧凑。桌面侧栏的日期和参考数没有出现在手机顶部。T4/M2 手机有一行参考数及日期，信息保留更完整。R7 对缺少独立参考链接的本地样本范围有清楚说明。

三者写入失败截图都已查看（mobile-storage-failed），告知刷新/离开可能丢失、仍保留本次收藏；实际切到 Saved 也看到已保存集合。恢复原写入方法后，R7 的 Retry storage、T4 的 Retry saving、M2 的 Try saving again 均使保存可在重载后恢复。R7 的 Download copy 实际下载了完整当前收藏 JSON，包括 id、分类、标题、摘要、参考数、日期和正文。这是确实有用的附加恢复途径。

测量脚本最初有两处自身问题，均保留：赋值表达式返回函数导致 Playwright 调用了故障函数而在注入阶段报错；M2 重试按钮文案为 Try saving again，最初正则漏匹配，产生错误的“没有 retry”中间记录。后来分别改为显式返回 void 的注入函数、精确文案选择器完成核实；不能把这两次失败归给产品。
