# T1 独立产品审阅

## 结论

**R7、T4、M2 都交付了能够完成核心任务的本地集合工具。本次直接操作没有发现足以支持总体强行排序的质量差距。** 三者的搜索、收藏与取消收藏持久化、带查询和筛选返回、列表位置恢复、正文阅读位置恢复、键盘主路径、减少动态效果以及存储失败后恢复均有可用结果。

可重复观察到的区别是：**T4 的桌面信息效率较高；R7 的手机标题排版较紧凑，并多了一条确实可用的失败导出路径；M2 的本地范围说明和手机保存操作的文字状态更直接。** 这些优势没有集中在同一个产品上。R7 手机详情隐藏更新时间，T4 手机详情保存操作仅剩图标，M2 桌面卡片起点较低，是各自相应的取舍或可改进处。它们不等于同等严重的缺陷，也不按发现数量累计分数。

## 独立性、顺序和审阅边界

本审阅未参与实现。先读 `TASK.md`、`ENVIRONMENT.md`，先实际运行及查看浏览器页面，再把感知写入 [perceptual-first-pass.md](perceptual-first-pass.md)。未阅读参与者对外消息、README、Skill 条件、方法映射或其他工作目录，也未以作者的完成声明当作证据。

实际浏览器为指定的 Chromium headless shell，Playwright 控制；使用指定字体配置。视口为 **1440×900、390×844，deviceScaleFactor=1**。手机检查是窄视口桌面 Chromium，未模拟真实手机软键盘、触屏硬件或 Safari。所有应用源码保持原样；只在本审阅目录创建脚本、截图、测量文件和外部 Vite 启动配置。

视觉判断来自实际查看的截图，交互判断来自实际执行的指针、键盘、搜索输入、按钮和导航操作。指针效果检查移动后静帧及对应计算样式；**未自然速度播放录屏、未评价帧率、未做用户研究或完整无障碍审计**。逐图的“已捕获 / 已实际查看”区别列于 [evidence-manifest.json](evidence-manifest.json)，不能把整个截图目录自动视为逐张看过。

## 构图、排版、材质和内容

三者均使用近黑底、暖白衬线标题、较细的无衬线辅助文字及受控暖色。页面有持续可用的页头、搜索/筛选、集合卡片和阅读详情，未变成营销页。主体标题和正文可读，长标题不截断、不与保存按钮重叠；本次检查未见横向内容溢出。

### 首屏和长短标题的可测差异

| 观察项 | R7 | T4 | M2 |
|---|---:|---:|---:|
| 桌面首张卡片上缘 | y≈349px | y≈335px | y≈437px |
| 桌面第一张卡片尺寸 | 415×268px | 415×254px | 404×288px |
| 桌面短标题 / 长标题字号 | 31 / 25px | 34 / 29px | 30 / 30px |
| 桌面指定长标题行数 | 3 | 3 | 4 |

| 手机 “The quiet interface” 行数 | 1 | 2 | 2 |
| 手机指定长标题字号 / 行数 | 28px / 4行 | 31px / 5行 | 32px / 5行 |
| 手机首张摘要字号 / 行高 | 13 / 21.45px | 12 / 20.4px | 12 / 19.8px |

表内数值来自 `initial_measurements.json`、`r7_isolated_initial_measurements.json`、`behavior_measurements.json` 和 `final_key_measurements.json`；“长标题”指 *Keeping your place when everything around you is changing*。它们用于解释感知差异，不作为评分公式。

**T4：** 桌面几乎把六张卡片全部放进900px高的首屏，搜索位于左侧，集合正文更快进入视线。较大标题和直角细边界有清晰的刊物索引感。手机第一屏顶部说明和工具占用不低，但整体与另外两者接近。它的手机长标题五行，卡片仍留有足够空间给摘要及元数据。

**R7：** 桌面信息密度接近T4，略圆的边角、偏暖的墨色与星号带来自己的语气。手机短标题一行，长标题四行，扫读比较紧凑；桌面长标题缩至25px，换来较少行数，也降低了这张集合标题相对其他标题的分量。正文为无衬线，详情段落比T4/M2的衬线正文更紧凑。

**M2：** 页头、总述、工具栏、结果行、卡片都有明确分段。卡片底部细线和稳定的元数据位置加强结构感，标题与摘要的层级清楚。桌面较大导语区及右侧06计数使卡片比T4晚约102px进入，第二排在首屏只看到上半；它是更松的阅读节奏，对快速扫六个集合不如T4省滚动。到手机时这项首屏差异显著缩小。

参考实看：[R7桌面](evidence/R7-desktop-isolated-initial.png)、[T4桌面](evidence/T4-desktop-initial.png)、[M2桌面](evidence/M2-desktop-initial.png)；[R7手机](evidence/R7-mobile-isolated-initial.png)、[T4手机](evidence/T4-mobile-initial.png)、[M2手机](evidence/M2-mobile-initial.png)；手机长标题见各应用 `mobile-lower-list.png`。

### 表面、边缘光照和不同输入方式

指针分别落到第一张卡片相对位置约12%/16%和88%/78%，等待300ms后捕获。三者均可看见同一张卡片内的暖色光区和邻近边缘随位置改变，其他卡片保持安静，文字没有被光斑压过。R7、T4、M2都达到了题目要求的克制反馈，**这些实看证据不足以把其中一个判为显著更有材质感或更流畅**。

在 `prefers-reduced-motion: reduce` 下，三者的光源均不再追随指针：R7的悬停主要保留边界提示，T4保留固定上部柔光，M2保留全部卡片的静态层次；键盘焦点均可辨识。R7和T4的框线直接，M2正常模式的首次焦点截图抓得较早，而reduce截图显示清晰的完整粗边界。由于焦点截图未统一等待过渡结束，本报告不由这项瞬时粗细差异排名焦点质量。

证据：各应用 `normal-pointer-left.png`、`normal-pointer-right.png`、`normal-keyboard-card.png`、`reduce-pointer-left.png`、`reduce-keyboard-card.png`，以及 `behavior_measurements.json` 的背景坐标、过渡和焦点记录。

### 详情阅读和具体差距

三者长标题详情稳定后均完整可读；手机大标题五行，无裁切。返回入口在上方，正文末端另有返回入口。T4/M2的正文以衬线字体延续刊物感；R7的无衬线正文更紧凑，没有更换成与产品脱节的通用对话框。

1. **R7 手机详情丢失更新时间。** 打开长标题集合，桌面左栏能读到更新时间和参考数；390px下该侧栏隐藏，标题至正文区没有等价日期行，页面可见文本也没有日期。参考数量仅在底部“缺少14个独立参考链接”的说明中再出现。T4/M2手机详情都保留参考数和日期。若用户需要核对时效，R7需返回列表。源码仅用于解释此已观察现象：`R7/app/src/styles.css` 的600px媒体条件将 `.reading-margin` 设为 `display:none`，该区域在 `App.jsx` 中承载日期及数量。
2. **T4 手机详情的保存状态依赖图标。** 桌面有 “Saved collection” 文字，手机为书签图标；键盘/可访问名称仍可用，不能称不可操作，但视觉上状态不及R7/M2带 “Saved” 文字的按钮直接。
3. **M2 桌面给导语较多空间。** 其首张卡片y≈437，T4为y≈335、R7为y≈349。读者需多滚动才能看完第二排。这是与宁静留白相伴的信息密度取舍；手机没有同量级差距。

三者的某些分类、编号和底部元数据仅8–10px；主标题和正文可读不代表这些细字适合所有读者。此处只报告实际字号及观察，没有做低视力模拟或完整对比度测量，不能据此宣称WCAG通过或失败。

详情实看：[R7稳定手机](evidence/R7-mobile-detail-settled.png)、[R7阅读中段](evidence/R7-mobile-detail-settled-reading.png)、[T4手机](evidence/T4-mobile-detail-top.png)、[M2手机](evidence/M2-mobile-detail-top.png)。

## 核心使用路径：未观察到实质差距

两个尺寸均实际输入 `light`，得到城市和纸/光两个集合；输入不匹配词得到明确空态。随后保存长标题集合、重载、切Saved、输入 `place`、打开、返回。三者都保留收藏及 `q=place&saved=1` 的搜索/筛选条件，并把焦点还给对应集合。

进一步在手机列表下部打开集合、阅读至y=600、使用浏览器Back再打开同一集合，结果如下。这一补充对照避免了“点击顶部返回链接先使页面滚至顶部”的测量歧义。

| 应用 | 打开前列表y | 返回后列表y | 离开前正文y | 再进入正文y |
|---|---:|---:|---:|---:|
| R7 | 1262 | 1262 | 600 | 600 |
| T4 | 1301 | 1301 | 600 | 600 |
| M2 | 1449 | 1449 | 600 | 600 |

三者都精确保留了这条路径中的列表和阅读位置。早期“点击顶部返回后再打开为0”的记录仍保留，但它记录的是已先回到顶部的页面，不是阅读记忆失效。证据为 `reading_reentry_measurements.json` 与各应用 `mobile-reading-reentered-stable.png`。

键盘实际用Tab遍历到集合链接、Enter进入、Shift+Tab至返回链接再Enter，三者均能操作，并转移焦点到详情标题/原集合。另用Space在书签按钮保存及取消；取消Saved视图最后一条后，R7聚焦“0 saved collections”结果标题，T4/M2聚焦Saved按钮，均未把用户丢到无关的页面起点。重载后空收藏仍为空。这里只覆盖这些关键路径，没有完整遍历所有快捷键及读屏器宣读。

## 保存失败：三者都有恢复路径，R7多一份可用副本

正常页面加载后，仅在浏览器运行态令 `Storage.prototype.setItem` 抛出 `QuotaExceededError`，再按保存。所有产品都继续显示本次收藏、Saved筛选仍可用，并明确告知离开/刷新可能丢失。没有观察到崩溃或伪称已持久保存。

恢复原写入方法后，实际点击R7的 **Retry storage**、T4的 **Retry saving**、M2的 **Try saving again**，重载均能读回 `quiet` 收藏。三个移动错误横幅都已查看，文字与按钮未裁切。T4横幅较紧凑；R7/M2更高，但仍留下集合和工具的可操作区域。

R7额外提供 **Download copy**。该按钮已实际下载 [R7-storage-failure-download.json](evidence/R7-storage-failure-download.json)，包含当前保存集合的id、分类、标题、摘要、数量、日期和正文。即使浏览器存储继续不可用，也有可阅读的外部副本；这项优势来自真实下载，未仅据按钮存在或作者声明判断。未测试重新导入，不能宣称它有导入恢复功能。

证据：[R7错误横幅](evidence/R7-mobile-storage-failed.png)、[T4错误横幅](evidence/T4-mobile-storage-failed.png)、[M2错误横幅](evidence/M2-mobile-storage-failed.png)；状态记录见 `storage_and_settled_measurements.json` 与 `final_key_measurements.json`。

本地边界也在产品里可见：M2页头一直写“Local to this browser”，R7页脚明确没有账户/云同步且详情操作旁说明保存位置，T4页脚和详情说明本地版本。三者都明确这是样本集合、独立参考文档/链接没有包含在内，未把代表性的参考计数伪装成可打开的真实文档库。

## 保留的失败检查和排除理由

| 检查记录 | 实际发生的事 | 审阅处理 |
|---|---|---|
| R7初次两尺寸白屏 | 页面标题已加载，`react-dom.js`请求504 `Outdated Optimize Dep` | 原截图和 `r7-loading-diagnostic.json` 保留。共享node_modules的Vite预构建缓存冲突；外部cacheDir隔离后正常。不计产品缺陷 |
| 初次写入故障注入 | 审阅脚本赋值表达式返回函数，Playwright在注入阶段调用该函数，尚未点击保存即抛异常 | `behavior_measurements.json` 的 `storage_failure` 及截图保留。改为显式函数块后完成真正写入失败操作，不归给产品 |
| M2重试按钮识别 | 初始正则仅匹配“try again”，漏掉实际按钮“Try saving again” | 初始toggle恢复记录保留；按实际文案精确点击后确认重试及重载成功。不能报“没有重试” |
| R7首次详情叠字及手机y=0 | 约100ms抓到列表与详情淡入淡出中间帧，滚动命令又早于转场完成 | 原图保留；600ms稳定图及滚轮操作正常。源码确认root转场180ms。未视作永久叠字或滚动故障，也未声称自然速度体验好坏 |
| 点击顶部返回后的阅读重进为0 | 点击返回控件前，自动滚动先到页面顶部 | 另用保留y=600的浏览器Back路径对照，三者均恢复600。保留两条路径的原始记录 |
| 截图拼图尝试 | 指定Playwright Python环境没有PIL，出现 `ModuleNotFoundError: No module named 'PIL'` | 未安装依赖、未生成拼图；直接查看原图，不影响产品判断 |

为解决缓存问题，仅新增 `review-vite-R7.mjs`、`review-vite-T4.mjs`、`review-vite-M2.mjs`，导入原应用配置并覆盖cacheDir；所有环境调整有据可查。初次失败不因后来成功而删除。

## 实际检查范围与仍未验证项

已实际操作：三个应用的两个指定视口、单词搜索/空态、保存后重载、Saved与查询组合、长标题阅读和上下文返回；桌面指针两位置与键盘入口；reduce偏好下的指针和焦点；手机键盘保存/取消与焦点；存储写失败/会话继续/恢复重试；R7的失败下载。短标题详情有实际键盘进入并留截图，但未逐张作视觉详审；视觉重点放在较容易暴露问题的长标题及连续正文。

未验证：真实移动设备/触屏与软键盘、其他浏览器、读屏器、200%缩放、完整WCAG、自然速度动画主观感受或性能、真实存储配额耗尽、跨标签同步/跨会话位置记忆、所有可能的畸形持久化数据、M2的排序结果以及外部参考文件。本报告没有把这些未验证项写成通过或失败。

本次集中审阅完成关键对照后停止扩测。**最终判断是三者核心能力相当、各有实在的表现侧重和少量可复现差距；证据支持按使用偏好选择，不支持以检查数量、恢复操作次数或某张转场中间帧作总体排名。**
