# T2：Fieldnote 三个匿名冻结产品独立审阅

## 结论

L6、N3、P8 都保住了主要写作路径：在指定的桌面和手机尺寸下可编辑笔记、翻面阅读、保存全文；保存延迟期间继续输入不会被旧版本覆盖；真实浏览器存储写入失败会保留当前草稿，释放空间后可以重试成功。正反面停稳后的可见外框位置、尺寸逐项相同，静态物体身份清楚。

本轮有三类具体差异，方向并不一致：

- **L6 的初始手机布局较紧凑。** 英文初始标题为一行，保存按钮完整落在 844px 首屏内；纸张边缘、问题与下方小插图的主次清楚。
- **N3 在转动中对可访问面的处理更贴近实际朝向。** 同条件早期按 Shift+Tab，没有进入尚不可见的背面文字。L6、P8 会在翻面开始时开放背面，能复现短暂的不可见焦点。
- **P8 的长文阅读和返回入口更明确。** 背面溢出时出现“可滚动阅读全文”提示；已存长文页的返回编辑按钮位于全文之前。L6、N3 的返回按钮位于全文之后，触控用户从页面顶部返回需要滚到下方。

**不设总分，也不建立总体名次。** 保存可靠性和主要任务结果相近，排版/材料取向存在取舍；动效自然速度播放能力缺失，不能把离散截图和属性轨迹升级为完整动效观感结论。

## 审阅顺序、条件与证据边界

先读 TASK.md、ENVIRONMENT.md，再真实打开、点击并实看三个产品。初次感知已单独写入 [initial-perception.md](initial-perception.md)，之后才诊断与已见现象相关的源码。没有读取作者 README、参与者说明、Skill 条件或方法映射，没有修改产品文件。

浏览器使用环境指定的 Chromium headless shell，设备像素比为 1。桌面为 1440×900；手机为 390×844。三者使用同样的测试文字、相同的输入节奏和独立干净浏览器上下文。

覆盖了英文浅色的两种尺寸、中文深色手机界面、桌面 600 字符英文长文、手机 599 字符中文长文，以及手机中文深色的系统减少动态效果。保存压力测试在英文浅色桌面进行。未把所有语言、主题、尺寸排列组合一遍。

运行环境能取得真实浏览器截图、DOM/样式状态、键盘焦点、存储结果和时间轨迹，**没有可供审阅者自然速度观看的实时窗口或视频播放接口**。因此本文只评价已看到的静态构图、实际输入结果以及离散采样所证实的状态，不判断流畅度、惯性手感或完整翻转的主观连续感。也没有运行屏幕阅读器；可访问性结论限定于实际键盘行为与 aria/inert 状态。

多数截图使用 full_page，能显示完整排版，图像高度可能超过指定视口；文件名含 viewport、early-focus、settled 的截图为实际视口截图。旧文件名 saved-dialog 对应整页已存笔记视图，并非模态框。

## 2. 长笔记可读性与返回编辑

三者背面都维持固定卡片大小，长文在卡片内部滚动。桌面输入同一段 600 字符英文；手机输入同一段 599 字符中文，末尾带“笔记结束。”。实际鼠标滚轮能够读到末尾，Shift+Tab 可进入背面正文区，Home/End 可滚动，保存页文字与提交全文逐字相同。

| 同条件测量 | L6 | N3 | P8 |
|---|---:|---:|---:|
| 桌面背面正文可视高度 / 总滚动高度，px | 173 / 634 | 206 / 655 | 155 / 588 |
| 手机中文背面正文可视高度 / 总滚动高度，px | 120 / 1155 | 110 / 1196 | 123 / 1122 |
| 手机中文背面字号 / 行高，px | 15 / 26.25 | 16 / 27.2 | 15 / 25.5 |
| 溢出时文案 | 当前笔记的预览 | 当前笔记的预览 | 当前草稿 · 可滚动阅读全文 |
| 从已存长文页进入时，“返回编辑”相对视口 y，px | 2066.5 | 1803.3 | 211.8 |

P8 的滚动提示把“还有正文”直接告诉读者。L6、N3 也确实可以滚动，但普通预览文案没有解释裁切区域；读者需要从截断的文字或滚动行为推断。三者的长文都不存在永久截断或保存丢失。

返回位置对长文尤其有影响：L6、N3 的按钮在整段已存笔记之后，手机顶部看不到；P8 将按钮放在正文之前，进入阅读页就能看到。键盘用户从已存页标题按一次 Tab，在三者都能到达返回按钮；L6、N3 会随焦点滚到下方。因此这里记录的是触控/视觉到达成本，而非键盘不可达。

另一次真实键盘操作从长文本中间选中五个字符，再进入已存页、Tab 到返回按钮并 Enter。三者回到 textarea，选区和输入框内部滚动位置均恢复：L6 的 106–111 / 146px、N3 的 107–112 / 132px、P8 的 109–114 / 103px 前后相同。不同选区位置来自不同换行宽度下的相同八次 ArrowDown 操作。

## 3. 延迟保存、真实写入失败与恢复

这部分三者的实际结果相同。

**延迟中继续编辑。** 测试将产品原本请求的 900ms 保存定时器延长到 2500ms，保留其真实写入逻辑。输入 A 后点击保存，约 100ms 后输入 B，并在 B 中选择字符 12–19。等待完成后：已存页显示 A；输入区继续保留 B 和选区；状态明确说明已保存提交时的版本，需要再次保存新修改。打开已存页再返回编辑，B 和选区仍保持。截图例如 [L6 延迟完成](captures/L6-desktop-delayed-result.png)、[N3 延迟完成](captures/N3-desktop-delayed-result.png)、[P8 延迟完成](captures/P8-desktop-delayed-result.png)。

**真实本地存储失败。** 先保存 B，再输入较长的 C。测试往同一隔离 origin 填入配额数据，直到浏览器原生 `Storage.setItem` 抛出 `QuotaExceededError`；记录器调用原生方法并记录/重新抛出其异常，没有伪造成功或失败。随后点击产品保存按钮，三者都在产品自己的存储 key 上实际发生 `QuotaExceededError`。页面显示无法保存及文字仍在，C 保留；已存页仍显示 B，没有用失败的 C 冒充已存笔记。

**恢复。** 删除测试填充数据，回到编辑页，三者都显示重试按钮。此时返回焦点落在重试按钮，适合继续恢复操作；点击重试后保存 C 成功，刷新及已存页都能读到与 C 完全相同的文字。真实失败截图：[L6](captures/L6-desktop-real-quota-failure.png)、[N3](captures/N3-desktop-real-quota-failure.png)、[P8](captures/P8-desktop-real-quota-failure.png)。

**共同保存边界。** 在 A 已提交、B 尚未再次保存时刷新，三者都会恢复 A，未提交的 B 不跨刷新保留。已验证的是保存过程与视图切换中的草稿保留；不能把它描述为持久化自动草稿。任务未给出跨刷新自动草稿要求或基准承诺，因此本文单列这个实际边界，不将其用作三者之间的优劣依据。

## 4. 翻转中段、快速反转与减少动态效果

### 可复现的中段焦点差距

三者都从浅色桌面正面开始，点击翻面，等待约 45ms 后按 Shift+Tab。L6 和 P8 的焦点进入 `preview-note`，此时卡片仍呈现正面；截图中看不到背面正文和对应焦点。N3 此时仍将背面设为 inert，Shift+Tab 回到主题按钮，避免进入不可见正文。近时截图分别为 [L6](captures/L6-normal-early-focus.png)、[N3](captures/N3-normal-early-focus.png)、[P8](captures/P8-normal-early-focus.png)。截图取得时间稍晚于状态读取，不能当作精确同一帧的时间标尺；这段操作的两种证据都显示相同方向的现象。

下表是一次普通翻面的时间轨迹。朝向由产品仅绕 Y 轴的变换矩阵符号推断，时间相对实际 click 事件，数值用于解释这次观察，不能当成跨环境性能基准。

| 本次轨迹 | L6 | N3 | P8 |
|---|---:|---:|---:|
| 首个背面 aria-hidden=false / inert=false 的采样 | 约 6ms | 约 278ms | 约 11ms |
| 首个几何上背面朝向视口的采样 | 约 290ms | 约 261ms | 约 145ms |
| 早期 Shift+Tab 后实际焦点 | 不可见的背面正文 | 主题按钮 | 不可见的背面正文 |

L6、P8 的差距是将目标面立即作为可访问面，而视觉转动尚未到达目标。这会在短暂阶段丢失可见焦点。N3 在本次早期操作中避免了这个问题，后续越中点反转采样仍观察到两次孤立的单帧级 aria/矩阵不同步；记录器与产品的 requestAnimationFrame 回调存在先后次序，不能凭这两条数据判定可感知故障，也不能宣称严格逐帧同步。

### 快速反转与停稳结果

第一组操作每隔约 100ms 点击，共五次；三者最后都停在背面。第二组有限复核先转约 340ms，再连续约 100ms 两次反转，共四次输入；三者都回到最后指定的正面，标签、aria/inert 与最终朝向一致，焦点仍在翻面按钮，没有观察到卡片残留半转状态或编辑内容丢失。第二组使用每页只注册一次监听器的记录器，修正了第一组重复 click 时间日志的问题。

暂停装饰后等待 100ms，再跨 350ms 比较，三者轨道的 transform 和 animation currentTime 都保持相同。这里只证明暂停结果，不评价暂停切换的主观手感。

### 减少动态效果

在系统偏好 reduce、手机中文深色条件下，三者没有活动动画记录，翻面直接呈现正确的一面，静态模式/轨迹已静止等文案替代暂停操作，相关装饰开关禁用。进入已存页再返回后，textarea 焦点和所选的 4–8 字符范围恢复。模式没有妨碍读写或使翻面含义丢失。此条件下也未复现普通动效早期的不可见背面焦点窗口。

## 5. 观察后的源码诊断

源码检查只用于定位上述实际现象：

- L6、P8 的 `setFace()` 在写入目标 `data-face` 后立即设置两面的 `inert` 和 `aria-hidden`；CSS 变换仍分别有 720ms 过渡。这解释了早期背面获得焦点。
- N3 的 `syncVisibleFace()` 读取实际变换矩阵，以当前朝向设置两面可访问状态，并在过渡期间由 requestAnimationFrame 跟随。这与早期键盘结果以及接近过中点才切换的轨迹相符。
- P8 的 `updateOverflow()` 根据正文 `scrollHeight` 与 `clientHeight` 切换滚动提示，解释了短文和长文文案的实际变化。
- 三者的保存逻辑都在点击时捕获提交记录，并在真正 `localStorage.setItem()` 成功后决定提示“已保存”还是“提交版本已保存，另有新修改”；异常路径保留输入。这与存储压力测试一致。
- 三者返回编辑会保存并恢复选区及输入区滚动位置；失败状态优先聚焦重试按钮。P8 另外保留页面滚动位置，已存页的返回按钮也位于正文之前。

没有根据源码的复杂度、函数数量或实现形式给产品加分。详细定位另见 [source-notes.md](source-notes.md)。

## 6. 未成功检查、已保留记录与停止范围

以下失败均保留，且与产品结果分开：

1. L6 中文主题按钮第一次用未经核实的精确可访问名称定位，超时；改为此前实际观察到的按钮文字后完成。
2. P8 翻面按钮第一次精确名称定位超时；按钮有可见旋转箭头，脚本对完整名称的假设未成立，改为包含可见文字的定位后实际点击成功。
3. 第一份快速翻转记录器重复注册 click 监听器，产生双时间戳；原始 JSON 保留，复核记录器每页只注册一次。
4. 暂停的第一份测量在点击同帧立即取样，存在末帧差值；等待停稳后的复核确认暂停有效。
5. 长文返回补测第一次遇到本地 HTTP 服务 `ERR_CONNECTION_REFUSED`，产品还未运行；原日志保留，在脚本生命周期内重新启动只读服务后完成同一检查。

原始日志和解释位于 [failed-checks.md](failed-checks.md)。这五项不被计算为产品缺陷。

关键对照已完成，未继续扩大到无关视口、超范围浏览器或所有设置组合。最重要的剩余证据缺口是自然速度动效观看；任何更全面的动效品质判断都需要补足这一能力。
