# T3 匿名产品审阅

## 判断

**D5、A9、K4 在本任务上的交付产品等价，均完成了这次局部字号修正；没有产品证据支持把三者排出优劣。** 标题输入框与正文文本域的占位文字从原始版的 15px 调整为 14px，实际输入文字仍为 15px。两种语言、两种主题和指定的两个视口保持相同层级。已查看界面没有发现字段尺寸、按钮比例或编辑区与最近保存区关系的退化，代表性保存与失败恢复流程也与原始版一致。

这个判断限定在冻结产品及本次检查范围，不推断各提交的制作过程、验证过程或方法优劣。

## 先看界面，再核对源码

首先实际打开四个应用，逐一查看 390×844、中文、浅色、空字段首屏。初看三个提交的占位文字比原始版略小，边框、留白与控件位置没有可见变化，三个提交彼此没有可辨的产品差异。首次观察保存在 `observations-initial.md`，初始截图为 `evidence/{D5,A9,K4,STARTER}-initial-390.png`。

随后才检查源码：D5、A9、K4 的 `app/` 文件集合及全部文件 SHA-256 一致。相对 STARTER，HTML、JavaScript 与 README 的字节也完全相同，只有 CSS 中以下规则发生变化：

```css
/* STARTER */
input::placeholder,textarea::placeholder{color:var(--muted);opacity:.85}

/* D5 = A9 = K4 */
input::placeholder,textarea::placeholder{font-size:14px;color:var(--muted);opacity:1}
```

因此后续矩阵检查以 D5 代表三个相同提交，与 STARTER 对照；没有重复对 A9、K4 跑相同流程。字节证据在 `source-equality.json`，便于阅读的唯一变更在 `source-change.txt`。未读取参与者消息、工作笔记、其他任务目录或方法映射；没有改动任何 `app/` 文件。

## 视觉层级与几何

浏览器计算样式与实际画面相符：标题与正文都采用 **14px 占位文字 → 15px 输入文字**，而字段外的提示仍为 12px。中文和英文使用同一规则，没有出现语言切换后字号恢复或主题切换后层级消失的问题。英文移动端正文占位提示自然换成两行，未见截断或横向溢出；输入之后字号增大且使用原有正文颜色。

占位文字保留原有 `--muted` 颜色，并将透明度提高至 1。按实际计算颜色与字段背景计算，浅色对比约 **5.03:1**，深色约 **8.28:1**；原始版考虑 0.85 透明度后分别约 3.72:1 和 6.39:1。这些是当前不透明背景上的颜色计算结果，不是包含抗锯齿、设备显示差异或完整可访问性评估的宣称。实际查看的浅色和深色画面均能清楚读出提示。

## 保存与失败恢复

在 D5 与 STARTER 上分别以隔离浏览器上下文实际执行同一条流程：保存首版、刷新恢复首版、修改草稿、开启页面自带写入失败与 1 秒延迟设置、再次保存、关闭失败设置、重试、刷新验证。

| 状态 | 实际结果 |
|---|---|
| 首次保存与刷新 | 标题和正文写入本地存储，最近保存区显示记录，刷新恢复原内容 |
| 延迟保存中 | 保存按钮禁用，`aria-busy=true`，状态文字说明正在保存，旧记录仍保留 |
| 模拟写入失败 | 新草稿标题与正文都留在字段内；本地存储和最近保存区仍保留成功保存过的首版；显示失败说明和重试按钮 |
| 关闭失败后重试 | 新草稿成功写入，最近保存区更新，重试按钮消失，焦点回到标题输入框 |
| 恢复后的刷新 | 新标题与正文从本地存储恢复 |

两份实现结果一致，未捕获页面 JavaScript 异常。操作与存储快照在 `save-retry.json`，实际查看了 `D5-save-failed-1440-en-light.png` 与 `D5-save-recovered-1440-en-light.png`。失败模拟使用应用自带控制，未模拟浏览器真实配额耗尽、系统禁用存储或读取损坏；JavaScript 相对原始版字节未变，为本次没有行为回归提供额外依据。
