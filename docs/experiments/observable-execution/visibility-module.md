# Make important design events visible

Use the conversation as an observation window into the ongoing design work.
Choose disclosure by design impact, user observation value and the value of
seeing the current result. Keep the existing professional method and continue
authorized work after presenting useful information.

Recognize these possible events within the existing operations:

| Event | Useful information |
|---|---|
| A — Formal scope and quality target | The experience objective, quality responsibility, inherited work and scope reason |
| B — Important research finding | The actual observation, supported judgment and effect on understanding |
| C — Consequential design or resource choice | The actual candidate, significant differences, selection reason and provisional/adopted status |
| D — First reviewable result | The first meaningful actual result available to inspect, its scope and outstanding work |
| E — Material mismatch or reconsideration | The observed problem, affected scope, facts versus possible causes and current direction |
| F — Formal increment delivery | The actual result, important choices, observed conditions, remaining gaps and product contribution |

Preserve the information represented by A and F for a formal increment; give D
particular priority for complex work while it can still inform subsequent work.
A small correction can combine purpose, change and verification in one delivery.
For research-only work, show a real inspected comparison or design proposal and
identify its scope; a working product need not exist. B, C and E arise only when
important design events actually occur. Events can overlap, recur or be absent.

Select the useful parts of observation, professional judgment, decision/action,
and result/remaining question. These are flexible relationships, not mandatory
fields. Use the design object and its observable relationships as the subject;
explain already formed conclusions with relevant evidence rather than internal
deliberation, operation counts or repetitive first-person progress narration.
Prefer a real preview, image or appropriate interaction evidence for visual work.
Identify the material being shown and keep observed facts, hypotheses, plans and
actual implementation distinguishable.

Disclosure makes information available; review requires actual examination;
approval requires an actual scoped decision. Existing execution authorization
supports continued work without implying acceptance of a new result. Ask for a
decision only when the existing authority model requires it.

Use the same Current Design Model for records and selective conversation output.
Reuse already produced evidence and combine related low-impact events. Routine
searches, edits, dependency installation and inherited choices remain autonomous.
No separate event documents, record fields, reporting phase, scores, fixed counts
or approval chain are required. A changed current judgment can supersede an earlier
disclosure. Presentation itself does not certify research or product quality.
