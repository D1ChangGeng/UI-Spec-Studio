# UI Spec Studio v1.16.0 独立实验与发布补充报告

记录日期：2026-10-28。新增批次：`replication-20261028-20e56`。本文记录发布后的实际实验，不改写 v1.16.0 最初发布时的证据状态。

## 1. 当前可以下的结论

这次补齐了 **12 次真实、独立上下文的实现，6 组完整匹配对，以及 3 位独立完成并锁定原始判断的匿名模型评审**。比较对象是完整生产版 v1.15.0 与完整生产版 v1.16.0；每次实现收到对应版本全部 37 个原始运行文件。新增产物均已完成、冻结并接受独立功能检查。早期批次仍为 12 次计划中的 9 份恢复产物，另 3 份保持缺失，两个批次不合并。[E1–E4]

**功能检查没有显示 v1.16.0 的提升。** 在每份产物十个验收组的固定口径下，v1.15.0 为 **59/60**，v1.16.0 为 **58/60**；六组匹配对中五组相同，一组 v1.16.0 少通过一组。这是本次具体任务和有限重复下的描述性结果，不是版本的一般可靠性概率。[E2]

**匿名模型判断没有支持 v1.16.0 的普遍整体提升。** 18 个配对判断中，11 次偏好 v1.15.0、4 次偏好 v1.16.0、3 次并列。v1.15.0 的偏好集中在完整研究产品与专业工作区；v1.16.0 的四次偏好都来自来源阅读弹层，且强度均为弱。六个分立维度中，只有“产品身份与目标适配”在三对产物上出现负的配对中位数，其余维度的六对中位数均为 0；没有正的配对中位数。这说明本次量表和判断下差异具有任务依赖性，不能换算成品质百分比，也不能由同等级评分推断界面视觉相同。[E2、E3]

**受控行为存在一项重复出现、可由代码确认的差异。** T3 来源阅读弹层中，v1.16.0 两次实现都实质保留了 Vaul 1.1.2 的拖动、释放和回落机制；v1.15.0 两次实现使用 Radix 与 Motion，并自行编写手势策略。T1 的局部 Vane 复用较为相近；T2 还存在 v1.15.0 复用更宽组件家族的反例。因此可以说新版本在这个局部任务上更常采用已有的完整时间行为实现，不能据此声称所有任务都更深复用、整体品质已经提高，或已采用完整成熟产品系统。[E5]

**你的实际反馈仍待补充。** 本次没有把模型评分、自动化界面的测试输入，或上一版本的接受意见写成你对 v1.16.0 的认可。交付界面支持真实操作、匿名配对、版本知情记录、逐维评分、锁定和导出；收到实际反馈后，应追加其观察范围和结论，保留本次原始模型记录。[E2、E9]

## 4. 三位匿名模型评审的视觉结果

评审只收到匿名产物、任务说明、共同参考及各自固定顺序，不读取版本、源码、功能得分、过程报告或其他评审。三份原始文件先保留并作 SHA-256 锁定，随后才把判断与版本映射关联。评审材料共 499 个锁定文件，包含原始稳定截图、必要状态、顺序图像、录像与参考；存在文件不代表评审实际查看了它。[E3、E4]

六个维度分别为任务与整体连贯性、构图与空间稳定性、排版与阅读层级、材质与素材整合、状态与动态表达、产品身份与目标适配。使用 0–4 序数量表：0 为缺失或严重损坏，1 为反复的重大缺陷，2 为基本可用但有明显弱点，3 为成熟连贯且仅有局部弱点，4 为在所见条件下高度完善且未见实质弱点。未实际观察的项目可以留空；六维不相加、不加权、不转换为“品质提高百分比”。[E1、E3]

**T1：完整研究路径的功能完成度相同，视觉判断更偏向 v1.15.0 的阅读组织。** 第一次有两位弱偏好 A、一位并列；第二次三位均弱偏好 A。评审给出的共同理由包括来源与出版者信息的呈现、手机端三份来源的可见性、阅读器中明确的前后切换入口，以及产品排版身份。它们不是笼统地认为字号越小或来源越多越好：第一次 B 组把三个来源同时放进手机首屏，第二次 B 组拥有较宽松的正文排版与明确的保留输入反馈，这些优势也被记录。固定 Vane 图片提供成熟研究产品的组织参照，但评审没有据此确认商业服务等价。[E3]

**T2：本次最一致的偏好来自完整工作视图，而非首页装饰。** 六个判断全部偏好 A；第一次为两次弱、一次中等，第二次三次均为中等。第一次 A 组的比较式日程、近期工作区块，以及在响应式项目卡片中保留预算、方法、负责人和日期，是反复出现的理由。B 组的紧凑桌面表格和清楚的按月议程也受到肯定。第二次 A 组把较鲜明的编辑式字体、方向标记与编号档案组织延续到实际工作，同时在桌面和中等窗口详情中把笔记编辑与保存入口放入可见区域；B 组则有更宽松的正文和部分更完整的项目上下文。这里支持的是该批次的产品表达和可见工作组织差异，不是“更多装饰一定更好”。[E3]

**T3：v1.16.0 在阅读空间利用上获得有限、较弱的偏好。** 第一次一位弱偏好 B、两位并列；第二次三位均弱偏好 B。理由主要是手机中可见的摘要更多、展开后引文在笔记栏上方露出更完整、全文入口更明确，以及阅读列宽和笔记产品身份的连续性。A 组的目录/笔记侧栏、明确模式标签、更强来源选中表现和部分背景上下文也被列为优点。六维配对分数在两次 T3 中都没有等级差值，因此这些偏好反映了同一等级内的取舍，不能扩大成明显的整体品质跃升。[E3]

**已有时间行为实现的采用，与运动品质提升仍是两个结论。** 源码审计能确认 B 的两份 T3 实质采用 Vaul；本次偏好理由则主要指向所见阅读布局。三位都没有连续观看录像，不能把这一局部偏好归因于 Vaul 的真实拖动手感、缓动或回落流畅性。R1 将 A 第一次的一些中间帧侧栏裁切纳入弱偏好；R2、R3 保留了相应可见事实和不确定性，仍给出并列。这种分歧原样保留。[E3、E5]

**量表分辨率是本次结果的实际限制。** 216 项逐维评分中，201 项为 3、15 项为 4；这是评分记录的分布，不是把 216 项当成独立样本或把分数相加。连贯性、构图、排版与状态表达的所有配对差值范围都是 0；材质维度只在 T1 第一次有一位评审给出 −1，其配对中位数仍为 0。身份维度在 T1 第二次、T2 两次的中位数为 −1。0–4 的较粗等级没有分开许多仍被成对理由辨认的差异。这里没有做等价性检验，也不把“同为 3”写成“没有任何可感知差别”。[E2、E3]

一些细节弱点同时存在于受偏好与未受偏好的产物：长回答中 Latest 控件与正文重叠、移动端标题和固定编辑区域压缩首屏阅读量、部分日程缩略条缺少刻度标签，以及详情笔记入口位于当前截图以下。报告保留对应观察，同时区分“当前画面未显示”与“用户无法滚动到达”，没有把后者当成已验证事实。[E3]

三位视觉评审均未进行实时应用操作。因此，模型视觉判断覆盖的是实际查看的图像与顺序样本；功能是否完成由独立浏览器验收另行支持，用户的实际操作体验则留待本地界面中的反馈。[E3、E6、E9]

R1 与 R3 查看了全部 192 张稳定原图；R2 查看了 156 张稳定原图，其余稳定组合通过总览图覆盖。具体而言，R2 的 T2 原图覆盖桌面初始主题、中等窗口另一主题，以及手机两种主题下的所有工作视图，其他宽度/主题组合来自总览；T3 的 900 像素笔记壳也来自总览。三人都查看了全部 36 张补充原图、各输出总览和三张基准图，选看的时间采样原图数量分别为 78、60、61。原图与总览的覆盖差异保留在原始限制及各自 HANDOVER.json 中；其他文件计数只反映清单内项目，不用于判断是否读过未列入清单的说明。[E3、E4]


三位模型评审的工作彼此独立，但仍是相关的模型判断；不是 18 个独立用户，也不会把 12 次生成扩大为 36 次。视频作为原始证据保留，只有实际连续观看才能支持自然速度的运动观感。顺序图片可以支持状态可见性和采样连续性的判断，不能证明真实播放的流畅性、帧交付或物理设备体验。[E3、E4]

### 原始参考、本地试验与成品并非一条无缝证据链

审计发现了一些实质但有范围限制的链条：固定 Vane 图片是静态参考；当前 shadcn 的 Base UI 演示并不完全等于保留的 Vaul 实现；Vaul 的吸附点演示不等于本地自定尺寸；当前 Radix 文档也不必与安装的 1.1.15 完全一致。报告按原始来源、本地试验和集成结果分别记录，既不抹去实际采用，也不声称每次都验证了同版本同变体的完整链条。[E5]

日志中的具体失败、后续代码和检查结果，能够支持停止、焦点、点击或对比度等修正的发生。参与者“看过图后改变设计”的表述，在缺少导出的实际看图轨迹时，仍只是自述。命令数量、来源数量、自写 CSS 比例和下载次数均未被当成设计质量指标。[E5]

### 受限改造保持边界

四份 T3 的 `domain.js`、`Shell.jsx` 与 `shell.css` 均与提供版本逐字节一致；导航只把 Saved 改为 Library，原 id、图标与计数保留。来源阅读组件内的新增工作单独列出。这个结果支持本次任务的范围控制，不能扩展为对任何未来改造都能维持边界的保证。[E2、E5]

## 8. 可启动对比界面与你的反馈

解压 `UI-Spec-Studio-v1.16.0-study.zip` 后，在解压目录运行：

```bash
python3 replay.py
```

Windows 可运行 `py -3 replay.py`。需要 Python 3.10 或更新版本；浏览器打开 `http://127.0.0.1:8765/`。不需要 npm、模型 API 或在线服务。每份成品使用独立本地端口，避免成品之间共享 localStorage。ZIP 对完全相同的文件只保存一份字节；首次启动根据 SHA-256 索引恢复相同副本，不重新生成图片、不联网下载，也不覆盖已修改文件。[E9]

界面提供新批次 12 份与旧批次 9 份可用成品，同时保留旧批次 3 个缺失位置。可以切换固定视口，操作真实编译输出，查看原始截图和 1× 录像，打开独立窗口，并展开任务及 T1 共同参考。并排显示通过缩放整个 iframe 保留指定的 CSS 视口；独立窗口尺寸由你的浏览器决定，工具不模拟真实设备的硬件性能。[E9]

反馈按六维分别填写，允许空白，并记录配对偏好、强度与原因。可操作成品的具体业务状态请写在观察理由中；界面不会误把菜单中选中的截图状态当成你当前操作到的实时状态。截图和录像则记录相应证据状态。若事先知道版本，应勾选知情；点击揭示版本后，新反馈也会标记已揭示。锁定会保留时间、条件和摘要，修订会保留旧记录，导出 JSON 后可交回用于追加发布记录。[E9]

匿名是一项评审流程，不是身份不可发现的技术隔离。完整证据包本就含有源码和版本映射。你的反馈应按实际观察和知情情况记录，不强求“盲评”标签。工具的合成测试反馈与真实用户意见分开，交付时真实 owner assessment 仍为 pending。[E2、E9]

完整性与纯数据复算可用：

```bash
python3 replay.py --verify-only
python3 tools/recompute_all.py
```

复算读取保留的原始检查与锁定判断，把新输出写到 `recomputed/`，不会再调用模型、修复应用或更改原始评分。除本次复算时间以外，新批次的结果字段应与交付结果逐项相同。这个命令检验的是证据与计算的可复核性，不会重新生成一次独立 Agent 实验。[E9]
