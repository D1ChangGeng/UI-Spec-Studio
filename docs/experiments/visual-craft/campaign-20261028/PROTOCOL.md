Does the full v1.16.0 skill improve observed research/resource selection and completed UI quality relative to the full, already substantial v1.15.0 skill in these three task families? No cross-model conclusion is possible. Six matched task/repetition pairs control task inputs and opportunity, not stochastic model outputs.

## Outcomes fixed in advance

Primary functional outcome: each task has10 published acceptance groups from TASK.md, exercised on frozen builds. Each group records detailed subassertions and passes only if its required conditions pass. Report pass count /10 and each failure; do not collapse visual quality into functional scores. Critical absent product paths are called out even if one group carries multiple conditions. Missing hooks are a harness issue only if equivalent accessible behavior can be located without source repair; selectors may be adapted, and those changes must be recorded.

Primary perceptual outcomes: 3 independent, version-blinded model reviewers inspect matched anonymous renders at normal scale and ordered transition samples, using six separate0–4 dimensions: (1)task/whole-product coherence,(2)composition and spatial stability,(3)type/readability/content hierarchy,(4)surface/material/asset integration,(5)state and motion communication,(6)brief-specific identity and target alignment. Score0missing or unassessable,1major recurring deficiencies,2adequate with conspicuous weaknesses,3coherent mature execution with minor weaknesses,4exceptionally resolved across provided conditions with no material weakness observed. Each score requires visible evidence and a limitation. No universal aesthetic sum, weighted quality total or pass/fail threshold is produced. For T2 dimension6 specifically assesses expressive identity through populated working views; for T1 it compares the supplied benchmark's maturity at matching task scope, never commercial service equivalence; for T3 it assesses sheet continuity with preserved surroundings. Static images cannot establish natural motion quality: reviewers must mark that part unassessed when only samples exist. Raters receive no source/manifests/timings/versions. Their independent original scores and disagreements are retained. Report dimension medians, ranges and pairwise preference with explicit reasons; no human-user preference is implied.

Secondary process outcomes: actual research retrieval and review claims; consequential choices altered by evidence; mature implementation adoption (distinct from icons/primitives/functionality); original demonstration→local trial→integrated verification chain; time to first successful build and elapsed duration when command timestamps support them; unnecessary work on T3 label control. Source files, hashes and observed commands establish retrieval/adoption. Image-view attestations and narrative choices are labelled self-reported where tool traces cannot be exported. Shell command logs are not total tool-call or token counts. Raw full conversation export is unavailable in this harness.

Runtime diagnostics: build outcome, page errors, offline/remote dependency behavior, transfer sizes, overflow, local task timing and relevant layout changes. Performance observations are headless measurements on a shared machine with concurrent agents; they are diagnostic, not production FPS, device benchmarking or causal speed claims. Finite timestamped motion samples are separate from full natural playback.

## Failures and inference

Include every assigned run. Unrenderable or absent output yields0/10 functional and perceptual0with failure flag, not a fabricated screenshot. Partial output is assessed as-is. Optional source failures are ordinary observed costs. Proven host outage affecting basic execution before output can trigger one paired rerun; original attempts retained. Application mistakes, weak design or overlong research do not trigger reruns. Any post-freeze repairs would be a distinct follow-up cohort and cannot replace original results.

Report all12 outputs, all6 paired deltas and per-family replication variation. Main inference is descriptive within3 selected briefs and one model/harness. Repeated generations and three correlated model raters do not create additional independent task samples. No claim of statistical significance, general design ability uplift, deployment readiness, commercial product parity or human usability improvement is supported by this sample. A negative or mixed result remains a completed experiment. Potential mechanism explanations are explicitly interpretations, not causal findings.

## Publication and evidence integrity

Preserve task/skill/runtime/source identities, start/end and artifact hashes, unmodified final applications, tests and anonymous review packets. Do not expose secrets. Third-party sources may be used in derived applications subject to their terms; if redistribution is restricted, publish source locators, hashes and a retrieval script instead of a standalone component collection. Report durable artifact identifiers and repository state only after verification. No skill revision or new release is part of this experiment.
