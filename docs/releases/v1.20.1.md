# UI Spec Studio v1.20.1 — Lean Skill Distribution & Unified Harness Installer

## Distribution fix

The earlier recommendation `npx skills add D1ChangGeng/UI-Spec-Studio --skill ui-spec` could clone the full Git repository before copying the one Skill folder. The source contains substantial archived research and evidence, which has no place in a consumer installation.

The supported default installation now uses the dependency-free UI Spec Studio installer packaged as a release tarball, directly executable by npm:

```bash
npx --yes https://github.com/D1ChangGeng/UI-Spec-Studio/releases/download/v1.20.1/ui-spec-installer.tgz install --agent codex
```

The release also retains the dedicated `ui-spec-1.20.1.zip` Skill archive for standard Skills CLI consumers, and the standalone Codex adapter ZIP for manual or offline use. None of these installation assets requires fetching the complete Git repository.

## Single installer, independent Harness adapters

- One CLI owns explicit `install`, `status`, `uninstall`, `--dry-run`, `--upgrade`, project and global scopes.
- The package bundles precisely `skills/ui-spec`, the already-supported Codex adapter and a declarative Harness registry. It excludes the repository's `docs/`, `tests/`, `.git/`, examples and archived study evidence.
- Codex installs the Skill plus the four native role registrations using its previously tested, separately owned Python adapter. Python 3.11+ is required for Codex adapter installation, not for the other supported Harnesses.
- Claude Code, Cursor and OpenCode install the portable Skill into their declared native locations; no specialized native role support is claimed for these hosts.
- An explicit runtime adapter entry can be added per Harness without moving host behavior into `SKILL.md`.
- SHA-256 inventory checks verify every bundled runtime file before changing the destination. Managed receipts protect user-modified and previously unowned Skill directories, upgrades are explicit and staged, and a failed adapter install restores the previous Skill folder.
- Release builds are deterministic. An offline end-to-end smoke test verifies package structure, repeatable archives, Host copies, Codex role preservation, tampering refusal and npm tarball execution.

## Scope of verification

This release changes installation and distribution mechanics, not the UI methodology or its acceptance evidence. Successful installer tests do not establish that a host exposes custom child-agent orchestration, that any model is available, or that particular UI quality improvements occurred. The validated v1.20.0 findings retain their original scope and limitations.
