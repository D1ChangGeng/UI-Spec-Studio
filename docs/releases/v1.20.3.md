# UI Spec Studio v1.20.3 — Official npm package distribution

## Objective

Provide one official, named, version-resolving installer:
`npx --yes ui-spec-studio@latest install --agent codex --global`.

The existing immutable, compact standalone release tarball continues to be available as a fallback. No GitHub clone is required, and no historical evidence or source archive is delivered to the consumer.

## New distribution foundation

- The self-contained npm tarball now declares the public npm package identity `ui-spec-studio`, repository provenance, one binary `ui-spec` and a versioned package manifest.
- The CLI supports `--version`, default interactive install and deliberate user/project installation scope selection; legacy Skill copies and Junction backups retain the reviewed v1.20.2 migration rules.
- A separate `npm-publish.yml` workflow creates a verified candidate artifact in PR CI and supports an explicitly authorized, OIDC-based npm publish after the npm account holder has claimed the package and configured trusted publishing.
- The npm package is **not** considered generally available until an actual registry publication and CLI readback succeed. The README must not advertise the registry entry prematurely.

## Acceptance boundaries

Cross-platform Skill installation, native Codex registration, migrated legacy files, actual Clack terminal interaction and reproducible bundle identity are tested separately from npm account authorization. No model runtime efficacy or UI outcome claim follows from publishing the installer.

## Registry bootstrap and future updates

The first npm publication requires the npm account holder, because npm does not allow binding a trusted publisher before an initial package exists. Subsequent versions can be published from the verified GitHub Actions workflow through npm's OIDC trusted-publisher mechanism. Maintain a single package name and `latest` dist-tag; do not reuse a published semver or silently change another user's registry package.
