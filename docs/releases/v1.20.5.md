# UI Spec Studio v1.20.5 — Verified npm OIDC publisher recovery

## Release scope

This patch corrects the npm publishing automation; it does not change any UI Spec Studio professional methods, visual requirements, model behavior, or agent permissions.

The previous `v1.20.4` GitHub Release was successfully published and is **immutable**. Its automatic npm workflow stopped **before executing `npm publish`** when an npm CLI query result was mistakenly treated as a pre-existing conflicting archive. Thus `v1.20.4` was not an accepted OIDC publication; do not move its release tag or republish it manually.

## Fix

1. Query the exact public version metadata over HTTPS. Only HTTP 404 permits a first publish attempt. HTTP 200 requires matching name, repository, version and SHA-512 to safely skip an already published identical archive. Unexpected metadata or connectivity errors block publication.
2. Remove `registry-url` from the publish job's `actions/setup-node` configuration, avoiding generated placeholder `_authToken` settings that can suppress OIDC. Retain Node 24, npm 11.5.1+ and `id-token: write`. Publish only to the official npm registry.
3. Run the same read-only registry preflight in the npm candidate CI, and test absent, matching, conflicting and unavailable version states.
4. Keep post-publish bounded readback, immutable Release SHA-512 parity, latest dist-tag verification, public CLI and reversible migration smoke tests.

## Required acceptance, pending actual execution

- All Linux, macOS, Windows tests, browser/product scenarios and installer portability checks pass for the exact new release.
- GitHub `v1.20.5` tag points to the approved main commit. The public GitHub Release assets pass SHA-256 readback.
- The configured GitHub Actions npm Trusted Publisher actually runs `npm publish` for **new version 1.20.5** using OIDC without long-lived npm credentials. A skipped or preflight-failed job is not evidence of authentication success.
- Public npm metadata reports `ui-spec-studio@1.20.5`, SHA-512 matches GitHub `ui-spec-installer.tgz`, `latest` references the right version, and the official npx installer passes clean installation, old Skill migration and rollback.
- Confirm npm Trusted Publisher no longer reports `Pending validation` and verify any available provenance attestation before closing Issue #11.

Never retry publishing a version that npm has already accepted merely because public readback is delayed. Investigate and use read-only checks first.

## Official installation

```powershell
npx --yes ui-spec-studio@latest install --agent codex --global --migrate --lang zh
```

`--migrate` is necessary only when replacing an earlier unowned Skill directory. The existing 37-file Skill inventory and Codex-native roles remain unchanged except for the published version metadata.
