## UI Spec Studio auxiliary work

When using `ui-spec`, keep the main agent responsible for the overall product goal, formal UI SPEC, pivotal visual judgment, final mature-resource choice and whole-product acceptance. Follow `references/delegation.md` whenever delegating auxiliary inquiries.

For high-craft discovery, naturally delegate to `ui_researcher` with the intended experience, taste bar, current conditions and consequential unknown (no rigid schema required): expect multi-tier wide sourcing across elite products, curated visual registries, specialist OSS codebases and type/icon ecosystems, rejecting generic defaults as final visual surfaces and returning curated craft mechanics alongside verified adoptable links. Inspect pivotal visual evidence directly; a recommendation is never acceptance.

Use `ui_integrator` only for already selected mature sources and bounded changes with clear interfaces, protected craft relationships and checks—expecting source-preserving de-templating, canonical token harmonization, `@layer` cascade isolation and rendering-fidelity repairs rather than improvised CSS. All four roles install by default; invoke `ui_challenger` on demand to challenge generic defaults, AI-slop signatures, degraded craft or premature convergence, and invoke `ui_experience_observer` on demand for side-by-side target-demo vs. integrated-UI capture, tight optical crops, mid-transition focus/`inert` episodes or authorized native-GUI checks. Ordinary browsing remains available to all relevant agents, and no role is a compulsory stage. Honor actual host permissions, non-overlapping writes and GUI isolation; without compatible subagents, execute the same Skill directly. All substantive UI SPEC work retains the eight-reference reading contract and default-deny W1–W3 boundary.

When the native Codex selector supports these custom roles, start the selected role in a fresh context and supply task-local product facts and source locations. A full-history fork inherits the parent's agent type on the tested interface and cannot simultaneously select a different custom role. Verify actual native role binding; a generic child reading a role file does not establish that binding.

Across long-running multi-session products, reconcile the Continuation Baseline (Overall Product Goal, Current Design Model and live Current Product UI/recent commits) before delegating or editing code, inherit settled foundations without re-litigating confirmed choices, preserve landed functional fixes and staged migration seams when addressing brownfield drift, and keep active design records compacted to the active product without dropping open obligations across Visual & Craft, Provisional Probe & Migration Bridge, Integration & Contract, or Verification Scope debt.
