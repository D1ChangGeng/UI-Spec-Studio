# Model and tool policy

Documentation check: 2026-10-31. Role files inherit model settings. Promote a model/role pairing only within the tasks and conditions supported by its recorded comparisons.

Keep professional Skill knowledge, stable role behavior, natural task delegation and model/tool configuration separate. Inherit the parent's available model by default. Do not silently fall back to an unapproved provider or paid model. A missing model is an environment limitation to report, not evidence that a weaker task result is acceptable.

Candidate comparisons, subject to account availability: researcher and scoped integrator — `gpt-6.1-sol` medium; visual/GUI-heavy work — compare `gpt-6.1-terra` medium; difficult long-loop analysis or challenge — compare Sol high or `gpt-6-astra`; narrowly mechanical confirmed work — consider `gpt-6-luna` only after measured adequacy. These are hypotheses, not model rankings. Reasoning settings must be supported by the selected model.

Codex resolves spawn/default/parent choices and then applies explicitly supplied role model settings according to its current documented contract. A model-only role override can preserve a previously resolved effort; set a compatible effort deliberately when pinning a model. Our role files avoid that coupling by leaving both unset. The installer never changes a user's defaults.

Evaluate actual resource relevance, visual and temporal observation, preserved diversity, research success, parent verification/repair burden, adopted source craft and assembled UI. Also record wall time, model/tool use, retries and rework. Unknown subagent/token costs stay unknown; main-thread usage is not total multi-agent cost. Token prices alone do not establish task efficiency. Use dated official pricing only when reporting an actual cost calculation; no permanent price table is bundled.

Update one layer at a time. Maintain frozen tasks, source hashes, real session identities, tool/environment versions, failed examples, reviewed outcomes and a recoverable previous configuration. A faster model that misses important states is not an automatic upgrade. Retain or restrict the stable choice when evidence is mixed. No theoretical monotonic improvement is promised.
