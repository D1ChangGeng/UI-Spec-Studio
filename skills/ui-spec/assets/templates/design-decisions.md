# Design decisions and resource map

Use only the portions needed for consequential choices, or equivalent existing
records. Keep representative evidence and decision changes rather than a search log.

## Product and scope

Task and audience; requested redesign scope; current business/engineering facts.
Primary working object, first meaningful action, repeated loop, continuation and
result location. State the target experience with or without a named product
reference. Expand names or style descriptions into the relevant task, surface,
state and relationship. Separate observations, inferred model and open intent.

Keep current-user intent, audience conventions and actual product practice distinct.
Identify the version, platform, role and conditions relevant to the target experience.

## Research question and evidence plan

Link the experience hypothesis to important parts, states, journeys and relationships.
Explain which text, rendered view or interaction can answer each consequential
question. Keep source statements, actual observations, interpretations and missing
evidence distinguishable. Name a finding that could change the current choice.

Record the significant discovery, its effect on understanding and the next useful
search, observation, comparison or trial. Independent origins and materially different
design relationships establish breadth; repeated listings retain their common lineage.

## Direction and authority

Recommended interaction model and visual direction; relevant mature product
flow links, inspected scope/date and transferable conventions. Name meaningful
alternatives and differences in actual use when a significant choice is open.
Record user choice, explicit delegation or provisional recommendation with its
source and affected scope. A preview option selection records only its stated scope.

Separate required task behavior, explicit aesthetic goals and revisable conventions.
Name functional, cross-domain expressive and implementation source roles. Show
consequential art directions with actual material and comparable completion;
identify what stays familiar, what changes and how the theme persists in core work.

## Foundation comparison and selected granularity

Concrete mature page/system/block candidates, source/demo/revision, actual observed
states, meaningful episodes and evidence. Explain the selected level, valuable design relationships
inherited together, local trial and meaningful alternatives. Identify the implementation actually
adopted and the mechanisms preserved. Classify code reuse, configuration, composition,
design transfer and original work accurately; give the evidenced gap for custom common UI.

Keep the design reference and implementation resource identifiable. Record the
research question, useful clue/action and conclusion: observed phenomenon,
likely perceptual effect, underlying relationship and what this product inherits.
Attribute evidence to its carrier page, player, depicted product UI or displayed
work; retain edited-demo or actual-operation context where it changes the claim.

Compare alternatives under corresponding content, scale, theme and state. Explain
the competing strengths, the evidence behind the current preference and unresolved
tradeoffs. Preserve a promising unexamined direction when it could close a quality gap.

## Reuse assessment

Preserved functional contracts and constraints. Existing visual candidates and
what makes each worth retaining, adapting or replacing against the target.

## Surface and resource selection

| ID / surface / state / dimension | Intended outcome and product-pattern reference | Exact implementation source / variant | Choice, reason and reuse depth | Adaptation and implementation/preview location | Evidence, date and current status |
|---|---|---|---|---|---|

Consider product objects, layout/navigation, content/typography, components, assets,
feedback, motion, runtime readiness and operating work as applicable.
Shared IDs can serve multiple pages. For native, authored or retained work,
identify the actual source and fit rationale. Link the exact source and demo when
external work is selected. Use an existing equivalent record instead of duplicating it.

Start candidates while direction is open. Reconcile studied, compared, trialed,
actually adopted and verified status with real code/assets and observed conditions.
Owner approval remains separate. A consequential trial uses current content, type,
themes and states before wider integration. Detailed notes may hold rights, versions,
modified mechanisms and maintenance ownership; reuse is assessed by the responsibilities carried.

Link important choices to a visible fact, likely perceptual effect, explanatory relationship
or hypothesis, product fit and actual implementation decision. Retain representative viewed
frames or time ranges and their display/crop/zoom conditions. Follow consequential details
back to their region, neighboring elements and whole-page effect. Inspect the reference, original resource demo, local trial and
integrated result separately; new evidence can reopen the choice. Retain quality
gaps, their responsible layer and any explicit decision changing the target or scope.

## Review and continuation

Working preview and source; inspected views, states and tasks; resulting changes;
remaining high-impact choice; approval source and acceptance evidence; next useful increment.
For motion-dependent decisions, identify the observed interval, trigger and
endpoint and which temporal questions remain open. Distinguish media acquired,
actually examined content and conclusions it can support. Record sufficient,
partial and missing evidence by decision impact; carry remaining questions into
the runnable slice and re-answer them under current product conditions.

Choose further research, a bounded trial or broader implementation from current
evidence maturity. Consider breadth, depth, temporal coverage, relevance and reliability
together. State which open question could overturn the decision and how the next
action will resolve or contain it. User approval keeps its actual scope.

## Asset production and placement

For identity-bearing or other consequential visual assets, link the shared asset ID
to its purpose, source/permission, editable master, production route, export
variants, delivery/placement and actual review. Use the asset record or existing
project equivalent. Keep visual approval, usable file delivery and runtime
verification scoped to their evidence.

## Content and language decisions

For consequential content, link the user question, surface/state, factual authority, localized wording, typography role and observed result. Reference the existing product content record or optional [content template](content-decisions.md). Keep routine strings in their component/content source.

## Runtime and operating decisions

For consequential choices, connect the intended sequence to preparation, validity,
resource cost, authoritative completion and recovery. Link relevant content/template
ownership, override behavior, role information and batch scope. Record measured
conditions and observed outcomes where evaluated; routine implementation stays in code.
