# Worked reasoning examples

These examples illustrate application. They are not executed product evaluations or a fixed recipe.

## A user with only a goal

“Help me design this research workspace; I have no visual direction.” Read product facts and existing tasks. Use optional shape to identify the collection/detail/edit loop, shared shell and desired working density. Study a small set of useful references, recommend one direction and build a representative list/detail interaction. Present its actual render and a clear next increment. The user evaluates the result rather than selecting a component catalog.

## A user with a precise reference

“Keep this typography and use this selected card interaction.” Treat the typography and intended interaction as constraints. Inspect the selected implementation for framework fit, focus behavior and motion control. Adapt the surrounding spacing, content and shared tokens. Verify actual behavior and supported views. Request a decision only when a material conflict changes the user's intended result.

## A continuation after approval

“Approved, continue.” Identify the reviewed scope, preserve its shared rules and choose the next highest-value incomplete task. In a workspace, a missing return path with retained filters may matter more than a new overview. Complete that path, inspect the affected screens and present a working result. Read required professional references when they are not already available in the execution context.

## Vague compositional feedback

“This feels too low.” Inspect the whole viewport, primary content mass, image contrast, top/bottom space and page family. A compact task may benefit from an optical upward adjustment. A settings tab instead inherits stable family anchors and solves balance within its content area. Implement the bounded hypothesis and compare the actual result.

## A bilingual cultural archive

Use reading flow and real licensed imagery. Shared identity links collection, item and editorial views, while each has its own content shape. Test translated long headings, glyph coverage, image loading and narrow widths. At finish, connect actual content and the contact endpoint; static routes complete through verified content/build behavior.

## A scheduling tool reaching finish

Reconcile the approved editor with existing services. Map create/edit/conflict/retry, permission and timezone owners. Connect a complete create outcome, preserve draft and selection during conflict recovery, then verify persistence and equivalent visual states. A real server rejection is both business evidence and a UI state to inspect.

## A changed design rule in an active project

When the user changes the family density, update its authoritative tokens and design decision, then recheck dependent pages. Preserve unaffected approved choices. The runtime supplies the execution context; project sources provide the current facts the agent can reread.


## A Vue account menu assembled from the right layers

Start from the project's existing shell and accepted identity. Find a reliable
menu primitive when one is needed, a coherent icon/owned avatar and an appropriate
transition. Use the catalog to locate Vue candidates, then read the exact APIs and
observe focus, dismissal and controlled state. Compose behavior and visual treatment
under shared tokens; test keyboard/touch, narrow layouts and real session state.
Keep the selected source/variant and adaptation in the project record.

## A visual direction improved by discovery

For an open introduction surface, research a small set of visual mechanisms that
support the subject. A parameterized background may create depth while leaving
copy readable. Inspect its actual controls and source, then place a representative
instance behind real content. Keep the valuable mechanism, tune its intensity to
the project and test the composed cost/quiet equivalent before extending it.

## A document index with a separate asset catalog

A font provider's AI documentation can describe installation while its generated
family catalog lives elsewhere. Use each entry for its intended role: inspect the
actual typeface and glyph coverage in the catalog, then read version-matched usage
and licensing guidance. An index's coverage informs retrieval; a current project
render establishes typography fit.
