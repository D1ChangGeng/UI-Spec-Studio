# Technique patterns: from a problem to editable form

Read these when a concrete technique helps the current design. They are original reasoning examples with representative content, not measured model-performance claims. Adapt the mechanism to the actual task; the common principles remain the foundation.

Use these patterns to identify useful mature implementations, diagnose them and adapt their supported relationships. A reasoning example is neither an adopted visual implementation nor permission to recreate one. Apply [default-deny original UI construction](component-sourcing.md#default-deny-original-ui-construction): each visible relationship inherits a mature source or complete approved design, with original construction limited to the [authorized allowlist](component-sourcing.md#closed-original-construction-allowlist). Host-provided Markdown, native controls and established diagram renderers can carry their actual visual responsibilities; their use does not authorize an unrelated custom shell. [Technical probes](component-sourcing.md#separate-probes-from-formal-delivery) retain their research scope; a formal implementation needs an actual mature foundation, complete approved design or authorized original exception and its own verification.

## A comparison that makes differences legible

**Problem.** Several options repeat the same attributes, while users must compare values before choosing.

**Mechanism.** Align equivalent attributes, distinguish the primary decision factors and keep units/missing values explicit. A comparison table or coordinated rows exposes differences more directly than separate descriptive cards when cross-reading is central.

**Realization.** Use semantic row/column headers and a content model with stable attribute keys. Keep the selected object identifiable. On a narrow display, choose scoped table scrolling or an attribute-preserving stacked presentation according to the actual reading task. Expose column measures, row spacing and selected emphasis as semantic controls.

**Inspect.** Try unequal labels, missing values, keyboard selection and long translated text. Check whether the same question can be answered in each layout. Distinct objects without comparable properties may need editorial summaries instead.

## Evidence beside a conclusion

**Problem.** A reader can see a claim but must repeatedly leave it to inspect its basis.

**Mechanism.** Pair the claim with a traceable source. A shared selection connects evidence and explanation while maintaining orientation.

**Realization.** Give claims and citations stable identities. A wide view may coordinate reading panes; a narrow view may expand the associated excerpt in document flow. Preserve a return target, scroll context and source permission. Use the same selected-state language in both representations.

**Inspect.** Follow multiple citations, return, handle a restricted or missing source and refresh. The excerpt must actually support the claim. This layout earns its density when evidence inspection is part of the task; short uncomplicated content can remain inline.

## A focused task with balanced presence

**Problem.** A small form feels lost in a large canvas or drops toward its bottom.

**Mechanism.** Treat readable control size and total composition occupancy separately. Group the task and necessary explanation, then balance their mass within the usable frame.

**Realization.** Select a mature focused-task layout or inherit the validated page family, then adapt its form measure, spacing hierarchy and outer space. Visual centering or a slight upward optical bias is a candidate to inspect for compact tasks, not a source-free layout recipe. On short viewports, natural content access governs the layout. A page inside an existing family inherits its stable shell.

**Inspect.** Compare whole viewports, long errors, zoom and virtual keyboard conditions. The exact offset is a project decision. Large reading surfaces or activity feeds instead need a stable upper origin and growth below.

## An option change that preserves orientation

**Problem.** A local choice causes an entire section to disappear and re-enter, moving the user's attention away from the control.

**Mechanism.** Preserve anchors and component identity; acknowledge the selection immediately and transition only affected information. Pending data and confirmed data have distinct semantics.

**Realization.** Key components by the represented object, not a changing animation counter. Associate request results with the latest valid intent. Reversible effects begin from the current visual state. Editable controls include response duration, emphasis and which content groups participate, while business state stays authoritative.

**Inspect.** Reverse the selection rapidly, delay or fail a response, use keyboard input and reduce motion. A smooth transition that shows an obsolete result fails the task; correct state and continuous presentation are joint requirements.

## A publication that helps a reader begin

**Problem.** A tool's README contains many features but makes fit, installation and first use hard to find.

**Mechanism.** Order information by the reader's decisions: purpose and fit, immediate entry, working example, deeper model, evidence and maintenance. Use real links and native text for the essential path. A distinctive illustration can make the organizing idea memorable without carrying the only explanation.

**Realization.** Use the publishing host's headings, links, code blocks, disclosure and tables, inheriting its mature rendering system. Adopt fitting editable artwork or faithfully translate a complete approved design; necessary original identity or illustration follows its authorized allowlist scope. Inspect theme variants at actual display sizes and adapt a narrow composition when a wide layout becomes illegible. Keep all necessary claims and commands selectable. The artwork's source, palette roles and build command remain available.

**Inspect.** Read at narrow and wide widths, switch themes, disable images, use keyboard links, copy the command and verify its installed result. A host-compatible local preview and the remote host are separate verification conditions. This repository's README applies this pattern as its own product surface.

## An explanatory diagram with semantic integrity

**Problem.** Prose describes relationships that a reader must mentally reconstruct.

**Mechanism.** Decide whether the relation is sequence, containment, dependency, state or quantity. Choose one dominant visual grammar, use consistent roles and encode direction and boundaries explicitly.

**Realization.** Use a suitable mature diagram system or renderer and keep the source entities/edges or data alongside its configuration and output. Those product facts are content; the rendering system carries the visual grammar. Configure connector routing for readability while preserving endpoints. Use semantic text, units and legends where needed. Offer a readable textual or tabular equivalent. Controls such as node spacing, label measure and emphasis remain separate from the underlying facts. A genuinely unmet bespoke visual grammar needs a scoped, authorized W2 judgment rather than an automatic hand-drawn replacement.

**Inspect.** Trace a path against the source, check overlaps at actual size and verify color-independent meaning. For a simple list, native prose or a table may be more direct. A visually elegant diagram with incorrect topology is not an acceptable tradeoff.

## Familiar work with an expressive visual language

**Problem.** A professional research tool needs an independent artistic identity while preserving understandable questions, sources and durable results.

**Mechanism.** Separate the familiar task relationship from its visual form. Study conversation and evidence inspection as functional references, then investigate cross-domain type, photography, material or editorial composition. Select a coherent theme and mature implementations that can carry it into working inputs, results and navigation.

**Realization.** Trial defining assets beside actual text and controls before scaling the design. Assign display, reading and control type roles; make crop, surfaces, spacing and motion adjustable. Existing input, focus and state mechanisms can remain while the product's visual relationships change. A theme might connect covers, citations and result sections through proportion or material rather than one repeated decoration. This is one application, not a prescribed editorial style.

**Inspect.** Compare equally resolved directions with representative content. Check populated work, long results, returning to sources, repeated input and a reduced-motion treatment. Record usability and expressive completion independently. If an animated asset competes with input, test its location, local intensity, suspension or delivery; preserve the selected direction where feasible. A simple local repair in an already accepted product can inherit its expression without opening a new art-direction study.

## A faithful source becomes an authored sequence

**Problem.** A selected static composition needs a timed presentation explaining its relationships without losing its visual craft.

**Mechanism.** Preserve the source's meaningful layers, typography, material and spatial relationships; animate a semantic sequence such as evidence connecting to a decision and then to a result. Give important text stable reading intervals and the loop an intentional reset.

**Realization.** Reuse editable source layers and a suitable timeline/runtime. Fix stage, content, assets and relevant seeds; expose timeline positions for repeatable frame comparisons. Preserve a full-quality source view for matched-region fidelity inspection. Identify output format and actual encoded duration separately from the authoring clock.

**Inspect.** View source, keyframes, intermediate states, seam and final playback at useful scale. Differences locate unintended departures; perceived composition and rhythm need visual judgment. This establishes an authored work. A live product additionally needs semantic controls, variable content, user interruption and actual completion authority; its responsiveness cannot be inferred from the deterministic film.

## Preserve a useful technique

When adapting one of these patterns, keep a short record only if it will improve future work: the task, the transferable relationship, local constraints, editable source, inspected evidence and limits. Separate the project's aesthetic choice from the general mechanism. Add new shared patterns through an authorized maintenance change, with provenance and a concrete counterexample that shows where the technique should change.


## A material-rich card without moving the reading surface

**Problem.** A research library needs distinct material and pointer response, while long titles and reading actions should remain spatially stable.

**Look and search.** Compare an edge/fill light following input with a card whose entire plane tilts. Study the actual source demos and comparable content. Light falloff, rim treatment and stationary type may matter more than rotation amplitude. Search for resolved card implementations rather than beginning with a custom pointer handler.

**Adopt and adapt.** Trial the chosen source with real titles, language variants, theme and neighboring cards. Adjust its supported intensity, light size, edge or motion controls first. Keep text/action hierarchy and keyboard focus owned by the product. Decorative illumination is not the only selected/focus cue. A tilt can instead suit an image object where manipulation is intentional; it is not intrinsically inferior.

**Inspect.** Follow pointer entry, travel, exit and keyboard focus. Read long content during motion, inspect the entire card family, repeat actions and use reduced motion/touch. A dramatic isolated demo that displaces important text may lose to a quieter surface in this particular task. This is a conditional selection problem, not a global ban on tilting cards.

## A mature input block with a product-specific identity

**Problem.** A conversational tool needs a refined input, attachments and actions; functional textarea and menu dependencies alone do not supply their coordinated proportions.

**Look and search.** Study working input blocks through multiline growth, attached files, pending work, submission and recovery. Search for complete composition/state implementations as well as semantic foundations. Compare their actual control hierarchy, reading space and continuity under the project's content; an empty rounded field is insufficient evidence.

**Adopt and adapt.** Prefer a suitable source block, configure its slots and tokens, and connect protected actions to the application. Keep source geometry and state mechanisms where they serve the task. Patch an evidenced gap such as input-method composition handling or focus restoration at the responsible boundary, preserving the rest and owning the changed behavior. Such engineering repair can be normal adaptation; a new visible mechanism that replaces the source's design responsibility requires the relevant allowlist judgment and authorization.

**Inspect.** Exercise keyboard and input-method composition, long localized strings, attachment addition/removal, quick repeated input and delayed outcomes. Check that adoption retained the source's spatial relationships as well as its function. A source with the wrong workflow may be a poor foundation even when its visual finish is strong.

## Expressive work that retains readable motion-free states

**Problem.** A professional workspace needs an independent artistic identity across working content, not just a marketing header.

**Look and search.** Study cross-domain editorial, photographic or spatial references alongside mature product task flows. Find adoptable assets and visual components whose focal position, material and timing can coexist with that work. Keep candidate source and current-project evidence separate.

**Adopt and adapt.** Compose a selected asset with an existing mature functional block. Adapt public controls, crop, layer order and type roles while retaining the asset mechanism; original replacement follows the closed allowlist. Keep one governing visual language while allowing different responsibilities to have different treatments. For reduced motion or limited rendering, use a source-supported still, derivative or simpler representation that retains the recognizable subject and usable task. Preserve any unsolved fallback quality as an explicit gap rather than inventing an unrelated substitute.

**Inspect.** Use populated work, long reading, navigation and repeated input in both active and quiet states. If the background overwhelms a result, test its local placement/intensity and content layer rather than automatically removing all expression. The selected asset and mature function still require whole-page verification; source quality does not add together automatically.


## Preserve task entry when a mature block changes responsive placement

**Observed failure.** A retained conversation block rendered correctly, but hiding
its navigation column at a narrow width removed the user's path to history.
Component maturity does not cover a surrounding shell's omitted entry.

**Adapt at the owner.** Keep the original conversation and thread-list mechanisms.
Use the source's responsive variant or a compatible mature navigation control to
provide a discoverable narrow entry. Associate the toggle with its region and
check opening, dismissal and task return with real populated content. A necessary
new visible extension requires the scoped W3 evidence and authorization; the missing
entry alone does not authorize a new shell.
A different task may use a different navigation pattern; the transferable rule
is preservation of the journey, not this study's particular shell.

**Inspect.** Compare wide and narrow initial, generating, long-result, error and
cancelled states. Distinguish a fixture adapter's behavior from a live model,
service persistence or full parity with a reference product. Reinspect the
assembled task rather than counting an imported block as complete alignment.

## Observe settled overlay behavior before changing a mature mechanism

**Observed uncertainty.** A short-delay screenshot after closing a source drawer
still contained an exiting dialog. A DOM object's presence did not by itself
establish whether it was open, focusable or about to finish its exit.

**Investigate and adapt.** Observe the relevant close and return sequence, inspect
actual open state and active focus after settling, and identify ownership. Use
supported controlled-state and close-autofocus hooks for a demonstrated gap while
retaining the mature drag/scroll mechanism. Any proposed original replacement
must meet the closed allowlist before implementation. Preserve edited local content
through reopen where the task needs it; do not imply server persistence.

**Inspect.** Exercise close, reopen, Escape, scrolling, drag reversal and focus
return at the actual conditions. A longer wait is an observation condition, not
a universal animation duration or a way to conceal an actual interaction defect.
Frame samples with screenshot overhead are not proof of smooth natural delivery.
